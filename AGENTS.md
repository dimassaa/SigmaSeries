# AGENTS — правила работы агента над этим проектом

> Короткий файл, загружается постоянно. Подробности — в `docs/06-agents/READING-MAP.md` и `docs/06-agents/PROTOCOLS.md`. Этот файл не пересказывает документацию, а задаёт **порядок работы**.
> Формат `.opencode/commands/` и `.opencode/agents/` сверен с документацией установленной версии opencode **v2.0.22**. При смене версии проверить первым делом: названия каталогов и поля фронтматтера между версиями менялись.

## Что это

Курсовой проект: сервис оценки и отслеживания сериалов с календарём выхода серий. Node.js + Express, JavaScript (не TypeScript), PostgreSQL, серверный рендеринг. Задание — `input/Бланк.md`. Спецификация — `docs/`. **Кода пока нет.**

## Требования, которые нельзя нарушить

1. **Бизнес-логика — только JavaScript.** TypeScript отклонён руководителем. Типизация — JSDoc с проверкой `tsc --checkJs`, язык остаётся JS.
2. **Одна каскадная таблица стилей** на всё приложение. Части собираются на этапе сборки — требование выполняется буквально.
3. **Изображения хранятся в БД.** Не в файловой системе, не в CDN.
4. **Интерфейс и подписи на схемах — по-русски.** Исключение возможно только после письменного ответа руководителя (`docs/07-kp/LETTER-SUPERVISOR.md` п. 2, на момент старта кода **не отправлено**).
5. **Инфраструктура — Windows 10+, Node.js, PostgreSQL из списка Бланка.** Redis, очереди, внешние планировщики, ORM, UI-фреймворки — **не ставятся** без письменного согласования. Список разрешённого — `docs/05-architecture/STACK.md` §3.
6. **Зависимости сверх списка не добавляются.** Нужна новая библиотека — вопрос автору по `PROTOCOLS` §5.

## Перед каждой задачей

```bash
node tools/docs-build/context-pack.mjs --check          # целостность документации
node tools/docs-build/context-pack.mjs F-01-03          # пакет под задачу
```

**Не читать документацию целиком.** Задача → один пакет → разделы «Куда смотреть дальше» и «Не найдено в документах». Порядок — `READING-MAP.md` §1.

## Порядок работы

1. **Прочитать пакет фичи.** Не начинать, пока не прочитан: §1 «Фича» и §2 «Модуль».
2. **Проверить `§10 Edge cases`** — это границы, а не украшение. Обработать каждую.
3. **Взять числа из таблицы настроек модуля.** Не из памяти, не из соседней фичи. Нет ключа — это находка, а не повод придумать значение.
4. **Написать тест, убедиться, что он падает.**
5. **Реализовать минимум.**
6. **Прогнать тест.** Убедиться, что проходит.
7. **Коммит:** `feat: <OP-xx> <название операции>`.

## Обязательные проверки перед коммитом

| Проверка | Как |
|---|---|
| Требования кода | `test` |
| Целостность документации | `cd docs && python3 ../tools/docs-build/build_registries.py` → ожидается `Ссылки сходятся, пустых измерений нет`, код 0 |

| Контраст | Не ниже 4,5:1; на стекле — к подложке, не к фотографии |

## Жёсткие правила оформления

1. **Только токены из `docs/02-design/TOKENS.md`.** Hex в компоненте — ошибка. Тема не переключится.
2. **Анимируются только `transform` и `opacity`.** Всё остальное вызывает пересчёт раскладки — это и есть то самое подёргивание панели, которого требовалось избежать.
3. **Шрифты — `font-display: swap`**, запасное семейство с кириллицей. Без этого текст мигает несовместимыми метриками.
4. **`aspect-ratio` у изображений.** Без него CLS не ноль.
5. **Цвет не единственный носитель состояния.** Всегда значок или текст.
6. **Стекло — только над изображением**, максимум два размытых слоя на экране, обязателен запасной вариант без `backdrop-filter` (`MATERIALS-GLASS.md`).
7. **`prefers-reduced-motion` выключает движение полностью**, а не ослабляет.
8. **Один primary на действие.** Две одинаково выделенные кнопки означают, что человек угадывает.
9. **Пользовательский текст экранируется всегда.** Свои тексты не «доверенные».
10. **HTML от пользователя не исполняется.** Только текст и структура.
11. **Права проверяются на сервере по сессии**, а не по телу запроса. Скрытие пункта меню — удобство, не защита.
12. **У каждой операции — тест.** Без теста операция не реализована (`TRACEABILITY`).

## Когда документация не сходится

**Не «исправлять» документацию под код.** Лестница: L0 перечитать → L1 `--where` → L2 `--neighbors` → **L3 стоп и вопрос автору**. Чаще всего ответ на L3 лежит на L0.

Вопрос обязан содержать: что говорит документ (цитата и ID) → что на самом деле (чем проверено) → предложение с одним вариантом → цена. Подробно — `docs/06-agents/PROTOCOLS.md` §1.

Ошибка безопасности или данных → **сразу L3, с откатом изменений.**

## Чего не делать без отдельной команды

Менять правила в стандартах · добавлять зависимости · переименовывать и удалять документы · менять публичные адреса и ключи настроек · коммитить без разрешения.

## О проекте

**Суть.** Пользователь отмечает просмотренные серии, ставит оценки, подписывается на выходы и получает уведомления. В каталоге есть рейтинги сериалов и отдельных серий, отзывы со спойлерами, календарь выхода серий и персонализированные подборки.

**Роли.** Гость (смотрит без регистрации), зритель, редактор (модерация), аналитик (дашборды и A/B-тесты), администратор (пользователи, каталог, бан, бэкап).

**Каталог.** Топ-1000 сериалов по голосам IMDb плюс сериалы с эпизодами до 31 декабря 2026 — всего 1197 позиций. Данные берутся из датасетов IMDb и API TMDB, чего нет — закрывается заглушкой, недостающее админ дописывает в контент-студии.

**Что отличает проект от аналогов.**

- Календарь выхода серий как основной сценарий, а не как дополнительный раздел.
- Защита от спойлеров в отзывах и описаниях с сортировкой по группам (положительные, смешанные, отрицательные; длинные и короткие).
- Модерация без машинного обучения: поиск по словарю на русском и английском, результат скрывается до решения редактора.
- Интерактив в духе Spotify Wrapped: персональные итоги по просмотрам.
- Светлая и тёмная темы, два языка (русский, английский), заложенная архитектура под добавление третьего.

> [!NOTE]
> Тема, роли и исходные требования автора зафиксированы в [`input/spec.md`](input/spec.md). Требования руководителя — в [`input/Бланк.md`](input/Бланк.md): MVC или MVP на Node.js + Express, бизнес-логика на JavaScript, одна каскадная таблица стилей, реляционная или нереляционная СУБД на выбор студента, не менее 10 бизнес-операций и 2–3 ролей.

## Быстрый старт

Требования: **Python 3.9+** для реестров, **Node.js 18+** для пакетов контекста, Git.

> [!NOTE]
> Node.js в текущем окружении не установлен, поэтому `context-pack.mjs` здесь не проверялся. Python-проверка выполнена.

```bash
git clone <url> && cd <repo>
```

**Пересобрать реестры и обновить STATUS** — запускается из корня `docs/`:

```bash
cd docs && python3 ../tools/docs-build/build_registries.py
```

Скрипт создаёт `01-product/FEATURES.md`, `00-process/COVERAGE.md`, `00-process/EDGE-CASES.md` и `docs/STATUS.md`, затем проверяет, что у каждого упомянутого `EC-`, `H-` и `R-` есть определение. **Код возврата 1 — это не авария, а найденные проблемы**, они печатаются в stdout.

Эти четыре файла генерируются — **править их руками нельзя**, изменения вносятся в спеки модулей и пересобираются.

**Собрать пакет контекста по фиче** — запускается из корня репозитория:

```bash
node tools/docs-build/context-pack.mjs F-01-03          # пакет одной фичи
node tools/docs-build/context-pack.mjs --module M1      # обзор модуля
node tools/docs-build/context-pack.mjs --where R-SEC-04  # где определено и где используется
node tools/docs-build/context-pack.mjs --check           # размеры пакетов, битые ссылки
```

Пакет — это один файл со всем, что нужно агенту для работы над фичей: сама фича, правила стандартов, граничные случаи, решения, чек-листы ревью по применимым измерениям.

**Замер данных (не часть продукта).** Требует ключ TMDB и датасеты IMDb, подробности — в [`tools/data-spike/README.md`](tools/data-spike/README.md).

## Проверка согласованности

Две независимые проверки, обе зелёные на 2026-10-09.

**Реестры и ссылки** — Python, без зависимостей:

```bash
cd docs && python3 ../tools/docs-build/build_registries.py
```

Создаёт `FEATURES.md`, `COVERAGE.md`, `EDGE-CASES.md` и `STATUS.md`, затем проверяет, что у каждого упомянутого `EC-`, `H-` и `R-` есть определение. **Код 0** — расхождений нет. Код 1 — расхождения есть, и это ожидаемый режим, не авария.

Текущее состояние: 106 фич (82 P0), 230 граничных случаев, 25 решений автора, 17 бизнес-операций, 58 экранов, 210 правил в стандартах.

**Пакеты контекста** — Node.js 18+ (проверено на v22.23.3):

```bash
export PATH="$HOME/.local/opt/node/bin:$PATH"   # node не в глобальном PATH
node tools/docs-build/context-pack.mjs --check
```

Проверяет размеры пакетов, неразрешённые ссылки и повторные определения. **Код 0**, максимум 300 строк при лимите 700.

Сверка по всем одиннадцати семействам ID (включая `S-`, `OP-`, `F-`, `E-`, не только те, что проверяет генератор) выполнена отдельно: найдено и исправлено 61 расхождение.

> [!WARNING]
> Проверка подтверждает, что правило **существует**, а не что оно **то самое**. Пример: в пяти местах «ссылки запрещены (`R-SEC-04`)» — а `R-SEC-04` это 2FA. Номер существовал и проходил любую автоматическую проверку; ошибку нашёл просмотр пакета глазами. Разбор — `docs/06-agents/PROTOCOLS.md` §5.

## Ограничения

- **Нет HTTP-слоя.** Бизнес-логика реализована и покрыта 95 тестами, схема применяется к живой PostgreSQL, но ни один экран не отдаётся: нет Express, маршрутов и шаблонов. Это ограничение перекрывает по значимости остальные.
- **Ревью не пройдено.** Ни одна из 106 фич не подтверждена автором. Матрица покрытия считает наличие раздела, а не содержание — 100% в ней не означает качества.
- **18 из 58 экранов** не покрыты пользовательскими путями, включая календарь (S-16) и почтовый ящик разработчика (S-84).
- **Матрицы состояний по экранам нет.** `SCREENS` обещал её для всех экранов; нарисовано ноль.
- **BPMN отсутствует**, хотя Бланк 3.4 требует учитывать стандарт.
- **Node.js не установлен в текущей среде**, поэтому `context-pack.mjs` проверен чтением кода, а не запуском.
- Лицензия не выбрана: проект учебный, публиковать его не планируется.

**Что, наоборот, сделано лучше среднего:** безопасность (42 правила и 35 угроз со статусом остаточного риска), спецификация функциональных требований (106 фич × 20 измерений), модель данных с исполняемым DDL и замеры на реальных данных. Это закрывает разделы ПЗ 4.1.3, 4.1.4 и 4.2.6 — их не придётся дописывать заново.

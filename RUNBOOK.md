# RUNBOOK — запуск SigmaSeries на ноутбуке

Инструкция для OpenCode: выполнять шаги по порядку, после каждого шага сверять результат. Всё делается в PowerShell (Windows 10/11); отличия для Linux/macOS указаны там, где важны.

## 0. Что понадобится

- Windows 10/11, права администратора для установки программ.
- Node.js **22 или новее**.
- PostgreSQL **16 или новее**.
- Ключ TMDB (для импорта каталога) — бесплатно выдаётся в личном кабинете TMDB: Settings → API → API Read Access Token.
- Свободное место: около 5 ГБ (зависимости, датасеты IMDb ~1,4 ГБ, изображения в базе 1–2 ГБ).

## 1. Скопировать репозиторий

```powershell
git clone <адрес-репозитория> sigmaseries
cd sigmaseries
```

Если репозиторий копируется папкой, просто перейти в неё. Проверить, что видны `package.json`, `db/schema.sql`, `src/`.

## 2. Установить Node.js

Скачать LTS-версию с nodejs.org, установить с параметрами по умолчанию. Проверить в новом окне PowerShell:

```powershell
node -v
npm -v
```

Ожидается `v22.x` или новее. Если команда не найдена — перезапустить терминал; при необходимости добавить путь к Node.js в `PATH`.

## 3. Установить PostgreSQL и создать базу

Установить PostgreSQL 16, запомнить пароль пользователя `postgres`. Добавить `C:\Program Files\PostgreSQL\16\bin` в `PATH` или выполнять команды из этого каталога.

```powershell
psql --version
createdb -U postgres serial_tracker
psql -U postgres -d serial_tracker -v ON_ERROR_STOP=1 -f db/schema.sql
```

Ожидается: команды завершаются без ошибок, создаются таблицы, индексы и служебная роль `st_app`. Если `psql` просит пароль — вводить пароль `postgres`.

> Для локальной демонстрации приложение подключается пользователем `postgres` (владельцем схемы). Правила прав на уровне СУБД при этом не проверяются, но все функции работают. Для проверки прав нужно задать пароль роли `st_app` и подключаться ею.

## 4. Настроить `.env`

Скопировать шаблон и заполнить:

```powershell
Copy-Item .env.example .env
notepad .env
```

Минимальный набор:

```dotenv
PGHOST=localhost
PGPORT=5432
PGUSER=postgres
PGPASSWORD=пароль_из_шага_3
PGDATABASE=serial_tracker
PORT=3000
MAIL_MODE=devbox
TMDB_TOKEN=токен_TMDB

SESSION_SECRET=...
BLIND_INDEX_SECRET=...
ADDRESS_SECRET=...
MAIL_SECRET=...
```

Секреты сгенерировать по одному (четыре разных значения):

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

`.env` уже в `.gitignore`; в репозиторий его не добавлять. `MAIL_MODE=devbox` оставляет письма в базе и показывает их на экране «проверьте почту» — интернет для регистрации не нужен.

## 5. Установить зависимости и запустить

```powershell
npm install
npm start
```

Ожидается строка о запуске сервера. Открыть `http://localhost:3000/ru/` — главная должна ответить 200. Если приложение пишет, что не хватает секрета, — проверить `.env`; если не подключается к базе — проверить `PG*` и что PostgreSQL запущен.

## 6. Загрузить каталог из IMDb и TMDB

Импорт идёт пятью шагами; для демонстрации достаточно ограничить объём флагом `--limit`. Все команды выполняются в отдельном терминале, сервер можно не останавливать.

```powershell
npm run import:candidates
npm run import:match -- --limit 100
npm run import:enrich -- --limit 100
npm run import:catalogue -- --limit 100
npm run import:images -- --limit 100
```

Что происходит:

1. `import:candidates` скачивает датасеты IMDb (~226 МБ) в `data/imdb/`, отбирает самые популярные сериалы и записывает прогон. Ключ TMDB не нужен.
2. `import:match` сопоставляет отобранное с TMDB. Нужен `TMDB_TOKEN`. 100 позиций занимают около 20 секунд.
3. `import:enrich` скачивает датасеты людей (~1,1 ГБ) и карточки TMDB: 100 сериалов — обычно 5–15 минут.
4. `import:catalogue` записывает сериалы, сезоны, серии и выходы в базу.
5. `import:images` загружает постеры и фоны в PostgreSQL (по 185/342/500 и 780/1280/1920 пикселей).

Проверка:

```powershell
psql -U postgres -d serial_tracker -c "SELECT count(*) FROM e_series WHERE publication_state='published';"
psql -U postgres -d serial_tracker -c "SELECT count(*) FROM e_image_variant;"
```

Ожидается несколько десятков опубликованных сериалов и тысячи вариантов изображений. Открыть `/ru/series` — каталог должен быть заполнен.

> Если ключа TMDB нет, каталог останется пустым. Альтернатива — развернуть готовую копию: `npm run demo:db` (нужен файл `backups/*.dump`, если он есть). Для чистой установки без ключа демонстрация каталога невозможна.

## 7. Создать демонстрационные аккаунты и материалы

```powershell
node tools/seed-demo.mjs
```

Скрипт создаёт пользователей, оценки, отметки, статусы, отзывы и руководство. Повторный запуск дублей не создаёт.

| Роль | Email | Пароль |
|---|---|---|
| Зритель | `demo-anna@example.com` | `DemoPass-2026` |
| Зритель | `demo-igor@example.com` | `DemoPass-2026` |
| Редактор | `demo-editor@example.com` | `DemoPass-2026` |
| Аналитик | `demo-analyst@example.com` | `DemoPass-2026` |
| Администратор | `demo-admin@example.com` | `DemoPass-2026` |

Скрипту нужен хотя бы один опубликованный сериал с постером — сначала выполнить шаг 6. Если каталог пуст, скрипт сообщит об этом и завершится.

**Двухфакторная аутентификация.** Редактор, аналитик и администратор при первом входе попадают на экран настройки 2FA: нужно отсканировать QR-код приложением-аутентификатором и ввести шестизначный код. Резервные коды показываются один раз. Настроить это заранее, а не на защите.

## 8. Что показывать

- `/ru/` — главная: баннеры дня, популярное, лента новинок, панель ближайших выходов.
- `/ru/series` — каталог с фильтрами и сортировками.
- `/ru/series/<slug>` — карточка сериала; отзывы видны в блоке и на `/ru/series/<slug>/reviews`.
- `/ru/guides` — список руководств; руководство создаётся скриптом.
- Войти как `demo-anna@example.com` — библиотека, статусы, рекомендации (`/ru/for-you`), итоги.
- Войти как `demo-editor@example.com` (после 2FA) — `/ru/mod`: очередь модерации.
- Войти как `demo-analyst@example.com` (после 2FA) — `/ru/analytics`.
- Войти как `demo-admin@example.com` (после 2FA) — `/ru/admin`, `/ru/admin/catalog`, `/ru/admin/import`, `/ru/admin/backups`.

Новинки на главной показываются за последние 14 дней; если импортированные даты выходов старше, блок будет пуст — для показа используйте каталог и карточки.

## 9. Резервная копия

```powershell
pg_dump -U postgres -d serial_tracker -Fc -f serial_tracker.dump
```

Восстановление:

```powershell
createdb -U postgres serial_tracker_restore
pg_restore -U postgres -d serial_tracker_restore serial_tracker.dump
```

`.env` копируется отдельно: в дампе его нет.

## 10. Если что-то не работает

| Симптом | Причина | Что сделать |
|---|---|---|
| `node` не найден | Node.js не в `PATH` | Перезапустить терминал, переустановить Node.js с добавлением в `PATH` |
| `psql` не найден | не добавлен `bin` PostgreSQL | Указать полный путь `C:\Program Files\PostgreSQL\16\bin\psql.exe` или добавить в `PATH` |
| `password authentication failed` | неверный `PGPASSWORD` | Проверить пароль в `.env`, при необходимости сбросить пароль `postgres` |
| «не заданы секреты» | пустые `*_SECRET` | Сгенерировать четыре секрета и заполнить `.env` |
| каталог пуст после импорта | `TMDB_TOKEN` не задан или прогон упал | Проверить токен и вывод команд; `import:catalogue -- --limit 10` для проверки |
| картинки не грузятся | импорт изображений не выполнен | `npm run import:images -- --limit 100` |
| администратор требует 2FA | правило для служебных ролей | Настроить 2FA при первом входе |
| порт занят | запущен другой процесс | Изменить `PORT` в `.env` |
| письмо не приходит | `MAIL_MODE=smtp` без SMTP | Поставить `MAIL_MODE=devbox` |

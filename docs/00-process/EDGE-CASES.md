# EDGE-CASES — реестр граничных случаев

> Собирается скриптом из таблиц `EC-…` во всех документах. Правило: каждая фича ссылается на свои `EC`; новая находка сначала попадает сюда. Всего: **230**.

## Права и роли (`EC-R*`)

| ID | Ситуация | Поведение | Где |
|---|---|---|---|
| EC-R1 | Роль снята или аккаунт забанен посреди работы с формой | Отправка отклоняется (403), черновик не теряется, интерфейс остаётся открытым до следующего действия | §3 п. 5 | `01-product/ROLES-PERMISSIONS.md` |
| EC-R2 | Два админа правят одну карточку | Оптимистичная блокировка: второй видит конфликт и сравнение двух версий, выбор «оставить мою» или «взять его» | §3 | `01-product/ROLES-PERMISSIONS.md` |
| EC-R3 | Админ архивирует сериал, на который ссылаются баннер, подборка, списки зрителей, отзывы | Ссылки остаются; сериал скрыт с главной; в списках — «снят с публикации»; данные не удаляются | §3 п. 7 | `01-product/ROLES-PERMISSIONS.md` |
| EC-R4 | Редактор мьютит админа или другого редактора | Запрещено: интерфейс не предлагает действие, сервер отклоняет с объяснением | §3 п. 3 | `01-product/ROLES-PERMISSIONS.md` |
| EC-R5 | У пользователя несколько дополнительных ролей | Права складываются, интерфейс показывает объединение разделов; меню ролей — одна кнопка, а не переключатель | §3 п. 2 | `01-product/ROLES-PERMISSIONS.md` |
| EC-R6 | Зритель удаляет аккаунт с отзывами и руководствами | Анонимизация автора; опционально — удалить материалы вместе с аккаунтом; оценки остаются и в агрегатах | §3, `M1` F-01-10 | `01-product/ROLES-PERMISSIONS.md` |
| EC-R7 | Попытка повышения прав через подмену идентификатора в запросе | Права берутся из сессии на сервере, не из тела запроса; попытка пишется в аудит | §3 п. 1 | `01-product/ROLES-PERMISSIONS.md` |
| EC-R8 | Админ вручную правит поле, которое потом перезапишет импорт | Ручное значение блокируется от перезаписи; в студии видно происхождение поля | `M10` F-10-03 | `01-product/ROLES-PERMISSIONS.md` |
| EC-R9 | Аналитик запрашивает выгрузку событий с идентификатором пользователя | Отказ: экспортируются только агрегаты, идентификаторы псевдонимизированы | §2, `ANALYTICS` R-AN-17 | `01-product/ROLES-PERMISSIONS.md` |
| EC-R10 | Админ выдаёт роль человеку, который не подтвердил email | Запрещено: неподтверждённый аккаунт не может носить служебную роль | §3 п. 4 | `01-product/ROLES-PERMISSIONS.md` |
| EC-R11 | Служебная роль снята во время открытой сессии | Сессия не продлевается при следующей проверке прав; открытые формы отвечают 403 | §3 п. 5 | `01-product/ROLES-PERMISSIONS.md` |
| EC-R12 | Пользователь с ролью аналитика пробует открыть очередь модерации | 403 по матрице: у аналитика нет доступа к модерации даже при активной сессии | §2 | `01-product/ROLES-PERMISSIONS.md` |

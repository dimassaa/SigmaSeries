## 5. Что этот файл доказывает

1. **Каждое требование Бланка имеет адрес в документации.** Строка «не начато» — честный статус, а не пробел.
2. **Каждая бизнес-операция имеет имя функции и имя теста.** Именно это отвечает на требование «не менее 10 бизнес-операций, не считая простых операций с БД»: операция считается реализованной, когда у неё есть тест.
3. **Каждое правило безопасности имеет тест.** 42 правила `R-SEC` — это 42 пункта, а не одно предложение «мы учли безопасность».
4. **Обратная прослеживаемость:** от функции можно дойти до требования и увидеть, зачем она существует.

## 6. Что нужно сделать, чтобы файл стал рабочим

1. По мере реализации менять статус строк: СПЕЦИФИЦИРОВАНО → ЕСТЬ КОД → ПРОВЕРЕНО.
2. Указывать реальные пути к тестам вместо описаний.
3. Добавлять строки для новых операций, если они появятся.
4. **Не удалять строки со статусом «не начато».** Пробел, записанный явно, виден; пробел, удалённый из таблицы, не виден никогда.

## 0. Сквозное для модуля

**Роли.** Оболочка одинакова для всех пяти ролей. Различие одно: у служебных ролей (редактор, аналитик, администратор) в меню появляются пункты разделов, которых нет у зрителя; проверка идёт на сервере по сессии, скрытие пунктов — только удобство (`R-SEC-12`, `ROLES-PERMISSIONS`).

**Границы модуля.** `MODULES` относит к M0 все 13 компонентов UI-01…UI-13. Это неверно: **UI-04 и UI-11 закреплены за M3** (правая панель выходов и центр уведомлений — они зависят от данных о выходах и подписках), **UI-09 и UI-10 — за M2** (поиск и карточка постера). M0 строит оболочку и отдаёт слоты: rail, верхнюю и мобильную панели, переключатели, скелетоны, заставку, согласие на cookies, служебные страницы.

**Правило раскладки, ради которого модуль существует.** Ширина рабочей области при развороте rail **не меняется**. Rail накладывается поверх контента, подписи проявляются, а не выталкивают соседние блоки. Причина из `input/spec.md`: на OpenSea панель подлагивает при развороте, и это сразу бросается в глаза. Анимация разрешена только по `transform` и `opacity` (`R-DES-25`) — иначе браузер пересчитывает раскладку на каждом кадре, и CLS становится ненулевым.

**Тема и язык.** Значение выбирается до первой отрисовки: читается из cookie, иначе из `localStorage`, иначе системные настройки, иначе `ru` + тёмная. Класс на `<html>` ставится в `<head>` до подключения таблицы стилей — иначе при перезагрузке видна вспышка светлого на тёмной (`UI-08`).

**Сущности (поля уточняет Фаза 5):** настройки интерфейса — E-UserSetting (`theme`, `locale`, `rail_state`), см. M1 F-01-06. В M0 собственных таблиц нет; всё состояние интерфейса, кроме выбора темы и языка, живёт в URL или в памяти вкладки.

## F-00-01 Каркас страницы, левый rail и второе меню (UI-01, UI-03) · P0

1. **Назначение.** Дать одинаковую навигацию на всех страницах и не сдвигать контент при её раскрытии.
2. **Роли.** Все. Пункты служебных разделов видны только носителям роли.
3. **Триггер.** Первая отрисовка любой страницы; возврат по кнопке «назад» — rail восстанавливается из памяти вкладки, а не из cookie, чтобы чужое состояние не подхватывалось.
4. **Сценарий.** Десктоп: сетка из трёх колонок — rail 56 px, контент, правая панель от 1280 px (`H-30`, подтверждено). Rail свёрнут, видны иконки. При наведении или фокусе на rail он раскрывается **поверх** контента до 240 px, подписи проявляются, контент под ним остаётся на месте. Уход курсора — закрытие с задержкой `shell.rail_close_delay_ms`, чтобы не «дёргалось», пока пользователь ведёт мышь к пункту. Касание и клавиатура: тап по иконке открывает, повторный тап и `Esc` закрывают, `Tab` переводит фокус внутрь открытого rail. Второе меню (UI-03) раскрывается по «Сериалы»: сетка жанров из справочника M10 плюс «Каталог», «Закладки», «Руководства», «Календарь».
5. **Альтернативы и ошибки.** Меню не загрузилось (сбой справочника жанров) — показываем «Каталог» одной строкой без сетки, страница при этом рабочая. Клавиатура: rail закрылся во время обхода Tab — фокус возвращается на иконку, а не теряется. Длинный список жанров — прокрутка внутри попапа, не растягивание страницы.
6. **Состояния.** Свёрнут · открыт по наведению · открыт по фокусу · открыт закреплённо (нажатием) · открыт по нажатию (touch) · второе меню закрыто / открыто / пусто.
7. **Данные.** Справочник жанров (M10 F-10-10); маршруты — `SCREENS`; состояние — память вкладки.
8. **Правила.**
   - (а) Ширина контента при раскрытии неизменна; разворот — `transform: translateX()` и `opacity` подписей, всё остальное запрещено (`R-DES-25`).
   - (б) Тень не используется для отделения rail — только тонкая линия-обводка, как в `DESIGN (1).md`; тени в этой системе нет вообще (`R-DES-19`).
   - (в) У каждого пункта — значок **и** текст; иконка без подписи при свёрнутом состоянии не является единственным носителем смысла (`R-A11Y-09`).
   - (г) Порядок пунктов фиксирован и не зависит от прав: Главная, Каталог, Сериалы ▸, Закладки, Руководства, Календарь; служебные — после разделителя, чтобы их не спутали с пользовательскими.
   - (д) При `prefers-reduced-motion` разворот мгновенный, без задержек (F-00-08).
9. **Валидация и лимиты.** Ширина rail фиксирована двумя настройками; при ширине окна < 640 rail не рендерится вовсе (F-00-03).
10. **Edge cases.** EC-O1, EC-O2, EC-O3, EC-O4.
17. **Побочные эффекты.** EV-01 при смене маршрута; сброс кэша картинок при первом открытии (картинки из БД по C-04).
18. **Приёмка.** *Дано* открыт каталог на 1440 px; *когда* курсор уходит на rail; *тогда* rail раскрывается, а левая граница сетки карточек остаётся на прежнем месте (CLS = 0 за всю сессию). *Дано* пользователь на телефоне; *когда* тапает по иконке «Сериалы»; *тогда* открывается список жанров, и тап вне списка его закрывает. *Дано* пользователь работает только с клавиатуры; *тогда* rail открывается по фокусу и подписи доступны для чтения.
19. **UI.** Разворот поверх контента, три колонки, без сдвига сетки:

```
┌──┬──────────────────────────────────────────┬───────────────┐
│▪ │  ┌ стекло, без содержимого ────────────┐ │  Предстоящие  │
│▪ │  │ ← сюда наезжает раскрытый rail      │ │  (UI-04, M3)  │
│▪ │  └─────────────────────────────────────┘ │               │
│▪ │  КОНТЕНТ. Левая граница не двигается       │               │
│▣ │  при раскрытии rail                        │               │
│  │                                             │               │
│  │ rail: 56 px свёрнут ──▶ 240 px, наложение    │               │
└──┴──────────────────────────────────────────┴───────────────┘
   ↑           ↑ ширина контента постоянна           ↑
   240 px, поверх          (ничего не сдвигается)   правой панели нет < 1280
```
   **Фокальная точка:** на главной — заголовок первого экрана; в каталоге — первый постер сетки; фокус картинки задаёт админ в студии (F-10-04), при отсутствии — 2/3, 1/3. **Телефон (< 640):** rail не рисуется, вместо него нижняя панель (F-00-03). **Планшет (640–1024):** rail есть, правая панель нет. **Скелетон:** 8 строк иконок одинаковой высоты, полоса без текста.
20. **КП.** Диаграмма вариантов использования «навигация по сервису»; скриншот на плакат «модели представления».

## F-00-02 Верхняя панель, тема и язык (UI-02, UI-08) · P0

1. **Назначение.** Дать доступ к поиску, входу и переключателям, не вытесняя содержимое страницы.
2. **Роли.** Все.
3. **Триггер.** Загрузка любой страницы; выбор темы или языка пользователем.
4. **Сценарий.** Слева — два переключателя: тема (светлая / тёмная / системная) и язык (RU / EN). Справа — поиск, затем вход или аватар. У аватара меню: профиль, уведомления с числом, выход. Красная точка на аватаре, если есть непрочитанные (детали — M3, UI-11). Смена темы применяется мгновенно без перезагрузки и без вспышки; выбор языка меняет путь на `/{locale}/…` с сохранением страницы, а не переходом на главную.
5. **Альтернативы и ошибки.** Значение темы из хранилища недоступно (приватный режим) — работает системная, выбор не сохраняется, предупреждение не показываем (мелочь, не ошибка). Перевод страницы на новый язык отсутствует — страница открывается, страница помечается `noindex` (`R-SEO-04`). Неизвестный код языка — 404.
6. **Состояния.** Гость (кнопка «Войти») · вошедший без ролей · вошедший со служебной ролью · есть непрочитанные · тема из системы / выбрана · язык по умолчанию / выбран.
7. **Данные.** E-UserSetting (тема, язык); для гостя — cookie.
8. **Правила.**
   - (а) Класс темы ставится на `<html>` до загрузки таблицы стилей; иначе при перезагрузке вспышка (`UI-08`).
   - (б) «Системная» тема следует `prefers-color-scheme` **вживую**: смена системной темы переключает сайт без перезагрузки.
   - (в) Смена языка: сохраняем текущий путь и полосу прокрутки; при отсутствии перевода — `noindex`, а не 404.
   - (г) Переключатели — кнопки с `aria-pressed`, не selects: вариантов мало и они должны быть видны сразу.
   - (д) Порядок записи: выбор применяется визуально раньше, чем уходит запрос на сохранение; при ошибке сохранения показываем одну строку и откатываем выбор.
9. **Валидация и лимиты.** Код языка — из `locale.supported`; тема — из трёх допустимых значений; всё остальное отклоняется на сервере (`R-SEC-13`).
10. **Edge cases.** EC-O5, EC-O6.
17. **Побочные эффекты.** EV-18 `theme_toggle`, `locale_switch`; сброс кэша выдачи при смене языка; переход по адресу с 301, если язык был пустым.
18. **Приёмка.** *Дано* тёмная тема выбрана; *когда* пользователь перезагружает страницу; *тогда* до первой отрисовки фона светлого нет. *Дано* открыт S-15 на RU; *когда* выбран EN; *тогда* та же персона открывается по адресу `/en/people/{slug}` и полоса прокрутки сохраняется. *Дано* система в тёмной теме, в настройках «системная»; *когда* тема системы меняется; *тогда* сайт меняется без перезагрузки.
19. **UI.** Переключатели слева, поиск и вход справа — по `input/spec.md`; аватар открывает список кнопок, а не сразу профиль:

```
┌──────────────────────────────────────────────────────────────────┐
│ [☀/🌙] [RU▾]                              [ Поиск…  ] ( ⬤● )    │
│  ↑       ↑                    ↑ иконка уведомлений с красной      │
│  тема    язык                 точкой; в меню — число (до «99+»)   │
└──────────────────────────────────────────────────────────────────┘
```
   **Фокальная точка:** на публичной странице — поиск; в кабинете — имя пользователя. **Телефон:** переключатели темы и языка уходят в меню аватара; поиск — иконка, раскрывается в строку во всю ширину. **Планшет:** как десктоп, но иконки уведомлений без числа. **Скелетон:** высота строки равна боевой, внутри пусто.
20. **КП.** Скриншот на плакат «модели представления».

## F-00-03 Мобильная навигация (UI-05) · P0

1. **Назначение.** Сохранить доступ ко всем разделам на телефоне, не пряча навигацию под кнопкой «ещё».
2. **Роли.** Все.
3. **Триггер.** Ширина окна < 640 px.
4. **Сценарий.** Внизу экрана фиксированная панель: Главная, Каталог, Календарь, Закладки, Профиль. Текущий раздел отмечен. Смена раздела — переход, не модальное окно. Живая точка приклеена к нижней части, поэтому контент получает `padding-bottom`, равный высоте панели плюс безопасная зона (`env(safe-area-inset-bottom)`) — иначе последняя строка уезжает под панель.
5. **Альтернативы и ошибки.** Пять пунктов не помещаются на 320 px по ширине — сокращаются подписи, не размер иконки; цели касания ≥ 44 px в любом случае (`R-A11Y-09`). Клавиатура открыта — панель прячется, поле ввода не перекрыто.
6. **Состояния.** Пять пунктов · текущий отмечен · назад некуда (прямая ссылка на 404) — нижняя панель не показывается.
7. **Данные.** Маршруты `SCREENS`; позиция — текущий путь.
8. **Правила.**
   - (а) Панель — не `position: fixed` поверх контента, а элемент потока: это проще и не даёт прыжков.
   - (б) Число непрочитанных не рисуется в мобильной панели: там нет аватара, а «Календарь» и так перегружен.
   - (в) Меню жанров на касании — полноэкранный список с поиском, а не попап: на узком экране попап нечитаем.
   - (г) `hover`-механики с ПК не применяются: на касании раскрытие только по тапу (`G-14`).
9. **Валидация и лимиты.** Ширина точки касания ≥ 44 px, расстояние между соседними ≥ 8 px.
10. **Edge cases.** EC-O7.
17. **Побочные эффекты.** EV-01 при переходе; смена активного пункта.
18. **Приёмка.** *Дано* телефон 360 px; *когда* открыта страница серии; *тогда* нижняя панель видна, а последняя строка описания не перекрыта. *Дано* 320 px; *когда* панель отрисована; *тогда* все пять пунктов помещаются, цель касания каждого ≥ 44 px.
19. **UI.** Пять пунктов, подпись + иконка, текущий — акцентом и точкой:

```
┌─────────────────────────────┐
│                             │
│      содержимое страницы     │
│                             │
├─────────────────────────────┤
│  ⌂     ▦     ▤     ☆     ☺  │
│ Главн  Катал  Кален Закл Проф│  ← активный: акцент + точка сверху
└─────────────────────────────┘
```
   **Фокальная точка:** точка над активным пунктом плюс смена цвета — состояние не кодируется только цветом (`R-A11Y-19`). **Десктоп:** панели нет. **Планшет:** панели нет, rail есть. **Скелетон:** пять равных по ширине серых блоков с подписью-полосой.
20. **КП.** Диаграмма вариантов использования «навигация на телефоне».

## F-00-04 Скелетоны загрузки (UI-07) · P0

1. **Назначение.** Показать форму будущей страницы, чтобы вёрстка не прыгала и пользователь понимал, что загружается.
2. **Роли.** Все.
3. **Триггер.** Запрос данных экрана дольше `shell.skeleton_min_ms`.
4. **Сценарий.** На месте каждого блока — серый прямоугольник **тех же размеров**, что будет содержимое. Текстовые полосы повторяют длину реальных строк: заголовок — две полосы разной длины, описание — шесть одинаковых. У постеров заранее известна пропорция, поэтому прямоугольник занимает нужную высоту. Скелетон не показывается, если ответ пришёл быстрее порога — мигание хуже ожидания.
5. **Альтернативы и ошибки.** Ошибка загрузки — скелетон заменяется блоком с текстом и «Повторить», а не остаётся навсегда. Данные пришли частично — показываем пришедшее, скелетоны только на недостающем. Долгая загрузка (> 10 с) — добавляется строка «Ещё загружаем», чтобы скелетон не выглядел зависшим.
6. **Состояния.** Нет скелетона (быстрый ответ) · скелетон · скелетон с подсказкой · замена на ошибку.
7. **Данные.** Только форма: размеры и пропорции из разметки блока.
8. **Правила.**
   - (а) Ни одного скелетона без зарезервированного места: CLS = 0 — требование `R-PERF-03`, а не пожелание.
   - (б) Скелетон не мигает: анимация либо статичная, либо одна очень медленная волна; при `prefers-reduced-motion` — статичный (`R-DES-27`).
   - (в) Скелетон не блокирует страницу целиком: шапка и навигация уже настоящие.
   - (г) Размеры скелетонов не хранятся в коде константами, а вычисляются из того же блока, который потом заполняется, иначе они разъедутся при первой же правке вёрстки.
9. **Валидация и лимиты.** Скелетон дольше 10 с заменяется сообщением.
10. **Edge cases.** EC-O8.
17. **Побочные эффекты.** EV-20 `web_vitals` при замене скелетона.
18. **Приёмка.** *Дано* медленный ответ; *когда* страница открывается; *тогда* на месте постеров серые прямоугольники правильной пропорции и загрузка страницы не сдвигает ничего (CLS = 0). *Дано* быстрый ответ 120 мс; *тогда* скелетон не показывается вовсе.
19. **UI.** Форма повторяет будущую страницу, а не абстрактные полосы:

```

│▮▮▮▮▮▮▮          ← лого (реальный)         │
├──────────────────────────────────────────┤
```

   **Фокальная точка:** зарезервированное место первого постара — по нему CLS и считается. **Телефон:** одна колонка вместо шести. **Планшет:** три. **Десктоп:** шесть.
20. **КП.** Не выносится на чертежи.

## F-00-05 Служебные страницы: «О проекте и данных», приватность, ошибки (S-40, S-42, S-43) · P0

1. **Назначение.** Закрыть требования об атрибуции, согласии и понятных ошибках — иначе часть Бланка 3.3.3 и раздел об источниках данных не выполняются.
2. **Роли.** Все.
3. **Триггер.** Переход по ссылке в подвале; ошибка любого маршрута.
4. **Сценарий.** **S-40 «О проекте и данных»:** что за сервис, откуда данные (IMDb Datasets и TMDB с обязательной атрибуцией и логотипами), что делаем при отсутствии данных, как связаться. **S-42 «Конфиденциальность и cookies»:** что собираем, зачем, срок хранения, как отозвать согласие; само согласие — баннер снизу (UI-12). **S-43:** 404 — «Такой страницы нет» и три подсказки (в каталог, на главную, поиск); 403 — «Недостаточно прав», без указания, каких именно; 500 — «Что-то сломалось, попробуйте ещё раз», без стека; 429 — «Слишком много запросов, попробуйте через N минут», со временем; офлайн — «Нет соединения» и кнопка «Повторить».
5. **Альтернативы и ошибки.** Снятый с публикации сериал по старому адресу → 410 с объяснением и подборкой похожих. Неизвестная локаль → 404. Ошибка при отдаче картинки — заглушка с фокусной точкой из студии, страница при этом рабочая (`CONTENT` §4).
6. **Состояния.** Загрузка · содержимое · ошибка внутри страницы · пусто.
7. **Данные.** Статический текст (версионируется в репозитории); списки жанров и правил — из справочников M10.
8. **Правила.**
   - (а) Страницы ошибок — `noindex` и не содержат внутренних деталей: пользователю текст и следующий шаг, в журнал — причина (`R-SEC-33`).
   - (б) Каждая страница ошибок отвечает правильным кодом, а не «200 с текстом ошибки» — проверяется тестом.
   - (в) Ссылки «О данных» и «Приватность» есть в подвале на всех страницах, включая страницы ошибок.
   - (г) Текст согласия пишется по-русски и по-английски; отказ равноправен согласию, кнопки одинакового веса (`R-A11Y-14`).
   - (д) Атрибуция TMDB — логотип и текст в S-40, как того требуют условия использования (`DATA-SOURCES` §8).
9. **Валидация и лимиты.** Страницы отдаются без персонализации и без обращения к БД, кроме текущего согласия.
10. **Edge cases.** EC-O9, EC-O10.
17. **Побочные эффекты.** EV-19 `client_error` с кодом и маршрутом; на S-42 — запись согласия.
18. **Приёмка.** *Дано* запрошен несуществующий адрес; *тогда* ответ 404, страница `noindex`, в тексте нет имени таблицы и стека, есть три ссылки. *Дано* аналитика не загружена; *когда* пользователь не соглашался; *тогда* ни одного сетевого запроса к аналитике. *Дано* сериал снят с публикации; *тогда* ответ 410 с подборкой похожих.
19. **UI.** 404 как точка возврата, а не извинение:

```
┌──────────────────────────────────────────┐
│                                          │
│              404                          │  ← число крупно, но не
│      Такой страницы нет                   │     главный фокус
│                                          │
│   Возможно, сериал снят с публикации      │
│   или адрес набран с ошибкой.             │
│                                          │
│   [ В каталог ]  [ На главную ]  [ Поиск ]│
│                                          │
├──────────────────────────────────────────┤
│ О проекте и данных · Приватность · Правила│
└──────────────────────────────────────────┘
```
   **Фокальная точка:** первая кнопка «В каталог» — один primary, не «назад» и не «главная» (`R-DES-06`). **Телефон:** кнопки в столбик во всю ширину. **Планшет и десктоп:** в строку. **Скелетон:** не применяется — страницы статические и отдаются сразу.
20. **КП.** Не выносится на чертежи; S-40 и S-42 — скриншоты на плакат, если хватит места.

## F-00-06 Заставка (UI-06) · P1

1. **Назначение.** Дать узнаваемый первый экран и время на прогрев шрифтов и загрузку оболочки, не задерживая пользователя.
2. **Роли.** Все, включая тех, кто пришёл сюда впервые.
3. **Триггер.** Первая загрузка сайта в браузере; повторный показ — не чаще раза в 24 часа на одном устройстве, и только если пользователь не досмотрел до конца хотя бы один раз.
4. **Сценарий.** Оверлей поверх **уже загруженной** страницы: счёт от 1 до 25 со скоростью, рассчитанной так, чтобы уложиться в `splash.max_duration_ms`, затем кадры с наложенным блюром по кругу, кадры сменяются с затуханием `splash.fade_ms`. Культовые сцены узнаются сквозь блюр. Всё, что делает счётчик, идёт параллельно обычной загрузке. Пропуск — любой клавишей, кликом, тапом, `Esc`.
5. **Альтернативы и ошибки.** Кадров меньше `splash.frames_min` — заставка выключается, показывается только счёт. `prefers-reduced-motion` — ни счёт, ни смена кадров, только статичный кадр с логотипом; полностью отключается настройкой. Пользователь пробыл на заставке > 10 с — она закрывается сама. Ошибка загрузки кадров — заставка не показывается вовсе, страница обычная.
6. **Состояния.** Показывается · пропущена · завершена по времени · выключена по настройке.
7. **Данные.** Список кадров и фокусных точек — из студии (M10 F-10-09); счётчик не зависит от данных.
8. **Правила.**
   - (а) Заставка — оверлей, а не отдельная страница: контент под ней в HTML с первого байта. Иначе страдает и LCP, и индексация (`R-PERF-01`).
   - (б) Время заставки — не более `splash.max_duration_ms`; цель из `input/spec.md` — 5–7 секунд.
   - (в) Мерцание ограничено: не чаще `splash.flicker_max_per_s` смен кадра и разница средней яркости соседних кадров не больше `splash.flicker_brightness_delta`; иначе WCAG 2.3.1 (R-A11Y-20).
   - (г) Фокус не заперт внутри оверлея: клавиша `Tab` уводит за пределы заставки, и она закрывается.
   - (д) Бот и первый запрос из поисковика заставку не получают: она не должна попадать в скриншоты и в сниппеты.
9. **Валидация и лимиты.** Кадров от `splash.frames_min` до `splash.frames_max`; счётчик всегда `splash.counter_from`…`splash.counter_to`.
10. **Edge cases.** EC-O11, EC-O12, EC-O13.
17. **Побочные эффекты.** EV-02 `splash_shown`, `splash_skipped`; запись отметки «показывали ещё раз» в cookie.
18. **Приёмка.** *Дано* первый визит; *когда* прошло `splash.max_duration_ms`; *тогда* заставка закрылась сама, страница под ней полностью рабочая. *Дано* пользователь перескакивает заставку клавишей; *тогда* она не появится снова 24 часа. *Дано* включён `prefers-reduced-motion`; *тогда* нет ни смены кадров, ни счётчика.
19. **UI.** Оверлей, контент под ним живой:

```
┌──────────────────────────────────────────┐
│  ГЛАВНАЯ   ← контент уже загружен и виден │
│  ...                                      │     под полупрозрачным
│                                          │     слоем с блюром
│              1…25                        │  ← счёт, крупно
│         ░░░ кадр ░░░                     │
└──────────────────────────────────────────┘
   любая клавиша · клик · тап · Esc — пропуск
```
   **Фокальная точка:** центр — счётчик, он единственный элемент внимания. **Телефон:** то же, кадры 16:9 на всю ширину. **Планшет и десктоп:** то же, по центру. **Скелетон:** под заставкой работают скелетоны обычной страницы.
20. **КП.** Не выносится на чертежи.

## F-00-07 Раскладка и адаптив · P0

1. **Назначение.** Описать поведение раскладки на трёх контрольных ширинах, чтобы ни один экран не приходилось додумывать при вёрстке.
2. **Роли.** Все.
3. **Триггер.** Изменение ширины окна.
4. **Сценарий.** Три контрольные ширины: 360 (телефон), 768 (планшет), 1440 (десктоп) — плюс промежуточные 640 и 1024 как границы перестроения. Между границами раскладка тянется, но не перестраивается по колонкам. Ниже 1280 скрывается правая панель «Предстоящие» (M3) — по подтверждённому H-30. Ниже 640 rail заменяется нижней панелью.

6. **Состояния.** ≥ 1280 (три колонки) · 1024–1279 (две колонки) · 640–1023 (две колонки, узкая правая) · < 640 (одна колонка, нижняя панель).

8. **Правила.**

   - (б) Нижняя панель и верхняя — в потоке либо с компенсирующим отступом, никогда не поверх контента без резерва (F-00-03).

   - (г) Псевдолокаль проверена на всех трёх ширинах (`PLAN` §7, адаптив обязателен по DEC-001).
9. **Валидация и лимиты.** Ширина контента: максимум 1440 px, дальше поля, а не растягивание.
10. **Edge cases.** EC-O14.
17. **Побочные эффекты.** Нет; при переходе через границу сетка перестраивается, данные те же.
18. **Приёмка.** *Дано* окно 1440 → 768 → 360; *когда* проходят границы; *тогда* число колонок 6 → 3 → 1, навигация меняется один раз, CLS = 0 при всех переходах. *Дано* 1300 px; *тогда* правая панель есть.

20. **КП.** Диаграмма размещения на листе А4.

## F-00-08 Доступность с клавиатуры и на касании · P0

1. **Назначение.** Сделать все hover-механики доступными без мыши — иначе часть интерфейса недоступна, а требования `A11Y` и WCAG 2.2 AA не выполняются.
2. **Роли.** Все.
3. **Триггер.** Наведение, фокус, тап, нажатие клавиши.
4. **Сценарий.** У каждой hover-механики есть эквивалент: раскрытие rail (F-00-01) — фокус и тап; карточка постера (M2 UI-10) — фокус и тап; меню жанров (F-00-01) — фокус, `Esc` закрывает; бегущая строка подборок (M6) — пауза по фокусу и по наведению, а кнопки «вправо/влево» для прокрутки вручную. Полный порядок обхода: подвал → пропуск по меню → rail → верхняя панель → контент. Видимый фокус у всех интерактивных элементов, ни разу не обрезанный родительским `overflow`.
5. **Альтернативы и ошибки.** Пользователь отключил анимацию — переходы мгновенные, функциональность та же. Экран озвучивания — у всех полей есть подпись, ошибки связаны через `aria-describedby`.
6. **Состояния.** Наведение · фокус с клавиатуры · тап · нажатие · отключённые элементы (не кликабельны и не в фокусе).
7. **Данные.** Порядок обхода — из разметки; обработчики — на элементах.
8. **Правила.**
   - (а) Ни один элемент не доступен только по наведению — это прямое нарушение WCAG 2.1.1.
   - (б) `prefers-reduced-motion: reduce` отключает счётчик заставки, смену кадров, разворот rail и бегущую строку (`R-DES-27`).
   - (в) Целевые размеры ≥ 44 px на касании; между соседними целями ≥ 8 px.
   - (г) Клавиатурные сокращения не перехватывают обычный ввод в поле: пробел в текстовом поле вставляет пробел.
   - (д) Пропуск по меню — первая ссылка в порядке фокуса, видна при Tab.
9. **Валидация и лимиты.** Сквозной прогон вкладкой по каждой контрольной ширине — обязательная проверка перед выпуском (`TESTING` R-TST-04).
10. **Edge cases.** EC-O4, EC-O7.
17. **Побочные эффекты.** Нет.
18. **Приёмка.** *Дано* страница каталога без мыши; *когда* пользователь проходит вкладкой; *тогда* rail открывается по фокусу, карточка постера раскрывается по фокусу, бегущая строка останавливается, а всё управление достижимо. *Дано* включён `prefers-reduced-motion`; *тогда* анимаций нет, функции те же.
19. **UI.** Один фокус — одна рамка, видимая на любом фоне:

```
┌──────────────────────────────────────────┐
│▌Пропустить к содержимому▐  ← первый Tab   │
│                                          │
│ ▸ rail    [ Фокус ]  ← рамка 2 px,       │
│                          контраст ≥ 3:1  │
│                                          │
└──────────────────────────────────────────┘
```
   **Фокальная точка:** на любой ширине ровно один фокус, рамка не перекрывается соседями. **Телефон:** проверяется отдельно — порядок обхода ведёт по нижней панели. **Скелетон:** фокус на скелетон не попадает, он `aria-busy`.
20. **КП.** Не выносится на чертежи.

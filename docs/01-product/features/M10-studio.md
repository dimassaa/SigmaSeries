# M10 — Контент-студия (раздел админа): глубокая спека

> v0.1 · Фаза 4 · P0 минимум, остальное P1 · экраны S-73…S-80 · операция OP-07 (расчёт полноты — в M12). Студия закрывает пробелы данных и ведёт кураторские части (DEC-005, DEC-008). Опирается на `M12-import` (коды причин, происхождение полей), `CONTENT-PLAN`, `ROLES-PERMISSIONS`, `SECURITY`, `A11Y`. Метки: **[ГИПОТЕЗА]**, **[проверить]**. Номера измерений — по `PLAN` §5.

## 0. Сквозное для модуля

**Роли.** Только админ (дополнительная роль, 2FA обязательна, `R-SEC-04`). Для остальных все адреса раздела отвечают 404 (`R-SEC-35`). Каждое изменение — в аудит (`R-SEC-36`) и в историю версий карточки.

**Принципы.** (1) **Ручное побеждает импорт:** любое вручную изменённое поле блокируется от перезаписи автоматически (H-41); рядом видно происхождение (IMDb / TMDB / вручную), и если импорт «предлагает» другое значение, студия показывает его с кнопкой «Принять». (2) **Очередь должна уметь опустеть:** причину можно «принять как есть» (H-47). (3) **Данные не теряем:** окончательное удаление только без зависимых данных (C-09), иначе архив.

**Сессия админа и долгая правка.** Для служебных ролей простой 30 минут (`R-SEC-03`). Чтобы не терять работу: пока пользователь печатает или двигает элементы, страница продлевает сессию (по реальному вводу за последние 5 минут), а несохранённые изменения копируются в браузер и восстанавливаются после повторного входа (H-42, EC-S1).

**Адаптивность.** Экраны рассчитаны на ≥ 1024 px; на меньших работают в одну колонку, но без перетаскивания, предпросмотра изображений и массовых операций (H-48).

**Сквозное качество (измерения 11–16):**

| Измерение | Для модуля |
|---|---|
| 11 i18n | Интерфейс студии — ru и en; поля контента — ru обязателен, en желателен (`CONTENT-PLAN` §3 не меняется); коды причин — ключи каталога |
| 12 a11y | Перетаскивание всегда с кнопочной альтернативой (`R-A11Y-09`); фокальная точка — клик, числовые поля, стрелки; таблицы с заголовками; ошибки у поля и в `aria-live` (`R-A11Y-11`); диалоги удерживают фокус; несохранённое — предупреждение при уходе |
| 13 SEO | Не применимо (`noindex`, закрыто `robots`, 404 для чужих) |

## F-10-01 Список сериалов (S-73) · P0

1. **Назначение.** Видеть весь каталог, находить нужное и состояние каждой карточки.
2. **Роли.** Админ.
3. **Триггер.** Переход в «Каталог» админки.
4. **Сценарий.** Таблица (50 строк на страницу): миниатюра постера · название ru / оригинал · год · состояние публикации (Импортирован / Опубликован / В архиве) · состояние выхода · уровень полноты (Минимум / К показу / Полная) · причины (значки с кодами) · «куда можно поставить» (чипы: Баннер, Заставка, Календарь, Новинки) · ранг и голоса IMDb · обновлено · число блокировок. Фильтры: поиск (название, `tconst`, `tmdb_id`), состояние публикации, состояние выхода, уровень, причины (несколько), жанр, годы, «есть блокировки», «добавлен вручную». Сортировка: популярность (по умолчанию), обновлено, название. Строка открывает S-75; стрелки и Enter работают с клавиатуры.
5. **Альтернативы и ошибки.** Каталог пуст → «Каталог пуст — запустите импорт» со ссылкой на S-76; фильтр без результата → «Сбросить»; ошибка загрузки → сообщение и «Повторить».
6. **Состояния.** Загрузка (строки фиксированной высоты) · пусто · ошибка · нет прав (404).
7. **Данные.** Поля карточек, состояния и причины из M12; «куда можно поставить» вычисляется на сервере и кэшируется до следующего изменения карточки.
8. **Правила.** Блокирующие причины подсвечиваются раньше остальных; информационные (например, `no_age`) — серым.
9. **Валидация и лимиты.** `page` ≥ 1, размер страницы фиксирован; значения фильтров — белый список.
10. **Edge cases.** EC-S16.
17. **Побочные эффекты.** Нет (только чтение). Экспорт CSV — P1.
18. **Приёмка.** *Дано* каталог из 1250 карточек; *когда* админ открывает S-73; *тогда* видит первую страницу по популярности, p95 ответа ≤ 300 мс, у каждой строки видны уровень и причины. *Дано* фильтр «причина = `no_backdrop`»; *тогда* только такие карточки.
19. **UI.** Плотная таблица, фокус — колонка «название + уровень»; фильтры сверху в одну строку; на < 1024 px — карточки-строки.
20. **КП.** Скриншот на плакат (рабочие окна).

## F-10-02 Очередь неполных карточек и сомнительных пар (S-74) · P0

1. **Назначение.** Привести каталог к состоянию «всё нужное есть» с минимумом ручной работы.
2. **Роли.** Админ.
3. **Триггер.** Раздел «Неполные»; ссылка из отчёта импорта (S-76).
4. **Сценарий.** Вверху счётчики по классам причин (блокирует · размещение · содержание · служебные), главное число — **«осталось N»** (без информационных и принятых причин), рядом информация: «Ждём сезон: N (не дефект)», «без возраста: N». Три вкладки: **«Неполные»** (по умолчанию) · **«Сомнительные пары»** · **«Ждём сезон»** (справочно: можно вручную ввести известную дату). Строка: миниатюра, название, чипы причин, ранг, «Открыть» (в S-75 на нужной вкладке), «Принять причину как есть». Сортировка — по приоритету из `M12` F-12-06: блокирующие → размещение (сначала с высоким рангом) → содержание → служебные.
5. **Альтернативы и ошибки.** Нет неполных → «Всё заполнено» с датой последнего пересчёта. Причина исчезла после импорта — строка уходит сама. Сомнительная пара: карточка сравнения «IMDb ↔ TMDB» (название, оригинал, год, жанры, голоса / название, оригинал, год, постер, фрагмент описания, IMDb-идентификатор из TMDB) и действия: **«Подтвердить пару»** (применяются данные TMDB), **«Указать другой TMDB id»** (с предпросмотром найденной карточки), **«Нет в TMDB»** (публикация по минимуму из IMDb), **«Исключить из каталога»** (архив + запись в список исключений, чтобы импорт не вернул сериал).
6. **Состояния.** Загрузка (скелет счётчиков и 10 строк) · пусто («Всё заполнено») · ошибка.
7. **Данные.** Причины из M12 F-12-06; E-AcceptedReason (сериал, код, кто, когда); E-Exclusion (`tconst` или `tmdb_id`, кто, когда, причина).
8. **Правила.** (а) «Принять как есть» убирает причину из «осталось», но она остаётся в фильтрах; **если данные поля изменились и причина исчезла, принятие снимается автоматически** (EC-S14) (H-47). (б) «Ждём сезон» неполнотой не считается. (в) Исключение — явное действие админа; обычный выход из топ-1000 сериал в каталоге сохраняет (EC-D7). (г) Режим «по одному» (P1): после сохранения открывается следующий элемент текущего фильтра.
9. **Валидация и лимиты.** `tmdb_id` — положительное целое; при подтверждении пары повторно проверяется год (±1), обратный идентификатор показывается как предупреждение, если не совпал, и требуется явное подтверждение.
10. **Edge cases.** EC-S13, EC-S14, EC-S2.
17. **Побочные эффекты.** Подтверждение пары запускает точечное обогащение (M12 F-12-03, F-12-05) этого сериала; исключение — аудит и скрытие; каждое действие — запись в аудит.
18. **Приёмка.** *Дано* 3 сериала с `no_backdrop` и 1 с `pair_doubt`; *когда* админ открывает S-74; *тогда* счётчик «осталось 4», сомнительная пара — в своей вкладке. *Дано* админ принял причину `no_overview_ru`; *тогда* «осталось» уменьшилось на 1. *Дано* после импорта появилось описание ru; *тогда* принятие снято, причина не показывается. *Дано* «Исключить из каталога»; *когда* следующий импорт; *тогда* сериал не добавлен.
19. **UI.**

```
┌ Неполные ───────────────────────────────────────────────────────┐
│  осталось      блокирует · размещение · содержание · служебные   │
│   ▉▉ N        n    ·    n     ·    n     ·    n                  │
│  Ждём сезон: N (справочно) · без возраста: N (инфо)              │
│ [Неполные] [Сомнительные пары] [Ждём сезон]                      │
│ ┌──┐ Название      [no_backdrop] [no_overview_ru]   Открыть ▸   │
│ │П │ ранг · год    Принять причину ▾                              │
│ └──┘                                                              │
└──────────────────────────────────────────────────────────────────┘
```
    **Фокальная точка:** число «осталось N» (левая треть, крупно); основное действие в строке — «Открыть» (один primary на строку). **Третьи:** слева — счётчик, в центре — список, справа — действия строки. **Скелетон:** счётчик и 10 строк. Карточка сравнения пар — два столбца с постерами, кнопки внизу; на < 1024 px столбцы друг под другом.
20. **КП.** Схема алгоритма приоритета очереди (дополнительно к схеме модерации).

## F-10-03 Правка карточки (S-75) · P0

1. **Назначение.** Исправить и дополнить данные сериала, сохранив происхождение и защиту от перезаписи.
2. **Роли.** Админ.
3. **Триггер.** Строка из S-73 или S-74; прямая ссылка.
4. **Сценарий.** Вкладки: **Основное** (названия ru / en / оригинал, годы, статус источника, страны, каналы) · **Тексты** (описание ru / en) · **Жанры и ключевые слова** · **Люди** (режиссёры, создатели, актёры: порядок, роль, персонаж; поиск человека или создание) · **Возраст** (RU, BY — ручное значение) · **Рейтинги** (IMDb и TMDB — только чтение с датой снятия; ручные платформы: платформа, значение, шкала, голоса, ссылка, дата снятия) · **Изображения** (F-10-04) · **Серии** (F-10-05) · **Служебное** (публикация, сопоставление с TMDB, `slug`, история, блокировки, принятые причины). Справа постоянно: **панель полноты** — уровень, причины, «куда можно поставить», мини-предпросмотр карточки.
5. **Альтернативы и ошибки.** Конфликт версии (другой админ сохранил раньше) → показ различий по полям и выбор «оставить моё / взять чужое». Потеря связи при сохранении → изменения остаются в форме и в локальном черновике. Ошибка валидации → у поля и в сводке сверху.
6. **Состояния.** Загрузка (скелет вкладки и панели полноты) · нет изменений (кнопка «Сохранить» неактивна) · есть несохранённые (предупреждение при уходе) · конфликт · ошибка · нет прав (404).
7. **Данные.** Поля по `DATA-SOURCES` §2; у каждого поля: значение, источник, блокировка, **последнее импортированное значение**; версия карточки (целое, растёт при каждом сохранении).
8. **Правила.** (а) Правка поля ставит блокировку автоматически (H-41); кнопка «Сбросить к импорту» снимает блокировку и возвращает последнее импортированное значение. (б) Если у заблокированного поля импорт предложил новое значение — рядом «Импорт предлагает: …» + «Принять» (EC-S3). (в) Жанры — только из справочника; без жанра сохранить для публикации нельзя. (г) Изменение `slug` создаёт запись для 301 и показывает предупреждение. (д) Сохранение — явное; быстрая клавиша Ctrl+S.
9. **Валидация и лимиты.** Название ≤ 300 знаков, описание ≤ 5000; годы от 1900 до текущего + 5; рейтинг в границах шкалы платформы (EC-C9); не более 10 актёров; ключевых слов ≤ 50; всё по схеме на сервере (`R-SEC-13`).
10. **Edge cases.** EC-S1, EC-S2, EC-S3, EC-S11, EC-C9.
17. **Побочные эффекты.** Запись версии и аудита; пересчёт полноты и «куда можно поставить»; сброс кэшей карточки, списков, поиска; если изменены даты — F-10-05.
18. **Приёмка.** *Дано* админ изменил описание ru; *когда* повторный импорт; *тогда* описание не изменилось, у поля «вручную». *Дано* два админа открыли карточку; *когда* второй сохраняет после первого; *тогда* видит конфликт и различия. *Дано* введён рейтинг 11 на шкале 0–10; *тогда* ошибка у поля, сохранение невозможно.
19. **UI.**

```
┌ Название сериала ──────────────  [Сохранить] (primary)           ┐
│ Основное│Тексты│Жанры│Люди│Возраст│Рейтинги│Изображения│Серии│Служ.│
│ ┌ форма (центр, 2 трети) ───────────────────┐ ┌ панель (правая) ┐│
│ │ Название ru [......] ⓘ IMDb 🔒             │ │ Полнота: К показу││
│ │ Название en [......] ⓘ TMDB                │ │ причины: …       ││
│ │ Описание ru [......] ⓘ вручную 🔒          │ │ можно поставить: ││
│ │   Импорт предлагает: «…» [Принять]         │ │ предпросмотр     ││
│ └────────────────────────────────────────────┘ └──────────────────┘│
└────────────────────────────────────────────────────────────────────┘
```
    **Фокальная точка:** форма; главное действие — «Сохранить» (один primary). **Третьи:** форма занимает центр и левую треть, панель полноты — правая треть. **Скелетон:** заголовок, 6 строк формы, панель. **< 1024 px:** панель полноты уходит под форму.
20. **КП.** Диаграмма последовательности «ручная правка и импорт» (блокировка полей).

## F-10-04 Изображения и фокальная точка · P0

1. **Назначение.** Заменить или добавить изображение и управлять тем, как его обрежет интерфейс.
2. **Роли.** Админ.
3. **Триггер.** Вкладка «Изображения» карточки, баннера подборки (F-10-07), кадра заставки (F-10-09).
4. **Сценарий.** Выбор роли (постер · фон · баннер подборки · кадр заставки) → загрузка перетаскиванием или выбором файла → проверка → обработка (перекодирование без метаданных, варианты, как в `M12` F-12-05) → показ с **выбором фокальной точки**: клик по изображению ставит метку; поля X и Y (0–100%); стрелки клавиатуры двигают на 1%, с Shift — на 5%; «Сбросить» возвращает (2/3, 1/3) (H-33). Предпросмотры (на одном и том же коде обрезки, что в продакшене): **«Баннер на главной»** (16:9 с зоной левой трети под текст), **«Шапка на телефоне»** (4:5), **«Карточка»** (2:3, для постера), **«Заставка»** (размытие).
5. **Альтернативы и ошибки.** Файл слишком мал → отказ с требуемыми размерами; не та пропорция (отклонение > 3%) → автообрезка по фокальной точке с предупреждением (EC-C5); неверный тип по содержимому или > 10 МБ → отказ; ошибка обработки → «Повторить», прежнее изображение остаётся.
6. **Состояния.** Нет изображения · загрузка с прогрессом · обработка · готово · ошибка; поле, заменённое вручную, — блокировка.
7. **Данные.** E-Image, E-ImageVariant (как в M12); признак «на изображении есть текст» — флажок при загрузке (по умолчанию «нет»; для баннера и заставки «с текстом» не допускается, H-34).
8. **Правила.** Требования: постер ≥ 500×750, 2:3; фон, баннер подборки, кадр заставки ≥ 1920×1080, 16:9 **[ГИПОТЕЗА]**; допускаются JPEG, PNG, WebP; ≤ 10 МБ; ручное изображение блокирует поле; предпросмотр предупреждает, если фокальная точка ближе 10% к краю (EC-S6). **P1:** выбор из сохранённых кандидатов TMDB (галерея с языком, размером, оценкой).
9. **Валидация и лимиты.** `R-SEC-17` (тип по содержимому, лимит байтов и размеров, перекодирование, имена генерируются); X и Y — числа 0–100.
10. **Edge cases.** EC-C5, EC-S5, EC-S6.
17. **Побочные эффекты.** Новая версия адреса изображения (сброс кэша); пересчёт `no_poster` / `no_backdrop` и «куда можно поставить»; запись в аудит и историю.
18. **Приёмка.** *Дано* загружен фон 1920×1080; *когда* админ ставит точку на (70, 30); *тогда* в «Баннере на главной» объект остаётся в кадре, сохранены три варианта. *Дано* файл 800×450; *тогда* отказ «нужно не меньше 1920×1080». *Дано* заменён постер вручную; *когда* повторный импорт; *тогда* постер не заменён.
19. **UI.** Слева изображение с меткой и подсветкой третей, справа — вкладки предпросмотра; поля X/Y под изображением. **Фокус:** изображение с меткой. Скелет — серая плашка нужной пропорции. На < 1024 px предпросмотры — переключатель под изображением.
20. **КП.** Диаграмма деятельности «Загрузка изображения».

## F-10-05 График серий · P0

1. **Назначение.** Исправлять и задавать даты выходов, когда источник их не знает.
2. **Роли.** Админ.
3. **Триггер.** Вкладка «Серии» карточки; «Ждём сезон» — ввод известной даты.
4. **Сценарий.** По сезонам: таблица серий (номер, название ru / en, дата, время (необязательно), точность «дата» / «дата и время», состояние Анонс / Запланирован / Вышел / Перенесён / Отменён, длительность). Серии с одной датой сгруппированы в «выход: N серий {дата}». **Генератор:** «сезон N: K серий, дни недели (несколько), с даты X, шаг (каждую неделю / раз в две недели), время (необязательно)» + режим **«все серии в один день»** → предпросмотр списка → политика при пересечении (**«только пустые»**, **«перезаписать»**, **«только будущие»**) → применить. Также: «сдвинуть всё на N дней», очистка даты (TBA), добавление серии вручную (для отсутствующих в TMDB).
5. **Альтернативы и ошибки.** Пересечение с существующими датами → предпросмотр различий; нарушена монотонность дат по номерам → предупреждение (можно подтвердить); серия с отметками пользователей — удалить нельзя, только скрыть (EC-S8); дата в прошлом у ещё не «вышедшей» серии → допускается как исправление с предупреждением, состояние станет «Вышел» (EC-S9).
6. **Состояния.** Загрузка (строки таблицы) · пусто (нет серий → «График уточняется», кнопка генератора) · ошибка.
7. **Данные.** Выход: сезон, серия или группа, дата, время, часовой пояс ввода (хранится в UTC), точность, состояние, блокировка даты.
8. **Правила.** (а) Ручное изменение даты блокирует поле у этой серии от перезаписи импортом (H-41). (б) Время указывается в выбранном админом поясе, хранится в UTC; при отсутствии времени точность — «дата». (в) Изменение даты у выхода, который уже был объявлен или находится в окне, порождает событие `release_changed` (M3, OP-09; EC-C3, EC-D5). (г) Появление даты у сериала «Ждём сезон» порождает `schedule_announced` (P1, H-26). (д) Состояние выхода сериала пересчитывается сразу после сохранения.
9. **Валидация и лимиты.** Номера серий уникальны в сезоне; ≤ 500 серий в сезоне; дата от 1900 до `import.until` + 3 года; номер сезона ≥ 0 (0 — спецвыпуски).
10. **Edge cases.** EC-S7, EC-S8, EC-S9, EC-C4, EC-D11.
17. **Побочные эффекты.** События для M3, пересчёт календаря, «Предстоящих», «Новинки дня»; аудит и версия.
18. **Приёмка.** *Дано* «сезон 2: 8 серий, по средам, с 15.10»; *когда* применить; *тогда* созданы 8 дат с шагом в неделю, у всех блокировка даты. *Дано* режим «все серии в один день»; *тогда* одна группа «8 серий». *Дано* дата уже объявленной серии перенесена; *тогда* подписчики получают уведомление (проверяется в M3).
19. **UI.** Таблица сезона слева, генератор справа в виде панели; предпросмотр — список дат. **Фокус:** таблица. На < 1024 px генератор — отдельный шаг.
20. **КП.** Алгоритм генерации дат — в ПЗ 4.2.4.

## F-10-06 Публикация, архив, удаление, история · P0

1. **Назначение.** Управлять жизненным циклом карточки без потери данных.
2. **Роли.** Админ; окончательное удаление — с повторным паролем (`R-SEC-12`, ◐¹).
3. **Триггер.** Вкладка «Служебное».
4. **Сценарий.** **Опубликовать** — доступно при минимуме (название, год, ≥ 1 жанр, состояние); иначе кнопка заблокирована, перечислены причины. **В архив** — показывает зависимые: записи в расписании баннеров, подборки, число пользователей со статусами и отметками, отзывы; после подтверждения карточка скрыта с главной, из поиска и карт сайта, адрес отвечает 410. **Вернуть из архива.** **Удалить окончательно** — только если зависимых нет; иначе предлагается архив. **История:** список версий (кто, когда, какие поля, источник — вручную / импорт) и «Откатить к версии» (создаёт новую версию с прежними значениями и блокирует эти поля).
5. **Альтернативы и ошибки.** Удаление при зависимых данных → отказ с перечнем; ошибка посреди операции → откат транзакции; потеря пароля при повторном вводе → операция не выполняется.
6. **Состояния.** Импортирован → Опубликован → В архиве (`STATES`); «Исключён» — запись в списке исключений.
7. **Данные.** E-CatalogVersion (карточка, версия, автор, время, различия, источник), E-Exclusion, E-AuditLog.
8. **Правила.** Архив обратим, удаление — нет; после удаления предлагается «не добавлять повторно» (запись в исключения); импорт архивные карточки обновляет, но не публикует; история хранится не короче журнала аудита (`SECURITY` §4).
9. **Валидация.** Повторный пароль при удалении; подтверждение вводом названия сериала **[ГИПОТЕЗА]**.
10. **Edge cases.** EC-S4, EC-C1, EC-R3.
17. **Побочные эффекты.** Сброс кэшей, обновление карт сайта, 410 для адреса, пересчёт подборок (EC-K8), уведомление админу, если подборка опустела.
18. **Приёмка.** *Дано* карточка без жанра; *тогда* «Опубликовать» недоступна, причина `no_genre`. *Дано* сериал в 2 подборках и у 5 пользователей; *когда* архивирование; *тогда* показаны зависимые, после подтверждения адрес 410, подборки пересчитаны. *Дано* есть отметки пользователей; *когда* «Удалить окончательно»; *тогда* отказ.
19. **UI.** Кнопки по состояниям; опасные — вторичные, красные только в подтверждении. История — список с различиями.
20. **КП.** Диаграмма состояний сериала.

## F-10-07 Подборки вручную (S-77) · P0

1. **Назначение.** Без подборок бегущая строка главной пуста; админ собирает тематические наборы (DEC-005).
2. **Роли.** Админ.
3. **Триггер.** Раздел «Подборки».
4. **Сценарий.** Список: название, число видимых сериалов, видимость, вес. Создание и правка: название ru (обязательно) / en, описание ru / en (до 500 знаков), `slug` (авто, можно править до публикации), **баннер** (по умолчанию фон первого сериала; можно загрузить свой с фокальной точкой, F-10-04), **сериалы:** поиск по каталогу (только опубликованные) → добавление; порядок перетаскиванием **и** кнопками «выше / ниже / в начало / в конец» и числом; удаление; видимость (черновик / опубликована); **вес** (целое, чем больше — тем раньше в бегущей строке; до включения авто-порядка по просмотрам, H-31).
5. **Альтернативы и ошибки.** Публикация при < 6 видимых сериалов или без ru-описания или без баннера — блокируется с перечнем причин; сериал в подборке стал неопубликованным — помечается «снят», в публичной выдаче скрыт, подборка автоматически скрывается при падении ниже 6 (EC-C6), админ получает служебное уведомление **[ГИПОТЕЗА]**.
6. **Состояния.** Черновик · Опубликована · Скрыта автоматически (мало сериалов).
7. **Данные.** E-Collection (`slug`, названия, описания, баннер, вес, состояние), E-CollectionItem (подборка, сериал, позиция).
8. **Правила.** До 100 сериалов в подборке; дубликаты запрещены; бегущая строка показывает 6 опубликованных подборок с наибольшим весом, при равенстве — более новые; предпросмотр бегущей строки в форме. **Подборки по правилам — P1** (OP-18).
9. **Валидация и лимиты.** Название ≤ 100, описание ≤ 500, `slug` уникален (латиница, цифры, дефис); вес 0–999.
10. **Edge cases.** EC-S10, EC-S11, EC-C6, EC-K8.
17. **Побочные эффекты.** Сброс кэша главной и страницы подборки; обновление карты сайта; аудит.
18. **Приёмка.** *Дано* подборка из 8 сериалов с баннером и описанием; *когда* публикация; *тогда* она появляется на главной по весу и по адресу `/collections/{slug}`. *Дано* 5 сериалов; *тогда* публикация заблокирована с перечнем. *Дано* порядок меняется кнопкой «выше»; *тогда* результат тот же, что при перетаскивании.
19. **UI.** Слева форма, справа — список выбранных сериалов с постерами (двухколоночная раскладка); **фокус:** список сериалов. Предпросмотр — как плашка бегущей строки.
20. **КП.** Диаграмма классов (подборка–сериал).

## F-10-08 «Выбор редакции» и предпросмотр баннеров (S-78) · P1

1. **Назначение.** Назначать «выбор редакции» на даты и видеть, что получится на главной.
2. **Роли.** Админ.
3. **Триггер.** Раздел «Баннеры».
4. **Сценарий.** Календарь месяца: в каждой ячейке назначенный сериал (миниатюра) или «авто». Назначение — поиск по сериалам, пригодным для баннера (`no_backdrop` нет); выбор даты. Для выбранной даты — **предпросмотр трёх баннеров** по правилам OP-05: «Новинка» (или какой запасной вариант сработал: «серия за 7 дней» / «ручной выбор»), «Классика», «Выбор редакции». Подсказка «автозаполнить пустые дни»: лучший по рейтингу из не показывавшихся 14 дней.
5. **Альтернативы и ошибки.** Назначенный сериал потерял пригодность (архив, нет фона) → день подсвечен, работает автовыбор (EC-S17); один сериал дважды в пределах 14 дней → предупреждение; прошлые даты — только чтение.
6. **Состояния.** Загрузка (сетка месяца) · пусто (все дни «авто») · ошибка.
7. **Данные.** E-EditorsPick (дата, сериал, кто назначил).
8. **Правила.** Без назначения «Выбор редакции» выбирается автоматически (`CONTENT-PLAN` §2); предпросмотр использует тот же код выбора, что главная.
9. **Валидация.** Дата не в прошлом; сериал опубликован и годен.
10. **Edge cases.** EC-S17, EC-C11, EC-C12.
17. **Побочные эффекты.** Сброс кэша баннеров дня; аудит.
18. **Приёмка.** *Дано* на завтра назначен сериал X; *когда* наступает день; *тогда* «Выбор редакции» — X. *Дано* X в архиве; *тогда* работает автовыбор, день подсвечен у админа.
19. **UI.** Календарь слева (две трети), предпросмотр баннеров справа. **Фокус:** выбранная дата.
20. **КП.** Операция OP-05 (описание в M6).

## F-10-09 Кадры заставки (S-79) · P1

1. **Назначение.** Подобрать 12–16 узнаваемых кадров для вступительной заставки.
2. **Роли.** Админ.
3. **Триггер.** Раздел «Заставка».
4. **Сценарий.** Поиск сериала → выбор годного фона → добавление в список; порядок кнопками и перетаскиванием; у каждого кадра — фокальная точка (F-10-04); при сохранении создаётся заранее размытая копия. **Предпросмотр** проигрывает заставку (счёт 1→25 и смену кадров) и показывает проверку мерцания: **смена кадров не чаще 4 раз в секунду** и **разница средней яркости соседних кадров ≤ 20%** (**[ГИПОТЕЗА]**, держит число «вспышек» ниже порога WCAG 2.3.1); при нарушении — предупреждение и подсказка поменять порядок.
5. **Альтернативы и ошибки.** Кадров меньше 12 → заставка автоматически выключена, предупреждение; больше 16 → нельзя добавить; кадр потерял пригодность (сериал в архиве) → кадр отключён.
6. **Состояния.** Нет кадров · меньше 12 (заставка выключена) · 12–16 (готово) · ошибка.
7. **Данные.** E-SplashFrame (изображение, порядок, фокальная точка, включён).
8. **Правила.** Только годные фоны без текста ≥ 1920 px (H-34); заставка использует размытые копии, не `filter` на больших картинках (`R-PERF-13`).
9. **Валидация.** От 12 до 16 включённых кадров; порядок — уникальные позиции.
10. **Edge cases.** EC-S18.
17. **Побочные эффекты.** Сброс кэша заставки; аудит.
18. **Приёмка.** *Дано* 11 кадров; *тогда* заставка выключена и в студии предупреждение. *Дано* 14 кадров со слишком резкой сменой яркости; *тогда* предпросмотр показывает предупреждение.
19. **UI.** Лента кадров с номерами, справа предпросмотр. **Фокус:** предпросмотр.
20. **КП.** Скриншот предпросмотра.

## F-10-11 Массовые операции · P1

1. **Назначение.** Исправлять одинаковое сразу у многих.
2. **Роли.** Админ.
3. **Триггер.** Выделение строк в S-73 / S-74 («страница» или «всё по фильтру»).
4. **Сценарий.** Действия: добавить или убрать жанр; опубликовать или архивировать (только допустимым); снять или поставить блокировку поля; принять причину. Подтверждение показывает число затронутых и примеры; выполнение — фоновая задача с прогрессом и итогом по каждому.
5. **Альтернативы и ошибки.** Часть элементов не подошла (нельзя опубликовать без минимума) → пропущены с причиной, остальные выполнены (EC-S15); сбой — повтор только упавших.
6. **Состояния.** Выбор · подтверждение · выполняется · готово с отчётом · частично.
7. **Данные.** Задание (действие, фильтр, число, результаты).
8. **Правила.** Не более 200 элементов за операцию **[ГИПОТЕЗА]**; одна запись аудита на операцию + версия у каждой карточки; отмены нет — для точечного возврата служит история.
9. **Валидация.** Все элементы проходят проверки одиночного действия.
10. **Edge cases.** EC-S15.
17. **Побочные эффекты.** Сброс кэшей, пересчёт полноты.
18. **Приёмка.** *Дано* выбрано 50 карточек и действие «добавить жанр»; *когда* подтверждение; *тогда* 50 версий, одна запись аудита, отчёт «50 из 50».
19. **UI.** Панель действий над таблицей; модальное подтверждение. **Фокус:** кнопка подтверждения.
20. **КП.** Не выносится на чертежи.

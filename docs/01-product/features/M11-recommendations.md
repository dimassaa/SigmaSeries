Опирается на `M3-tracking` (точные отметки, статусы), `M4-reviews` (оценки), `M2-catalog` F-02-08 («Похожие», базовый), `M6-home` F-06-06, `E-TasteSeed` (`DOMAIN-MODEL` §4), `GLOSSARY` (рекомендации ≠ похожие). ## 0. Сквозное для модуля

**Разница, которую чаще всего путают.** В проекте два разных механизма, и они не смешиваются ни в одном списке:

- **«Похожие»** (M2 F-02-08, P0) — про сериал, который открыт: похожие на него. Основано на жанрах, ключевых словах и людях. Работает без истории пользователя.
- **«Для вас»** (этот модуль, P1) — про самого пользователя: что ему вообще может понравиться. Основано на его истории.

На главной это две разные строки с разными заголовками. Если показать «похожие к последнему открытому» под заголовком «Для вас», человек получит ложное обещание.

**Что вообще можно знать о вкусах.** Три источника, по убыванию веса: **точные** отметки просмотра (самый сильный сигнал — человек потратил время), **оценки** (сильный, но искажённый: ноль любят только ставить), **любимые из регистрации** (`E-TasteSeed`, самый слабый — три названия на три года). Ретро-отметки не участвуют, как и в `M7`.

**Объяснимость — требование, а не украшение.** У каждой рекомендации есть причина, которую видно пользователю: «похоже на Лучшие сезоны», «потому что вы отметили Драму». Рекомендация без причины не показывается — она выглядит как догадка, а человек вправе спросить «откуда».

**Никаких внешних сервисов.** Ни рекомендательных систем SaaS, ни эмбеддингов. Всё считается на данных, которые уже есть в базе.

**Холодный старт.** Новый пользователь без истории видит «Популярное» (M6 F-06-06), а не пустую строку. Любимые из регистрации дают первое приближение, но не переносятся в «просмотрено» (H-55).

**Сущности:** `e_taste_seed`, `e_reco_dismiss` (из `DOMAIN-MODEL` §4). Собственных таблиц нет — кэш рекомендаций не хранится, считается на запрос и протухает быстрее, чем живёт.

## F-11-01 Персональные рекомендации (OP-11) · P1

1. **Назначение.** Предложить шесть сериалов, которые человеку, вероятно, понравятся, и объяснить почему.
2. **Роли.** Зритель и выше; гостю — «Популярное».
3. **Триггер.** Открытие S-01.
4. **Сценарий.** Считается профиль вкуса: жанры по точным отметкам и оценкам, люди, ключевые слова. Отбираются сериалы, которые человек **не смотрел** и которые не отклонены. Для каждого — причина. Если история меньше `reco.min_history_marks`, строка не показывается, гостю и новому пользователю — «Популярное».
5. **Альтернативы и ошибки.** Ничего не нашлось (весь каталог отмечен) — строка скрывается, главная работает. Рекомендация совпала с баннером — допускается: это разные блоки, но если совпадение в трёх подряд, приоритет у баннера. Отключены рекомендации в настройках — «Популярное» без объяснения.
6. **Состояния.** Рекомендации · популярное (мало истории) · популярное (отключено) · скрыто (нечего показать) · загрузка.
7. **Данные.** `e_watch_mark` (точные), `e_rating`, `e_taste_seed`, `e_series`, `e_series_genre`, `e_series_person`.
8. **Правила.**
   - (а) **Только несмотренное** и не отклонённое (`reco.exclude_watched`, `reco.dismiss_days`).
   - (б) У каждой рекомендации есть **одна** причина, самая сильная из сработавших: «похоже на {сериал}» > «потому что жанр {жанр}» > «потому что вы отметили {сериал}». Несколько причин — визуальный шум.
   - (в) Причина вычисляется из того, что человек делал, а не из того, что система предполагает. Формулировки «потому что вам нравится» без основания запрещены.
   - (г) Рекомендация, нажатая и закрытая без действия, учитывается как показ без клика — это и есть доля нерелевантности.
   - (д) Любимые из регистрации — только как слабый сигнал; в причинах не упоминаются.
   - (е) При одинаковых баллах порядок детерминирован: по рейтингу IMDb, затем по `slug`, чтобы строка не прыгала между заходами.
9. **Валидация и лимиты.** Шесть позиций; расчёт ≤ 200 мс, кэш 600 с; один сериал — одна строка.
10. **Edge cases.** EC-M1, EC-M2, EC-M3.
17. **Побочные эффекты.** EV-14; кэш ключа включает набор рекомендаций.
18. **Приёмка.** *Дано* пользователь отметил 40 сериалов драм; *тогда* в рекомендациях преобладает драма, и у каждой позиции видна причина. *Дано* пользователь уже отметил рекомендованный сериал; *тогда* он больше не рекомендуется. *Дано* рекомендация отклонена; *тогда* она не возвращается 30 дней. *Дано* у пользователя 8 отметок; *тогда* строка называется «Популярное».
19. **UI.** Причина обязательна и мелким шрифтом под названием:

```
┌ Для вас ─────────────────────────────────────────────────┐
│ [ ][ ][ ][ ][ ][ ]                                       │
│  ↑ постер                                                │
│    Название        ← название сериала                   │
│    похоже на «Лучшие сезоны»   ← причина, обязательна   │
└──────────────────────────────────────────────────────────┘
```
   **Фокальная точка:** первый постер; причина — второй по важности элемент, без неё строка не объяснима. **Телефон:** два постер в ряд, причина под каждым. **Планшет:** три. **Скелетон:** шесть прямоугольников 2:3 с двумя полосами.
20. **КП.** Скриншот на плакат.

## F-11-02 «Похожие»: базовый алгоритм (OP-11) · P1

1. **Назначение.** Дать «похожие к этому» на странице сериала — без истории пользователя.
2. **Роли.** Все.
3. **Триггер.** Блок «Похожие» на S-06 (объявлен M2 F-02-08, P0).
4. **Сценарий.** Считается балл: общие жанры × 3, общие люди (актёры, режиссёры) × 3, общие ключевые слова × 2. Отбираются шесть сериалов с наибольшим баллом, кроме открытого. У каждого — одна причина по наибольшему вкладу.
5. **Альтернативы и ошибки.** Общих жанров нет — берётся по людям; нет и людей — по ключевым словам; нет и слов — шесть популярных в жанре открытого сериала, и это честнее пустоты.
6. **Состояния.** Похожие · по людям · популярное в жанре · пусто.
7. **Данные.** Только каталог: жанры, люди, ключевые слова сериала. История пользователя в расчёте «похожих» не участвует вовсе.
8. **Правила.**
   - (а) Базовый алгоритм, **не машинное обучение.** Это осознанный предел (`VISION`), а не заглушка: объяснение «похоже на» должно быть предсказуемым.
   - (б) Причина всегда называет конкретное общее: жанр, человека или слово — не «похоже».
   - (в) Портрет в кадре не считается признаком сходства: это художественное решение, а не свойство сериала.
9. **Валидация и лимиты.** Шесть позиций; ≤ 150 мс.
10. **Edge cases.** EC-M4.
17. **Побочные эффекты.** EV-04 при открытии карточки.
18. **Приёмка.** *Дано* два сериала с общим режиссёром и одним жанром; *тогда* причина называет режиссёра, так как его вклад больше. *Дано* общего ничего; *тогда* показано шесть популярных в жанре открытого.
19. **UI.** Как «Для вас», но причины конкретные:

```
┌ Похожие ──────────────────────────────────────────────────┐
│ [ ][ ][ ][ ][ ][ ]                                       │
│    Название                                               │
│    общий режиссёр — Марк Логовский                       │
└──────────────────────────────────────────────────────────┘
```
   **Фокальная точка:** первый постер. **Скелетон:** как «Для вас».
20. **КП.** Не выносится на чертежи.

## F-11-03 Отключение и управление рекомендациями · P1

1. **Назначение.** Дать человеку выключить то, что его раздражает, без последствий.
2. **Роли.** Зритель и выше.
3. **Триггер.** Кнопка «Не интересно» на карточке рекомендации; настройка в профиле.
4. **Сценарий.** «Не интересно» скрывает сериал на `reco.dismiss_days` дней, не запрашивая объяснений. Настройка `recs_enabled` выключает строку целиком. Отключение — это тихо: без последствий для оценок, отметок и видимости профиля.
5. **Альтернативы и ошибки.** Скрыли больше 20 сериалов подряд — строка скрывается целиком, без предложения отключить (это тоже ответ). Отключение переносится между устройствами, так как это настройка аккаунта.
6. **Состояния.** Включено · выключено · скрыто много.
7. **Данные.** `e_reco_dismiss` (пользователь, сериал, дата) и `E-UserSetting.recs_enabled`. Причина скрытия не хранится.
8. **Правила.**
   - (а) Отключение **не влияет ни на что, кроме самих рекомендаций.** Никаких последствий для рейтинга, отметок, видимости.
   - (б) Причина скрытия не запрашивается и не хранится, кроме самого факта.
   - (в) «Не интересно» на «похожих» на странице сериала тоже работает — это один и тот же список `e_reco_dismiss`.
9. **Валидация и лимиты.** Одно нажатие; без подтверждения.
10. **Edge cases.** EC-M5.
17. **Побочные эффекты.** EV-14 `reco_dismiss`.
18. **Приёмка.** *Дано* пользователь нажал «Не интересно»; *тогда* сериал не появляется 30 дней ни в «Для вас», ни в «похожих». *Дано* рекомендации выключены в настройке; *тогда* строка не показывается, а причина отключения не объясняется нигде.
19. **UI.** Кнопка появляется по наведению и фокусу на карточку рекомендации:

```
┌ [постер] ──────────────┐
│                        │
│   Не интересно     ✕   │  ← по наведению/фокусу, всегда с текстом
└────────────────────────┘
   без иконки: «✕» рядом с карточкой означал бы «закрыть блок»
```
   **Фокальная точка:** сам постер; кнопка вторична. **Телефон:** кнопка видна всегда, по наведению там нет. **Скелтон:** постер с одной полосой.
20. **КП.** Не выносится на чертежи.

# M12 — Импорт данных (IMDb + TMDB): глубокая спека

> v0.1 · Фаза 4 · P0 · операции OP-06, OP-07 · экран S-76. Опирается на `DATA-SOURCES` (карта полей, отбор, конвейер, итоги спайка), `CONTENT-PLAN` (полнота, заглушки), `STATES`, `SECURITY`. Метки: **[ГИПОТЕЗА]** — стартовое значение, **[проверить]** — подтверждаем прогоном 2 или документацией. Измерения шаблона (`PLAN` §5) — по номерам.

**Роли.** Запускает и смотрит отчёты только админ; фоновые задачи запускает планировщик. Все ручные действия — в аудит (`R-SEC-36`).

## F-12-01 Отбор кандидатов из датасетов IMDb · P0

1. **Назначение.** Из файлов IMDb определить, какие сериалы входят в каталог, и их рейтинг.
2. **Роли.** Планировщик (полный прогон), админ (кнопка).
3. **Триггер.** Полный прогон; еженедельное обновление рейтингов (F-12-07).
4. **Сценарий.** (1) Скачать `title.basics.tsv.gz`, `title.ratings.tsv.gz` (+ `title.crew`, `title.principals`, `name.basics` для людей, шаг F-12-03) → (2) читать **потоком**, проверив заголовок → (3) оставить `titleType` ∈ {tvSeries, tvMiniSeries}, `isAdult = 0`, у которых **не все** жанры входят в `catalog.excluded_genres` (EC-I2, DEC-037) → (4) присоединить рейтинг → (5) отсортировать по числу голосов, взять `import.top_n` → (6) записать список с рангом и голосами в результаты запуска.
5. **Альтернативы и ошибки.** Нет файла или повреждён архив — три повтора, затем запуск завершается ошибкой; предыдущие данные остаются; если прошлые файлы моложе 7 дней — используем их с предупреждением **[ГИПОТЕЗА]**. Заголовок отличается от ожидаемого — запуск прерывается («схема изменилась»). Строка не разобрана — пропускается и считается.
6. **Состояния.** Скачивание · чтение · отбор · готово · ошибка.
7. **Данные.** `tconst`, `titleType`, `primaryTitle`, `originalTitle`, `isAdult`, `startYear`, `endYear`, `genres`, `averageRating`, `numVotes`; значение `\N` = «нет».
8. **Правила.** Популярность = `numVotes` (без рейтинга ранжировать нельзя — в спайке 101 857 из 272 410 кандидатов с рейтингом); равенство голосов — по `tconst`; сериал, однажды попавший в каталог, остаётся (EC-D7); названия жанров сопоставляются со справочником `E-Genre` по английскому имени.
   **Список исключаемых жанров — один на оба пути (DEC-022, 2026-10-09).** Таксономии IMDb и TMDB не совпадают, поэтому храним две проекции одного набора решений, а не два независимых списка: `catalog.excluded_genres.imdb` = Animation, Talk-Show, News, Game-Show, Reality-TV, Short, Soap · `catalog.excluded_genres.tmdb` = Animation, Talk, News, Reality, Soap, Kids. Расхождения намеренные: у TMDB **нет** жанров Game-Show и Short, зато есть Soap и Kids. Обе проекции равны по смыслу — «то, что не сериал» (DEC-022). Расширен Soap и Kids: раньше они попадали в каталог только через путь TMDB, и состав каталога зависел от того, каким путём пришёл сериал.
9. **Валидация и лимиты.** Размер скачиваемого файла ограничен сверху (защита диска); таймаут скачивания; один запуск за раз.
10. **Edge cases.** EC-I1, EC-I2.
17. **Побочные эффекты.** Запись `E-ImportItemResult`; обновление рейтингов IMDb у каталога.
18. **Приёмка.** *Дано* корректные файлы; *когда* запуск полного прогона; *тогда* в результатах ровно `import.top_n` сериалов, ни один не отсеян по жанрам (EC-I2: отсеивается тот, у кого запрещены **все** жанры), порядок по голосам убывающий. *Дано* повреждённый архив; *когда* запуск; *тогда* запуск «ошибка», каталог не изменён.
19. **UI.** Прогресс стадии в S-76.
20. **КП.** OP-06 (часть); диаграмма деятельности «Импорт».

## F-12-02 Сопоставление с TMDB · P0

1. **Назначение.** Найти карточку TMDB для каждого `tconst` и убедиться, что пара верна.
2. **Роли.** Планировщик; админ (ручная привязка, сброс).
3. **Триггер.** Для сериала без сохранённого `tmdb_id`, и при сбросе сопоставления.
4. **Сценарий.** Поиск TMDB по внешнему идентификатору IMDb (`/find`, спайк 80/80) → взять результат среди сериалов → запросить детали → **проверка пары:** в `external_ids` тот же `tconst` и |год начала TMDB − `startYear`| ≤ 1 → сохранить `tmdb_id`.
5. **Альтернативы и ошибки.** Не найдено → исход `no_tmdb`: сериал всё равно публикуется по минимуму из IMDb (EC-D1). Несколько результатов → берём тот, у которого обратный идентификатор совпал; иначе `pair_doubt`. Проверка не прошла → `pair_doubt`, данные TMDB **не** применяются, пара идёт в список «сомнительные» (F-10-02). Админ может подтвердить, указать другой `tmdb_id`, пометить «нет в TMDB» или исключить сериал.
6. **Состояния.** Не искали · найдено и подтверждено · не найдено · сомнительно · подтверждено админом.
7. **Данные.** `tconst`, `tmdb_id`, результат проверки, дата последней проверки.
8. **Правила.** Название не участвует в проверке (H-28; в спайке оба «расхождения» оказались разными локализациями). Сохранённая пара не пересматривается, пока админ не сбросит.
9. **Валидация.** Ручной `tmdb_id` — положительное целое; перед сохранением показываем найденную карточку (название, год, постер) для сверки.
10. **Edge cases.** EC-D1, EC-D2, EC-I3, EC-I14.
17. **Побочные эффекты.** Запись исхода; запись в аудит при ручном решении.
18. **Приёмка.** *Дано* сериал с корректной парой; *когда* сопоставление; *тогда* `tmdb_id` сохранён, обратный идентификатор совпадает. *Дано* `/find` вернул сериал с другим `tconst` в `external_ids`; *тогда* исход `pair_doubt`, данные не применены.
19. **UI.** Карточка сравнения «IMDb ↔ TMDB» в S-74 (F-10-02).
20. **КП.** OP-06.

## F-12-03 Обогащение из TMDB · P0

1. **Назначение.** Получить описания, рейтинги контента, переводы, ключевые слова, изображения-кандидаты, сезоны и серии; из IMDb — людей.
2. **Роли.** Планировщик.
3. **Триггер.** После F-12-02 для подтверждённых пар; ежедневно для «активных» (F-12-07).
4. **Сценарий.** (1) Запрос деталей на `ru-RU` с подзапросами `content_ratings, external_ids, images, keywords, translations` и `include_image_language = ru,en,null` (как в спайке) → (2) для каждого сезона с номером > 0: данные на `ru-RU` и на `en-US` (H-29; замер прогона 2: ≈ 13 запросов на сериал, ≈ 26 минут на 1197 сериалов) → (3) люди из IMDb: `title.crew` (режиссёры), `title.principals` (категории actor, actress, self, по `ordering`, первые 10) + `name.basics` только для нужных `nconst`; если у сериала нет режиссёра — создатели из `created_by` TMDB **[проверить]** → (4) сложить всё в сырой слой для F-12-06.
5. **Альтернативы и ошибки.** Запрос сезона не удался — сезон помечается «не загружен», остальные сохраняются; повтор в следующем запуске. Пустое описание ru — остаётся пустым (цепочка резерва — `R-I18N-06`). Сезон 0 («спецвыпуски») загружается, но по умолчанию скрыт и не входит в прогресс (H-38).
6. **Состояния.** По каждому сериалу: детали · сезоны · люди · готово.
7. **Данные.** См. `DATA-SOURCES` §2. Серии: номер сезона и серии, названия ru/en, описания ru/en, дата, длительность. Дата записывается как «только дата» (точность `date`); время и точность `datetime` — только при ручном вводе. Рейтинг контента — все страны, выбор метки для показа по H-25.
8. **Правила.** Группировка выходов: серии одного сезона с одной датой образуют **один выход** (EC-D11). Рейтинги TMDB (`vote_average`, `vote_count`) → платформа «TMDB». Ключевые слова — для подборок и рекомендаций.
9. **Валидация и лимиты.** Названия ≤ 300 знаков, описания ≤ 5000, число актёров ≤ 10; всё усечённое помечается; HTML и разметка из источников не допускаются (`R-SEC-15`).
10. **Edge cases.** EC-D3, EC-D13, EC-I4, EC-I5.
17. **Побочные эффекты.** Заполнение сырого слоя; пересчёт состояния выхода и полноты (F-12-06).
18. **Приёмка.** *Дано* сериал из спайка с 5 сезонами; *когда* обогащение; *тогда* все сезоны и серии имеют даты, у серий с `ru` — русские названия, остальные — английские. *Дано* TMDB вернул ошибку на сезоне 3; *тогда* сезоны 1, 2, 4, 5 сохранены, сезон 3 «не загружен».
19. **UI.** Счётчики стадии в S-76.
20. **КП.** OP-06; последовательность «Импорт → TMDB».

## F-12-04 «Новинки и идущие» через TMDB · P0

1. **Назначение.** Добавить в каталог свежие сериалы и те, у которых есть серии до `import.until` — именно они наполняют календарь (спайк: у новинок даты есть в 61%).
2. **Роли.** Планировщик; админ.
3. **Триггер.** Ежедневно (после синхронизации расписания) и в полном прогоне.
4. **Сценарий.** Обзор TMDB по двум условиям: (а) первая дата выхода в окне `[сегодня − new_window_months; until]`; (б) есть серия с датой в окне `[сегодня; until]` (фильтр по дате эфира подтверждён прогоном 2: в TMDB 2183 сериала с серией до 31.12; у первых 30 добавленных дата в окне есть у всех) → объединить, отсортировать по популярности TMDB → взять до `import.new_cap` → для каждого получить IMDb-идентификатор из `external_ids` → если его нет в датасете, ключом остаётся `tmdb:{id}` и рейтинга IMDb нет (в спайке: у 17% новинок) → дальше F-12-03.
5. **Альтернативы и ошибки.** Нет IMDb-идентификатора — сериал входит с «внутренним» ключом и меткой «без IMDb»; когда идентификатор появится, ключ меняется на `tconst` без потери данных пользователей. **Исключение жанров обязано совпадать с путём IMDb** (F-12-01 §4, DEC-022): иначе сериал, отсечённый при отборе по IMDb-рейтингу, прошёл бы через TMDB-путь и попал в каталог. Взрослый контент не берём.
6. **Состояния.** Обзор · добавление · готово.
7. **Данные.** `tmdb_id`, `first_air_date`, популярность TMDB, причина включения (`new` | `airing` | оба).
8. **Правила.** Добавленный сериал остаётся (EC-D7), даже если «окно» прошло. Потолок считается по новым добавлениям за запуск, а не по всему каталогу **[ГИПОТЕЗА]**.
9. **Лимиты.** До 5 страниц обзора за запуск; не более `import.new_cap` новых сериалов за запуск.
10. **Edge cases.** EC-I6, EC-I7.
17. **Побочные эффекты.** Появление новых карточек на главной («Новинки») и в календаре.
18. **Приёмка.** *Дано* в TMDB есть сериал с серией через 5 дней; *когда* ночной запуск; *тогда* он в каталоге, состояние «Выходит», серия в календаре. *Дано* найдено 450 подходящих; *тогда* добавлено не более 300.
19. **UI.** Строка «добавлено новых» в отчёте.
20. **КП.** OP-06.

## F-12-05 Загрузка и подготовка изображений · P0

1. **Назначение.** Положить постер и фон в БД в нужных размерах и подготовить фокальную точку.
2. **Роли.** Планировщик.
3. **Триггер.** После F-12-03, если путь изображения изменился и поле не заблокировано вручную.
4. **Сценарий.** Постер: взять `poster_path` из деталей на `ru-RU`. Фон для баннеров, заставки и шапки: среди `images.backdrops` взять **без указания языка** (без текста), шириной ≥ 1920 и пропорцией ≈ 16:9, предпочтительно с высшей оценкой; если такого нет — сериал не годится для баннера и заставки (H-34), в шапке страницы используется обычный `backdrop_path`, а при его отсутствии — размытая копия постера (`CONTENT-PLAN` §4). Скачать только с `image.tmdb.org` → проверить тип по содержимому → перекодировать (убрать метаданные) → создать варианты → записать в БД → поставить фокальную точку по умолчанию **(2/3, 1/3)** (H-33).
5. **Альтернативы и ошибки.** Нет постера — заглушка в интерфейсе, ничего не записывается. Загрузка не удалась — три повтора, затем пропуск с причиной в отчёте. Слишком большой или нечитаемый файл — отклоняется. Совпал хэш с имеющимся — пропуск.
6. **Состояния.** Есть изображение · нет · не загрузилось · заменено вручную (блокировка).
7. **Данные.** E-Image (владелец, роль, источник `tmdb|manual`, исходный путь, размеры, хэш, фокальная точка, признак «без текста») и E-ImageVariant (ширина, формат, байты, `ETag`). **Варианты [ГИПОТЕЗА]:** постер 185 / 342 / 500 px, фон 780 / 1280 / 1920 px — размеры 185 / 342 / 500 у постеров и 780 / 1280 у фонов — стандартные размеры TMDB (подтверждено `/configuration`); вариант 1920 получаем из `original` уменьшением; без увеличения; формат — современный (+ запасной) по решению Фазы 7. Бюджет БД под изображения ≤ 2 ГБ; замер прогона 2: ≈ 1,2 МБ на сериал в форматах TMDB, ≈ 1,4 ГБ на 1197 сериалов, после перекодирования меньше **[оценка]**.
8. **Правила.** Ручное изображение (F-10-04) блокирует поле, импорт его не заменяет.
9. **Валидация и лимиты.** Размер исходника ≤ 15 МБ, таймаут 10 с, только JPEG/PNG/WebP по содержимому (`R-SEC-17`), только домены TMDB (`R-SEC-18`), параллельность `import.image_concurrency`.
10. **Edge cases.** EC-C5, EC-I8.
17. **Побочные эффекты.** Сброс кэша изображений (новая версия адреса), пересчёт «куда можно поставить» (F-10-01).
18. **Приёмка.** *Дано* у сериала есть фон без текста ≥ 1920; *когда* импорт; *тогда* в БД три варианта фона, фокальная точка (2/3, 1/3), признак «без текста» истинен. *Дано* фон только с текстом; *тогда* сериал не годится для баннера, причина `no_backdrop`.
19. **UI.** Отчёт: «без постера», «без фона».
20. **КП.** OP-06; ER-диаграмма изображений.

## F-12-06 Запись в каталог, состояние выхода, полнота · P0

1. **Назначение.** Идемпотентно записать данные, уважая ручные правки; рассчитать состояние выхода и полноту (OP-07).
2. **Роли.** Планировщик.
3. **Триггер.** Конец обработки сериала на любой стадии (транзакция на один сериал).
4. **Сценарий.** (1) Обновление по `tconst` (или внутреннему ключу) → (2) для каждого поля: если заблокировано (`manual`) — пропуск, иначе запись + источник → (3) жанры IMDb → справочник; неизвестное имя жанра создаёт скрытую запись справочника и попадает в отчёт («новый жанр») → (4) **состояние выхода** (H-27, H-39, H-40): **сначала даты, потом статус** — если есть выход с датой ≥ сегодня − 14 дней, состояние «Выходит» при любом статусе TMDB; иначе по статусу: `Ended` → Завершён; `Canceled` → Отменён; `In Production`, `Planned`, `Pilot` → Анонс; `Returning Series` → «Ждём сезон»; нет данных TMDB → по `endYear` IMDb: есть — Завершён, нет — «Ждём сезон». Значения статуса в прогоне 2: Ended, Returning Series, Canceled, In Production **[долю «Завершён» с датами в окне подтвердить по `catalog-snapshot.json`, Q-19]** → (5) **полнота и причины** (таблица ниже) → (6) публикация: новый сериал становится «Опубликован», если выполнен минимум (название, год, ≥ 1 жанр, состояние); иначе остаётся «Импортирован» и идёт в неполные → (7) сбросить кэши главной и карточки.
5. **Альтернативы и ошибки.** Ошибка записи — откат транзакции сериала, исход `write_failed`, остальные продолжаются. Архивный сериал данные обновляет, но остаётся архивным.
6. **Состояния публикации:** Импортирован → Опубликован → В архиве (`STATES`).
7. **Данные.** Поля по `DATA-SOURCES` §2 + E-FieldProvenance.
8. **Правила — коды причин** (используются в S-74 и фильтрах):

| Код | Условие | Класс |
|---|---|---|
| `no_tmdb` | Нет пары в TMDB | блокирует |
| `pair_doubt` | Проверка пары не пройдена | блокирует |
| `no_genre` | Ни одного жанра из справочника | блокирует публикацию |
| `no_poster` | Нет постера | содержание |
| `no_overview` | Нет описания ни ru, ни en | содержание |
| `no_overview_ru` | Нет описания ru (есть en) | содержание |
| `no_backdrop` | Нет фона без текста ≥ 1920 px | размещение (баннер, заставка) |
| `schedule_gap` | Состояние «Выходит», но у серий последнего сезона есть пустые даты | размещение (календарь, «Новинка дня») |
| `no_people` | Нет ни режиссёра/создателя, ни актёров | содержание |
| `new_genre` | Жанр вне справочника | служебная |
| `no_age` | Нет метки возраста ни для RU/BY, ни по другим странам | **информационная**, уровень не меняет (EC-D13) |

   Уровни: **минимум** — название, год, ≥ 1 жанр, состояние; **пригодна к показу** — минимум + постер + описание (ru или en); **полная** — пригодна + фон + `ru`-описание + нет `schedule_gap` + есть люди. «Ждём сезон» не создаёт причин. Приоритет в S-74: блокирующие → размещение (сначала для сериалов с высоким рангом) → содержание → служебные; внутри класса — по числу голосов IMDb.
9. **Валидация.** Значения полей проверяются по схеме и границам (`R-SEC-13`).
10. **Edge cases.** EC-D7, EC-D8, EC-I9.
17. **Побочные эффекты.** Изменение даты выхода у сериала с подписчиками порождает событие `release_changed` для M3 (OP-09); смена «Ждём сезон» → «Выходит» — событие `schedule_announced` (P1, H-26).
18. **Приёмка.** *Дано* ручное название с блокировкой; *когда* повторный импорт; *тогда* название не изменилось, источник «вручную». *Дано* сериал `Returning Series` без дат; *тогда* состояние «Ждём сезон», причин нет, в календарь не попал. *Дано* сериал без жанров; *тогда* «Импортирован», причина `no_genre`.
19. **UI.** Бейджи уровня и причин в S-73, S-74.
20. **КП.** OP-07; диаграмма состояний сериала; схема алгоритма расчёта состояния выхода.

## F-12-07 Расписание запусков · P0

1. **Назначение.** Данные свежие без участия админа и без лишней нагрузки.
2. **Роли.** Планировщик; админ меняет время и включает/выключает.
3. **Триггер.** Время; запуск приложения.
4. **Сценарий.**

| Задача | Периодичность | Что делает | Объём (оценка) |
|---|---|---|---|
| `schedule_sync` | ежедневно в `import.schedule_time` | Для сериалов не в состояниях Завершён и Отменён: детали + последний сезон на `ru-RU` и `en-US`; пересчёт состояний; события о переносах и объявлениях | ≈ 3–5 запросов на сериал, 300–500 сериалов ⇒ 3–5 мин **[проверить]** |
| `discover_sync` | ежедневно после `schedule_sync` | F-12-04 для новых | ≈ 10–20 запросов + F-12-03 для новых |
| `ratings_sync` | еженедельно | Обновить `numVotes` и рейтинг IMDb из датасета для каталога | Чтение датасета |
| `full_run` | по кнопке | Все стадии, пересчёт топ-N | ≈ 20 мин **[проверить]** |

**Виды запуска (`E-ImportRun.kind`) исчерпывающе перечислены выше:** `schedule_sync`, `discover_sync`, `ratings_sync`, `full_run`. Кнопка «Сухой прогон» в S-76 (F-12-08) — **не пятый вид**, а флаг `dry_run` у `full_run`: те же стадии и тот же объём запросов, но без записи в каталог, с отчётом «что изменилось бы». Без этого уточнения кнопка и перечисление видов противоречат друг другу.

5. **Альтернативы и ошибки.** Компьютер был выключен ночью — при старте, если последний успешный `schedule_sync` старше 36 часов, он запускается сразу **[ГИПОТЕЗА]**. Задача ещё идёт при следующем запуске — новый запуск пропускается и записывается. `import.enabled = off` — планировщик ничего не запускает.
6. **Состояния задачи:** запланирована · идёт · успех · частично · ошибка.
7. **Данные.** E-ImportRun.
8. **Правила.** Не более одного запуска одновременно (блокировка); ночное окно не пересекается с резервной копией (M9) — порядок: резервная копия → `schedule_sync`.
9. **Валидация.** Время задаётся как `ЧЧ:ММ`.
10. **Edge cases.** EC-I10.
17. **Побочные эффекты.** События для M3, сброс кэшей, служебное уведомление админу при ошибке.
18. **Приёмка.** *Дано* последний успех 40 часов назад; *когда* старт приложения; *тогда* `schedule_sync` запущен. *Дано* идёт `full_run`; *когда* наступило 04:00; *тогда* ночной запуск пропущен и записан.
19. **UI.** Панель расписания в S-76.
20. **КП.** Диаграмма деятельности планировщика.

## F-12-08 Отчёты и экран «Импорт» (S-76) · P0

1. **Назначение.** Видеть, что произошло, и что мешает календарю.
2. **Роли.** Админ.
3. **Сценарий.** S-76: сверху — **состояние и покрытие**: крупное число «Выходит с датами N из M» (ключевое число, `R-DES-04`), счётчики состояний (Выходит · Ждём сезон · Завершён · Отменён · Анонс), плотность календаря по неделям до `import.until`; кнопки «Полный прогон», «Сухой прогон», «Запустить синхронизацию расписания»; режим (работает / режим защиты); таблица запусков (время, вид, статус, длительность, обновлено, ошибки); деталь запуска — счётчики и фильтруемый список исходов по сериалам.
4. **Счётчики отчёта:** отобрано · сопоставлено · сомнительных · нет в TMDB · добавлено новых · обновлено · без изменений · изображений загружено / пропущено / ошибок · без постера · без фона · без описания ru · с пропусками графика · новых жанров · запросов, 429, время.
5. **Состояния.** Нет запусков («ещё не запускали») · идёт (прогресс по стадиям) · есть ошибки (список) · режим защиты.
6. **Правила.** Метрика готовности расписания (`DATA-SOURCES` §7) — по сериалам «Выходит»; цель 100% с датами. **Плотность N записей в неделю — измеренная величина, а не целевая:** прогон 2 дал 189/147/120/112 в первые недели окна и 27/27/16/11/4 в декабре. Порог «не менее 25 в неделю» из `DATA-SOURCES` §7 выполняется в 7 раз на старте и не выполняется в конце, то есть метрика ничего не ловит. **Число в этот файл не пишем, пока автор не выберет, что полезнее видеть: предупреждение о «дырках» в календаре или сравнение с прошлой неделей.** Кнопка «Сухой прогон» — `full_run` с флагом `dry_run` (F-12-07), не отдельный вид запуска.
7. **Edge cases.** EC-I11.
8. **Приёмка.** *Дано* завершённый запуск; *когда* админ открывает S-76; *тогда* видит счётчики запуска, число «Выходит с датами», таблицу запусков. *Дано* идёт запуск; *тогда* виден прогресс и кнопки запуска отключены.
9. **UI (условные числа).**

```
┌ Импорт ─────────────────────────────────────────────────────────┐
│ Режим: Работает      [Полный прогон] [Сухой прогон] [Расписание] │
│                                                                 │
│  Выходит с датами       Выходит · Ждём сезон · Завершён · Отменён│
│    ▉▉  N / M            число каждого состояния                  │
│  календарь до 31.12:  ▁▃▅▇▇▅▃▂▁▂▃  (серий по неделям)            │
│ ─ Запуски ──────────────────────────────────────────────────────│
│ время │ вид │ статус │ длит. │ обновлено │ ошибки               │
│ ─ Запуск: детали ───────────────────────────────────────────────│
│ счётчики…           │ исходы по сериалам (поиск, фильтр)        │
└─────────────────────────────────────────────────────────────────┘
```
   **Фокальная точка:** число «Выходит с датами» (левая треть, крупно). Третьи: слева — состояние и действия, в центре — календарная диаграмма, справа — счётчики. **Брейкпоинты:** ≥ 1024 — три колонки; < 1024 — одна колонка, таблицы в горизонтальной прокрутке внутри контейнера. **Скелетон:** блоки с высотой строк таблицы.
10. **КП.** Скриншот S-76 на плакат.

**Остальные измерения шаблона.**
- **Триггер.** Переход в «Импорт»; пока идёт запуск, экран обновляется (опрос раз в несколько секунд).
- **Альтернативы и ошибки.** Нет прав — 404; ошибка загрузки отчёта — «Повторить»; идёт запуск — кнопки запуска неактивны, виден прогресс.
- **Данные.** E-ImportRun и E-ImportItemResult; счётчики состояний — из каталога; плотность календаря — число выходов по неделям до `import.until`.
- **Валидация и лимиты.** Фильтры списка исходов — белый список; список исходов постраничный (50 строк).
- **Побочные эффекты.** Просмотр ничего не меняет; запуск создаёт E-ImportRun и запись в аудит.

## F-12-09 Надёжность запуска · P0

1. **Назначение.** Запуск переживает сбои сети и API.
2. **Роли.** Система.
3. **Сценарий и правила.**
   - 429: ждать `Retry-After` + 250 мс, до 5 попыток; 5xx и сеть: 1, 2, 4, 8, 16 с; 404 на сезоне — «нет данных», на `/find` — `no_tmdb`; 401 — запуск прерывается («неверный ключ»), админ получает служебное уведомление.
   - **Лёгкий размыкатель:** если за последние 50 запросов > 50% неудачны — пауза 5 минут; после трёх пауз запуск «частично».
   - Контрольная точка по сериалу и стадии; повторный запуск пропускает завершённое («возобновить»); **сухой прогон** читает и считает, но ничего не пишет в каталог и не качает картинки.
   - Каждый сериал — своя транзакция; сбой одного не останавливает остальных.
4. **Edge cases.** EC-D6, EC-I12.
5. **Приёмка.** *Дано* API отвечает 429 с `Retry-After: 3`; *когда* запуск; *тогда* пауза ≥ 3 с и повтор, итог без потери сериалов. *Дано* неверный токен; *тогда* запуск «ошибка» сразу, каталог не тронут. *Дано* запуск оборван посреди; *когда* «возобновить»; *тогда* обработанные сериалы пропущены.
6. **КП.** Диаграмма последовательности «повтор и размыкатель».

**Остальные измерения шаблона.**
- **Триггер.** Любая ошибка сети или API во время запуска.
- **Альтернативы и ошибки.** Правила по кодам ответов — выше; неизвестный код трактуется как 5xx.
- **Состояния.** Идёт · пауза размыкателя · частично · ошибка · успех.
- **Данные.** Контрольная точка (сериал, стадия) и число попыток — в E-ImportItemResult.
- **Валидация и лимиты.** Попыток ≤ 5; окно размыкателя 50 запросов, порог 50%, пауза 5 минут, пауз ≤ 3 — стартовые значения (H-24).
- **Побочные эффекты.** Служебное уведомление админу при ошибке 401 и при итоге «частично»; запись в журнал запуска.
- **UI.** Не применимо: собственного экрана нет, статус виден в S-76 (F-12-08).

## F-12-10 Режим защиты: снимок данных · P0

1. **Назначение.** Показ без интернета и без сюрпризов (Бланк C-12, DEC-010, EC-D9).
2. **Роли.** Админ (шаг подтверждения — повторный пароль, `R-SEC-12`).
3. **Сценарий.** Кнопка «Заморозить для защиты» (за 1–2 дня до защиты): (1) полный прогон → (2) показать итоговую полноту и список проблем, админ подтверждает → (3) создать резервную копию с пометкой «снимок для защиты» и проверить восстановление (M9, OP-17) → (4) `import.enabled = off` и, по отметке админа, `mail.mode = devbox` (M1 F-01-12: письма регистрации без интернета), в S-76 бейдж «Режим защиты» → «Разморозить» возвращает всё обратно.
4. **Правила.** В режиме защиты запросов к внешним API нет; изображения уже в БД; данные синтетического населения помечены демо (`R-AN-11`). Время в календаре — настоящее: серии «сегодня» берутся из снимка по датам.
5. **Edge cases.** EC-D9, EC-I13.
6. **Приёмка.** *Дано* режим защиты включён; *когда* пропал интернет; *тогда* главная, каталог, карточки и календарь открываются без ошибок и без запросов наружу. *Дано* копия не восстанавливается; *тогда* заморозка отменяется с сообщением.
7. **КП.** Руководство по развёртыванию и сценарий защиты.

**Остальные измерения шаблона.**
- **Триггер.** Кнопка «Заморозить для защиты» в S-76.
- **Альтернативы и ошибки.** Копия не создалась или не восстанавливается — заморозка отменяется с сообщением; полный прогон завершился с ошибками — предупреждение со списком и обязательное подтверждение админа.
- **Состояния.** Работает · Заморожено.
- **Данные.** Настройка `import.enabled`; метка резервной копии «снимок для защиты» (M9).
- **Валидация и лимиты.** Повторный пароль и явное подтверждение; заморозить можно, только если нет идущего запуска.
- **Побочные эффекты.** Планировщик останавливается; в S-76 бейдж «Режим защиты»; запись в аудит.
- **UI.** Кнопка и бейдж в S-76 (F-12-08); отдельного экрана нет.

## Edge cases модуля (новые)

| ID | Ситуация | Поведение |
|---|---|---|
| EC-I1 | Датасеты IMDb обновились в середине скачивания | Скачиваем во временный файл, заменяем после проверки целостности |
| EC-I2 | Сериал есть в топе по голосам, но его жанр целиком из исключённых | Не входит; админ может добавить вручную |
| EC-I3 | `/find` вернул сериал, а обратный идентификатор указывает на другой `tconst` | `pair_doubt`, данные не применяются |
| EC-I4 | В названии или описании из источника есть разметка или скрипт | Сохраняется как обычный текст, при выводе экранируется (`R-SEC-15`) |
| EC-I5 | Номера серий в сезоне с пропусками или повторами | Сохраняем как есть; повтор номера — предупреждение в отчёте |
| EC-I6 | Сериал появился в обзоре TMDB без IMDb-идентификатора, а потом получил его | Ключ меняется на `tconst`, данные пользователей сохраняются |
| EC-I7 | Обзор вернул тысячи подходящих | Потолок `import.new_cap`; остальные — при следующих запусках |
| EC-I8 | Изображение не 16:9 или с неправильными размерами | Не годится для баннера и заставки; в отчёте «без фона» |
| EC-I9 | Две записи претендуют на один `slug` | Правило H-32: `-{год}`, затем `tt…`; конфликт в отчёте |
| EC-I10 | Сервер выключили на несколько дней | При старте запускается пропущенное (до 36 часов), иначе предупреждение «данные устарели» в S-76 |
| EC-I11 | Нет ни одного запуска (чистая установка) | S-76: «Импорт ещё не запускали» + кнопка «Полный прогон»; публичный сайт показывает пустое состояние каталога |
| EC-I12 | Ключ TMDB истёк во время запуска | Запуск «частично», служебное уведомление админу |
| EC-I13 | Заморозку включили, а потом нашли ошибку в данных | «Разморозить» → исправить → «Заморозить» снова |
| EC-I14 | В прогоне 2 не нашлись 6 из 1000 (Blackadder II, Blackadder Goes Forth, 24: Live Another Day и др.) — вероятно, IMDb ведёт сезон или мини-сериал отдельным тайтлом, а TMDB — сезоном другого сериала | Исход `no_tmdb`: публикуется по минимуму из IMDb, постер и фон — вручную (F-10-04); данные родительского сериала на сезон не переносим **[ГИПОТЕЗА]** |

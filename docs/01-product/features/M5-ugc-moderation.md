## 0. Сквозное для модуля

**Четыре вида UGC и их границы.** Различие не в длине и не в оформлении, а в **предмете и последствиях**.

| Вид | Предмет | Где живёт | Особое |
|---|---|---|---|
| **Отзыв** | Сериал целиком | S-06, S-09, S-10 | Обязательна оценка; без отметки просмотра не принимается (M4 F-04-01). Это единственный вид, влияющий на рейтинг |
| **Комментарий** | Отзыв, тема обсуждения, страница серии | S-08, S-10, S-14 | Короткий, без оценки; отвечает на конкретную реплику |
| **Руководство** | Сериал: статья с разделами | S-11, S-12 | Редактируемый текст с оглавлением и спойлер-меткой. **Определение:** автор пишет о сериале то, чего нет в описании, — порядок просмотра, где остановиться, что смотреть с детьми, о чем сериал на самом деле. Не пересказ сюжета и не отзыв: отзыв выражает мнение, руководство даёт порядок |
| **Обсуждение (тема)** | Сериал: тема с постами | S-13, S-14 | Свободная тема, создаётся первым постом; посты отвечают друг другу |

Все четыре проходят один конвейер (F-05-02) и различаются только обязательными полями и тем, что происходит после публикации. Общая черта, обязательная для всех: **ссылки запрещены** (DEC-015, `R-SEC-14`) — это единственное правило, не подлежащее исключению ни для какого вида.

**Правило проверки.** Без машинного обучения. Материал нормализуется, по нему ищутся слова словаря; находка — это совпадение, а не «вердикт». Работает и с русским, и с английским словарём одновременно. При совпадении материал не публикуется, а уходит в очередь; автору сразу показывается, что материал предположительно содержит недопустимое, и предлагаются два пути — исправить и пройти проверку ещё раз (не чаще раза в 5 минут) или дождаться решения редактора. Отдельное уведомление приходит при окончательном решении, всегда с причиной.

**Массовый поток.** Проблема из `input/spec.md`: тысячи пользователей могут одновременно слать запрещённое. Решается не ограничением пользователя, а **кластеризацией** (OP-02): похожие материалы попадают в один кластер, редактор принимает одно решение на все, а новые материалы в решённый кластер получают то же решение автоматически. Плюс бюджеты: при превышении нормы помеченных материалов модерация переходит в режим «осторожно» — новые материалы ждут, а не публикуются автоматически.

**Сущности (поля уточняет Фаза 5):** E-Material (автор, вид `review | comment | guide | topic`, объект и тип объекта, тело, спойлер-метка, состояние, версия, дата решения) · E-MaterialLink (материал, родитель, цель) — комментарий привязан к посту или отзыву, ответ — к комментарию · E-Report (автор жалобы, материал, причина, комментарий, состояние) · E-DictionaryWord (слово, язык, список `block | allow`, автор правила) · E-ModerationCluster (материалы, признак сходства, решение, применимо к) · E-EditorDecision (редактор, материал, решение, причина, отвергнутое правило, время) · E-RateEvent (пользователь, вид действия, окно) — техническое, для антиспама.

## F-05-01 Отзыв (M4 передаёт оценку и расчёт рейтинга) · P0

1. **Назначение.** Собрать мнение о сериале в виде, пригодном для чтения и для расчёта рейтинга.
2. **Роли.** Зритель и выше — свой; редактор — модерирует; гость — читает.
3. **Триггер.** Форма на S-06 или S-08 (к отзыву об сериале).
4. **Сценарий.** Оценка (обязательна) → текст → галочка «содержит спойлеры» → отправка. Отзыв без оценки невозможен: оценка и текст — одна форма. Без отметки просмотра форма заблокирована с подсказкой «сначала отметьте серию» (M4 F-04-01) — но **отметка не нужна для уже опубликованного отзыва при правке**. Отправка проходит проверку (F-05-02) и либо публикуется, либо уходит в очередь.
5. **Альтернативы и ошибки.** Спойлер-метка не проставлена, а текст содержит спойлер — материал уходит в очередь с причиной «спойлер без метки», решение принимает редактор, а не эвристика. Повторная отправка раньше `ugc.recheck_cooldown_min` — отказ с указанием оставшегося времени. Уже есть опубликованный отзыв по этому сериалу — форма предлагает правку, второй отзыв не создаётся (`EC-V1`).
6. **Состояния.** Черновик · на проверке · опубликован · помечен · запрещён · скрыт (бан автора) · удалён.
7. **Данные.** E-Material (`review`), E-Rating (M4), E-RateEvent.
8. **Правила.**
   - (а) Один отзыв на пару «пользователь — сериал». Правка создаёт новую версию; предыдущая остаётся в истории (`STATES` §1).
   - (б) Спойлер-метка скрывает текст при показе и помечает `data-nosnippet` (DEC-023).
   - (в) Ссылка в тексте — материал в очередь с причиной «ссылка», независимо от словаря (DEC-015).
   - (г) Удаление оценки автором удаляет и отзыв (M4 F-04-01); удаление отзыва оценку не трогает.
   - (д) Материал с состоянием «Скрыт» (бан автора) не отдаётся в списках и на странице, но остаётся в базе — вернётся при разбане.
9. **Валидация и лимиты.** Текст ≤ 5000 знаков, ≥ 1 после обрезки; ≤ 20 правок в сутки; 5 отправок в минуту.
10. **Edge cases.** EC-U1, EC-U2, EC-U3, EC-R6, EC-V1.
17. **Побочные эффекты.** EV-10; пересчёт рейтинга сайта (OP-03); пересчёт счётчиков групп (OP-04); запись в журнал.
18. **Приёмка.** *Дано* зритель без отметки просмотра; *когда* открывает форму отзыва; *тогда* форма заблокирована с пояснением. *Дано* отправлен отзыв со ссылкой; *тогда* материал в очереди с причиной «ссылка», автору показано, что можно исправить. *Дано* опубликованный отзыв; *когда* автор банится с флажком; *тогда* отзыв получает состояние «Скрыт» и пропадает из списков без удаления.
19. **UI.** Форма на S-06, одна колонка, без лишних полей:

```
┌─ Ваш отзыв ─────────────────────────┐
│  Оценка  ① ② ③ ④ ⑤ ⑥ ⑦ ⑧ ⑨ ⑩     │  ← radio, обязательна
│                                    │
│  [ Текст отзыва…              ]    │
│                                    │
│  ☐ Содержит спойлеры               │
│                                    │
│  [ Опубликовать ]  ← один primary   │
│                                    │
│  ⚠ В тексте есть слово из          │  ← результат проверки
│    запрещённого списка.             │    в момент отправки
└────────────────────────────────────┘
```
   **Фокальная точка:** поле оценки — то, без чего нельзя продолжить; после отправки фокус переходит на результат проверки. **Телефон:** оценка — прокручиваемая строка из 10 чисел, кнопка во всю ширину. **Планшет:** как десктоп. **Скелетон:** не применяется — форма отдаётся сразу.
20. **КП.** Диаграмма классов «Материал»; лист «схема алгоритма» берётся из конвейера F-05-02.

## F-05-02 Проверка материала: нормализация, словарь, решение (OP-01) · P0

1. **Назначение.** Не допустить публикации запрещённого содержимого и не наказать за невинное слово.
2. **Роли.** Система; редактор — принимает решение по спорным.
3. **Триггер.** Любая отправка материала любого вида.
4. **Сценарий.** (1) Нормализация: регистр, `ё → е`, `ъ`, повторы пробелов, NFKD для латиницы, схема URL из текста. (2) Поиск по белому списку: слова, которые выглядят как плохие, но допустимы в контексте (названия, имена, термины). Белый список проверяется **первым**. (3) Поиск по запрещённому словарю, русский и английский одновременно. (4) Проверка ссылок — отдельно и всегда. (5) Решение: чисто → публикация; есть находка → материал в очередь с указанием причины и конкретного слова. (6) Если материал похож на уже помеченный — присоединяется к открытому кластеру (F-05-04).
5. **Альтернативы и ошибки.** Словарь не загрузился — проверка **не пропускается**: материал ждёт и помечается «проверка недоступна», ничего не публикуется вслепую. Пустое тело после нормализации — отказ с объяснением. Слово найдено в белом списке — находка снимается, факт логируется для правил. Два слова найдены — показываются оба, решение одно.
6. **Состояния.** Чисто · помечен (с причиной) · в кластере · проверка недоступна · отказ по валидации.
7. **Данные.** E-DictionaryWord, E-Material, E-ModerationCluster.
8. **Правила.**
   - (а) Порядок обязателен: **белый список раньше запрещённого**, ссылки — независимо от обоих. Иначе «в белом» сработает и ссылка пройдёт.
   - (б) Материал показывается автору как «предположительно содержит недопустимый контент» — не «запрещён». Он не знает, что именно нашлось: иначе обходится заменой одного слова на синоним. Причина с точным словом раскрывается только в уведомлении о **окончательном** решении.
   - (в) Материал, ждущий проверки, виден автору в разделе «Мои материалы» (S-35) со статусом.
   - (г) Дословный текст автора **не подменяется**: проверяется и хранится то, что он написал. Автозамена слов не применяется нигде.
   - (д) Событие `material_submit` не содержит текста материала и совпавшего слова — только факт результата и вид (`R-AN-04`).
9. **Валидация и лимиты.** Бюджет проверки ≤ 50 мс при 10 000 слов словаря; при превышении материал уходит в очередь без автоматической публикации.
10. **Edge cases.** EC-U4, EC-U5, EC-U6, EC-U7.
17. **Побочные эффекты.** EV-10; запись в очередь; обновление счётчика «осторожного» режима (F-05-04); сброс кэша страницы материала.
18. **Приёмка.** *Дано* в белом списке есть «сценарий»; *когда* материал содержит его; *тогда* публикуется без замечания. *Дано* то же слово без записи в белом списке; *тогда* материал в очереди. *Дано* словарь не загрузился; *тогда* ничего не публикуется автоматически. *Дано* материал с URL; *когда* проверен; *тогда* причина «ссылка» независимо от словаря.
19. **UI.** Результат проверки — одно сообщение, без раскрытия слова:

```
┌─ Проверка ────────────────────────────────┐
│  ⚠ Материал предположительно содержит      │
│    недопустимый контент.                  │
│                                          │
│  Что можно сделать:                       │
│  • исправить и проверить ещё раз          │
│    (не чаще раза в 5 минут)               │
│  • дождаться решения редактора —          │
│    мы сообщим и напишем причину           │
│                                          │
│  [ Исправить ]  [ Понятно ]               │
└──────────────────────────────────────────┘
```
   **Фокальная точка:** первая кнопка — исправить, она ведёт к результату. **Телефон:** сообщение во всю ширину, кнопки в столбик. **Скелетон:** не применяется.
20. **КП.** **Кандидат на лист 5.2 «Схема алгоритма, реализующего бизнес-логику»** — блок-схема из `MODERATION` §1, развёрнутая шагами R-MOD-02…07. Это единственный алгоритм проекта с однозначным началом, концом и ветвлением.

## F-05-03 Антиспам: бюджеты, кластеры, приоритизация очереди (OP-02) · P0

1. **Назначение.** Не дать волне запрещённых материалов завалить очередь и не дать одному автору завалить её числом попыток.
2. **Роли.** Система; редактор видит кластеры.
3. **Триггер.** Очередь модерации достигает `mod.queue_target_min` в минутах разбора либо доля помеченных превышает `mod.auto_block_share`.
4. **Сценарий.** (1) Приоритет очереди: сначала материалы с большим числом жалоб, затем свежие, затем старые — старый материал в очереди дольше суток поднимается. (2) Кластеризация: материалы с совпадающей сигнатурой (нормализованный текст, автор, близость по времени) объединяются; редактор решает один раз. (3) Бюджеты: превышение доли помеченных переводит систему в «осторожный» режим — новые материалы ждут решения, автоматической публикации нет; режим показывается редактору и администратору. (4) Кластер, решённый как «запретить», распространяет решение на новые материалы с той же сигнатурой **[ГИПОТЕЗА]**.
5. **Альтернативы и ошибки.** Очередь растёт быстрее, чем редактор разбирает — приоритет спасает свежие материалы, но старые копятся; администратор видит предупреждение и может временно закрыть отправку для новых авторов (J-14). Кластер ошибочно объединил разные материалы — редактор разделяет кластер, решение применяется только к выбранным. Автор создал 20 материалов за минуту — лимит `mod.submission_rate_per_min`, предупреждение до третьего.
6. **Состояния.** Обычный режим · очередь в норме · очередь растёт · «осторожный» режим · отправка закрыта администратором.
7. **Данные.** E-ModerationCluster, E-RateEvent, счётчики очереди.
8. **Правила.**
   - (а) Закрытие отправки — только администратором, только с указанием причины и срока, всегда в аудит.
   - (б) Ожидание в очереди показывается автору точно, без округления «почти сутки».
   - (в) «Осторожный» режим не блокирует легитимных авторов, чьи материалы чисты — ограничивается только поток помеченных.
   - (г) Кластер — это способ разбора, а не наказание: решение всегда выносится редактором, автоматика только группирует.
   - (д) Повторная проверка после правки не обходит `ugc.recheck_cooldown_min`.
9. **Валидация и лимиты.** Размер кластера ≤ 200 материалов; окно кластеризации 24 часа.
10. **Edge cases.** EC-U8, EC-U9, EC-U10.
17. **Побочные эффекты.** EV-22 `spam_budget_hit`; событие админу; счётчик на системном обзоре (M9).
18. **Приёмка.** *Дано* 40 похожих материалов за час; *когда* они попали в очередь; *тогда* редактор видит один кластер на 40 и принимает одно решение. *Дано* доля помеченных 0,35; *тогда* система в «осторожном» режиме, новые материалы не публикуются автоматически. *Дано* автор отправил 6 материалов за минуту; *тогда* после 5-го — предупреждение, после 6-го — отказ.
19. **UI.** Очередь показывает кластеры, а не отдельные материалы:

```
┌─ Очередь модерации ───────────────────────┐
│  ⚠ Растёт: 48 мин разбора. Режим: ��осторожный» │
│                                          │
│  ┌ 12 похожих ─────────────────────────┐ │
│  │ «Сериал X — концовка объяснена…»     │ │
│  │ 8 авторов · ждут с 12:04            │ │
│  │ [ Открыть ]  [ Разделить ]          │ │
│  └──────────────────────────────────────┘ │
│                                          │
│  ┌ 3 жалобы · ждёт с 11:50 ────────────┐ │
│  │ «Автор, который уже заблокирован…»  │ │
│  │ [ Открыть ]                         │ │
│  └──────────────────────────────────────┘ │
└──────────────────────────────────────────┘
```
   **Фокальная точка:** предупреждение о росте очереди, если режим «осторожный» — она требует решения, а не внимания. **Телефон:** кластер занимает всю ширину, кнопки в столбик. **Скелетон:** три блока высотой кластера.
20. **КП.** Диаграмма состояний «очередь модерации».

## F-05-04 Очередь модерации: решения редактора · P0

1. **Назначение.** Дать редактору принять решение за минимум действий и с причиной, которую можно объяснить автору.
2. **Роли.** Редактор и выше; админ видит, но решение принимает редактор (DEC-005).
3. **Триггер.** Открытие S-50.
4. **Сценарий.** Материал крупно: текст целиком, совпавшее слово (редактору показывается — автору нет), причина, история автора за последние решения. Две кнопки (DEC-012): «Одобрить» и «Запретить». У «Одобрить» — дополнительный флажок «добавить слово в белый список», чтобы одно и то же ложное срабатывание не повторялось. После решения — следующий материал; при кластере решение применяется ко всем сразу. Решение отменяемо в пределах окна **[ГИПОТЕЗА]** — 10 минут, как у отметок.
5. **Альтернативы и ошибки.** Материал уже удалён автором — показываем «удалён автором», решение не требуется, пропуск без ошибки. Материал из другого кластера пришёл, пока открыт прежний — помечается, решение всё равно принимается. Слово добавлено в белый список и тут же нашлось в другом открытом материале — предлагается применить ко всем совпадениям **[ГИПОТЕЗА]**.
6. **Состояния.** Очередь пуста · материал на разборе · ожидает решения · решён · отменено решение · кластер.
7. **Данные.** E-EditorDecision, E-Material, E-ModerationCluster.
8. **Правила.**
   - (а) Решение всегда с причиной; автору уходит конкретная причина и найденное слово, а не код правила.
   - (б) Материал, ждущий решения, виден автору в «Моих материалах» со статусом, но без найденного слова.
   - (в) Действие необратимо для материала, но отменяемо для редактора в пределах окна; отмена пишется в аудит отдельной записью.
   - (г) Редактор не может мьютить привилегированного (EC-R4) и не видит данных модерации по администраторам.
   - (д) Добавление слова в белый список требует основания и попадает в аудит; удалить слово может администратор.
9. **Валидация и лимиты.** Не более 200 решений в час на редактора — защита от заведомо неправдоподобного темпа, которая сама является сигналом (`R-SEC-31`).
10. **Edge cases.** EC-U11, EC-U12, EC-R4, EC-U13.
17. **Побочные эффекты.** EV-21; уведомление автору; применение к кластеру; пересчёт счётчиков «качество модерации» на дашборде (M8).
18. **Приёмка.** *Дано* материал с находкой; *когда* редактор жмёт «Одобрить» с флажком белого списка; *тогда* материал опубликован, слово добавлено, оба события в аудите. *Дано* кластер из 12; *когда* решение принято; *тогда* все 12 получили одно решение и один результат. *Дано* автор удалил материал, пока он в очереди; *тогда* редактор видит «удалён автором» и пропускает без ошибки.
19. **UI.** Два действия, причина обязательна, текст крупно:

```
┌─ Материал ────────────────────────────────┐
│  найдено: «<слово из словаря>»            │  ← видно редактору
│  причина: запрещённый список              │
│  автор: 4 материала за неделю, из них      │
│         3 помечены                         │
│                                          │
│  ┌──────────────────────────────────────┐ │
│  │ Текст материала целиком,              │ │
│  │ с подсветкой найденного слова         │ │
│  └──────────────────────────────────────┘ │
│                                          │
│  ☐ Добавить «<слово>» в белый список      │
│                                          │
│  Причина: [запрещённый список      ▾]     │
│  [ Запретить ]   [ Одобрить ]  ← primary  │
└──────────────────────────────────────────┘
```
   **Фокальная точка:** текст материала, а не кнопки — решение принимается по содержанию. **Телефон:** кнопки в столбик, «Запретить» не красный: цвет остаётся только для подтверждения необратимого действия, которого здесь нет (отмена возможна).
20. **КП.** Диаграмма последовательностей «модерация материала».

## F-05-05 Жалобы на материал (EC-U-общий) · P0

1. **Назначение.** Дать пользователям сигналить о плохом содержимом — без этого модерация видит только то, что словарь поймал.
2. **Роли.** Зритель и выше.
3. **Триггер.** Кнопка «Пожаловаться» на отзыве, комментарии, руководстве, посте.
4. **Сценарий.** Выбор причины из списка `report.reasons` → необязательный комментарий → отправка. Жалоба не показывается автору жалобы и не влияет на видимость материала сама по себе: она поднимает приоритет в очереди и при достижении `report.threshold_hide` отправляет материал на дополнительную проверку.
5. **Альтернативы и ошибки.** Жалоба на собственный материал — не принимается. Повторная жалоба от того же пользователя на тот же материал — обновляет счётчик, новой записи не создаёт. Материал удалён — жалоба сохраняется в журнале, но не влияет ни на что. Причина «спойлер без метки» не удаляет материал, а ставит пометку на проверку.
6. **Состояния.** Нет жалоб · одна · несколько · порог достигнут · материал удалён.
7. **Данные.** E-Report (автор, материал, причина, комментарий, состояние, дата); счётчик по материалу — агрегат.
8. **Правила.**
   - (а) Жалоба не анонимно наказывает: материал уходит на проверку, а не удаляется автоматически.
   - (б) Счётчик жалоб виден только редактору и администратору.
   - (в) Автор материала не знает, кто жаловался.
9. **Валидация и лимиты.** ≤ 5 жалоб в сутки от пользователя; комментарий ≤ 500 знаков.
10. **Edge cases.** EC-U14, EC-U15.
17. **Побочные эффекты.** EV-28; приоритет в очереди; при пороге — вход в очередь.
18. **Приёмка.** *Дано* три жалобы «мусор» на отзыв; *тогда* отзыв в очереди у редактора, но не удалён. *Дано* жалоба на удалённый материал; *тогда* она сохранена в журнале и ни на что не влияет.
19. **UI.** Короткая форма, одна причина:

```
┌─ Пожаловаться ──────────────────┐
│  Причина:                        │
│  ○ Спам                          │
│  ● Оскорбление                   │
│  ○ Спойлер без метки             │
│  ○ Не по теме                    │
│  ○ Мусор                         │
│                                  │
│  Комментарий (необязательно):    │
│  [                              ] │
│                                  │
│  [ Отправить ]        [ Отмена ] │
└──────────────────────────────────┘
```
   **Фокальная точка:** список причин — их пять, показывать выпадающим списком незачем. **Телефон:** в столбик. **Скелетон:** не применяется.
20. **КП.** Не выносится на чертежи.

## F-05-06 Руководства: список, статья, редактор · P1

1. **Назначение.** Дать пользователям писать справочные статьи о сериалах.
2. **Роли.** Зритель и выше пишет; редактор модерирует; все читают.
3. **Триггер.** S-11 (список) и S-12 (статья).
4. **Сценарий.** Редактор статьи: заголовок, сериал, разделы (заголовок + текст), спойлер-метка на весь текст и на отдельный раздел, предпросмотр → проверка → публикация. Список: по всем сериалам или по одному, сортировка по дате и по популярности. Правка опубликованной статьи: предыдущая версия остаётся видимой до проверки новой — читатель не видит полуправленый текст.
5. **Альтернативы и ошибки.** Статья без разделов — отказ, одна сплошная стена нечитаема. Оглавление длиннее 20 разделов — схлопывается. Помечено — публикуется после решения редактора, как отзыв.
6. **Состояния.** Список пуст · список · статья · статья со спойлер-меткой · на проверке · отклонена.
7. **Данные.** E-Material (`guide`) с разделами в теле; E-DocumentVersion.
8. **Правила.**
   - (а) Тело статьи — структурированное (разделы), а не HTML: `R-SEC-11` запрещает исполняемый код пользователя.
   - (б) Спойлер-метка на разделе скрывает этот раздел, но не весь текст статьи.
   - (в) Ссылка в любом разделе — материал в очередь (DEC-015).
   - (г) Обложка статьи берётся из фона сериала автоматически; своей картинки у статьи нет.
9. **Валидация и лимиты.** `ugc.guide_min_chars` … `guide_max_chars`; ≤ 30 разделов; черновик сохраняется каждые 30 секунд.
10. **Edge cases.** EC-U16, EC-U17.
17. **Побочные эффекты.** EV-10; при новой статье — событие `guide_published` для подписчиков сериала **[ГИПОТЕЗА]**.
18. **Приёмка.** *Дано* статья с пятью разделами; *когда* один помечен спойлером; *тогда* остальные видны, этот скрыт под кнопкой. *Дано* правка опубликованной статьи; *тогда* читатель видит прежнюю версию до решения по новой.
19. **UI.** Статья читается, правится — блоками:

```
┌─ Порядок просмотра: S01 ───────────────┐
│  сериал · 12 разделов · обновлено вчера   │
│                                          │
│  Оглавление        │  Содержит спойлеры   │
│  1 Первые три       │  ☐ раскрыть         │
│  2 С четвёртой ◀    │                     │
│  3 О фinale         │  Текст раздела…     │
│  …                  │                     │
│                    │ [ Пожаловаться ]     │
└──────────────────────────────────────────┘
```
   **Фокальная точка:** заголовок текущего раздела. **Телефон:** оглавление сворачивается в кнопку «Оглавление». **Скелетон:** заголовок и два блока абзацев по ширине.
20. **КП.** Скриншот на плакат «модели представления».

## F-05-07 Обсуждения: темы, посты, закрепление · P1

1. **Назначение.** Дать место для разговора о сериале, привязанное к произведению.
2. **Роли.** Зритель и выше; редактор модерирует и закрепляет.
3. **Триггер.** S-13 (список тем сериала) и S-14 (тема).
4. **Сценарий.** Тема создаётся первым постом: заголовок, текст, спойлер-метка → проверка → тема. Посты отвечают друг другу по цепочке, глубина отображения — два уровня, дальше по кнопке. Редактор закрепляет полезный пост вверху темы. Тему можно закрыть: ответы прекращаются, тема остаётся видимой с пометкой.
5. **Альтернативы и ошибки.** Тема пустеет после удаления первого поста — тема помечается «удалено автором», остальные посты скрыты. Много постов — постраничная навигация, не «показать всё». Флуд — лимиты и мьют (F-05-08).
6. **Состояния.** Тема открыта · закрыта · закреплена · удалена · на модерации.
7. **Данные.** E-Material (`topic`, `comment`) + E-MaterialLink.
8. **Правила.**
   - (а) Закрытая тема принимает только чтение; ответ отклоняется с причиной.
   - (б) Закрепляет только редактор; автор темы — может, если он сам модератор темы **[ГИПОТЕЗА] — нет**.
   - (в) Спойлер-метка темы скрывает первый пост, но не обязана скрывать ответы — это разные материалы со своими метками.
   - (г) Ответ — один уровень вложенности в интерфейсе; глубже в структуре, показывается по раскрытию.
9. **Валидация и лимиты.** Тема: `ugc.topic_min_chars` … `max_chars`; ответ ≤ `ugc.comment_max_chars`; ≤ 200 постов на тему.
10. **Edge cases.** EC-U18, EC-U19.
17. **Побочные эффекты.** EV-10; счётчик ответов; уведомление автору темы об ответе **[ГИПОТЕЗА]**.
18. **Приёмка.** *Дано* тема закрыта; *когда* пользователь отвечает; *тогда* поле ответа заблокировано с текстом «тема закрыта». *Дано* 500 постов; *тогда* постраничная навигация, страница отдаётся целиком.
19. **UI.** Тема — плоский список постов с закреплённым сверху:

```
┌─ S01 — концовка объяснили? ──────────────┐
│  📌 Закреплено редактором                │
│  > Финал стоит смотреть целиком. (12)    │
│                                          │
│  nick · вчера 18:04                       │
│  > Я пересмотрел после спойлеров в чате…  │
│    [ Ответить ] [ Пожаловаться ]         │
│                                          │
│  nick · сегодня 09:12                    │
│  > Согласен, но второй сезон лучше.      │
│    [ Ответить ] [ Пожаловаться ]         │
│                                          │
│  ───────────────────────────────         │
│  [ Написать ответ…                  ]   │
└──────────────────────────────────────────┘
```
   **Фокальная точка:** закреплённый пост — он и есть ответ на вопрос «что почитать первым». **Телефон:** кнопки действий под постом во всю ширину. **Скелетон:** три блока поста по 4 строки.
20. **КП.** Скриншот на плакат «модели представления».

## F-05-08 Мьют и бан со стороны редактора · P0

1. **Назначение.** Остановить поток материалов от нарушителя, не отнимая у него доступ к сервису.
2. **Роли.** Редактор — мьют зрителю; администратор — мьют любому и бан; мьют привилегированного запрещён (EC-R4).
3. **Триггер.** Карточка автора материала в очереди или в S-53 («Мьюты»).
4. **Сценарий.** Мьют: срок от `ugc.mute_min_h` до `ugc.mute_max_h`, причина обязательна. Во время мьюта отправка любого материала отклоняется с текстом и датой окончания; чтение, оценка, отметки работают. Бан (только админ) — полная блокировка с отзывом сессий и флажком «скрыть материалы» (DEC-020). Материалы при бане получают состояние «Скрыт» и возвращаются при разбане.
5. **Альтернативы и ошибки.** Мьют истёк — доступ возвращается сам, уведомление не требуется. Автор попытался отправить материал в последнюю минуту мьюта — отказ, срок пересчитывается. Материал, отправленный до мьюта, всё равно проходит очередь. Редактор выдал мьют самому себе — запрещено.
6. **Состояния.** Нет ограничения · мьют активен · мьют истёк · бан · разбан.
7. **Данные.** E-Restriction (пользователь, вид `mute | ban`, срок, причина, автор решения, снят); E-AuditLog (`ROLES-PERMISSIONS` §1).
8. **Правила.**
   - (а) Мьют не отнимает чтение, оценки и отметки: он ограничивает только создание.
   - (б) Верхняя граница редакторского мьюта — `ugc.mute_max_h`; админ может больше.
   - (в) Срок и причина видны автору; формулировка причины — как её написал редактор, без машинных кодов.
   - (г) Все решения — в аудит, ничего не удаляется из журнала.
   - (д) Материалы скрытых авторов не попадают в агрегаты качества модерации как «плохие» — иначе бан делает статистику красивее, чем она есть.
9. **Валидация и лимиты.** Один активный мьют на пользователя; повторный продлевает, а не создаёт второй.
10. **Edge cases.** EC-U20, EC-U21, EC-R4, EC-U22.
17. **Побочные эффекты.** Событие администратору; EV-21 при бане; сброс кэша профиля.
18. **Приёмка.** *Дано* мьют зрителю на 24 часа; *когда* он пытается отправить отзыв; *тогда* отказ с текстом «до ограничения осталось 3 часа» и датой конца. *Дано* бан с флажком «скрыть материалы»; *когда* автор разбанен; *тогда* его материалы возвращаются в списки. *Дано* редактор пытается мьютить администратора; *тогда* действие недоступно, а сервер отклоняет.
19. **UI.** Решение о наказании — не тихий список, а причина и срок:

```
┌─ Ограничить пользователя ────────────────┐
│  nick · 4 материала на этой неделе        │
│                                          │
│  Действие: (•) Временно запретить        │
│            ( ) Забанить                   │
│                                          │
│  Срок: [24 ч ▾]  (до 168 ч)              │
│  Причина: [ Флуд отзывов           ]     │
│                                          │
```

## F-05-09 «Мои материалы» (S-35) · P0

1. **Назначение.** Дать автору видеть судьбу своих материалов и понять, что происходит.
2. **Роли.** Зритель и выше.
3. **Триггер.** Из меню аватара или со страницы материала после отправки.
4. **Сценарий.** Список всех материалов пользователя с фильтром по виду и по состоянию. Для каждого — заголовок, вид, объект, дата, состояние человеческим языком: «опубликован», «на проверке», «запрещён: спам», «скрыт до разбана». Действия: правка (только у черновика и опубликованного), повторная проверка (только с истечением паузы), удаление.
5. **Альтернативы и ошибки.** Материал в очереди и автор не знает слова — статус «на проверке», без причины. Запрещённый — причина видна (уведомление её уже прислало). Удаление во время проверки — материал снимается с очереди, решение не принимается.
6. **Состояния.** Пусто · список · фильтр · загрузка.
7. **Данные.** E-Material пользователя (тело не отдаётся в списке, только метаданные); E-MaterialStatus — производная от состояния материала.
8. **Правила.**
   - (а) Удаление возможно в любом состоянии, включая «опубликован» и «на проверке».
   - (б) Список не показывает счётчики модерации и кластеры: это внутреннее редакторское.
   - (в) Экспорт всех своих материалов — через «Мои данные» (M1 F-01-10).
9. **Валидация и лимиты.** Постранично; ≤ 20 правок в сутки суммарно по всем видам.
10. **Edge cases.** EC-U23.
17. **Побочные эффекты.** EV-10 при правке.
18. **Приёмка.** *Дано* три материала в разных состояниях; *тогда* у каждого своя подпись состояния, у запрещённого — причина. *Дано* материал в очереди; *когда* автор его удаляет; *тогда* из очереди исчезает, редактор его не видит.
19. **UI.** Таблица состояний — главное, а не карточки:

```
┌─ Мои материалы ──────────────────────────┐
│  [ Все ] [ Отзывы ] [ Руководства ]       │
│                                          │
│  Заголовок        Вид          Состояние  │
│  Концовка S01     отзыв        ✓ на       │
│                                  проверке  │
│  Порядок          руководство  ✗ запрещён:│
│  просмотра                      спам      │
│  Тема о финале    обсуждение   ○ черновик  │
│                                          │
│  Запрещён: найдено «<слово>». Можно      │
│  исправить и отправить снова.            │
└──────────────────────────────────────────┘
```
   **Фокальная точка:** причина запрета под запрещённым материалом — то, за чем пришёл человек. **Телефон:** таблица превращается в список карточек, состояние крупно. **Скелетон:** три строки высотой карточки.
20. **КП.** Скриншот на плакат «модели представления».

## 0. Сквозное для модуля

**Что страница решает.** Одна задача: показать, что нового, и дать одно действие, чтобы это посмотреть. Всё остальное — вторично. Поэтому главная не содержит ни формы поиска, ни фильтров, ни длинного текста: это экран, который открывают на несколько секунд.

**Порядок блоков и почему он такой.** Порядок задан `input/spec.md` и не переставляется без решения автора: три баннера → «Для вас» или «Популярное» → новинки → бегущая строка подборок → жанры. Причина: от самого важного к наименее важному, а новинки и подборки — это способы уйти в каталог, а не самостоятельные цели.

**Три баннера дня (OP-05).** Ровно три, каждый со своим правилом отбора и запасным:

1. **Новинка** — сериал с наибольшим рейтингом IMDb среди тех, у кого сегодня вышла серия. Запасной, если таких нет: лучший рейтинг среди «Выходит» за последние 7 дней.
2. **Классика** — сериал старше 10 лет с рейтингом выше 8,5. Запасной: ниже порога рейтинга → любой сериал старше 10 лет.
3. **Выбор редакции** — назначается админом вручную (M10 F-10-08). Запасной: последний активный выбор; если выборов нет — «Новинка» или «Классика» второго круга, но не тот же сериал дважды.

**Правило ротации.** Баннеры обновляются раз в сутки, в момент смены локальной даты, не по расписаниюcron-совпадением. Каждый баннер показывает: название, **почему он здесь** («Новинка», «Классика», «Выбор редакции») и рейтинг IMDb. Формулировка причины обязательна: без неё три баннера выглядят одинаково и пользователь не понимает, что перед ним.

**Баннеры — единственное место на сайте с текстом поверх фотографии.** `input/DESIGN.md` (21 TSI) это запрещает, и правило принято для сцены заставки; для баннеров оно осознанно отменено, потому что баннер без названия бесполезен. Выбран компромисс: текст лежит на градиентной подложке, а не прямо на кадре, и контраст текста к подложке ≥ 4,5:1 (`R-DES-23`).

**Стекло.** Только на поверхностях над изображением (M0 F-00-01 правило). Стеклянные карточки поверх фонового фона страницы не используются: на сплошной подложке стекло выглядит как серый прямоугольник и съедает бюджет размытия (`R-DES-20`).

**Сущности (поля уточняет Фаза 5):** E-Banner (тип `new | classic | editorial`, сериал, дата показа, активен) — по одному на дату и тип; E-EditorialPick (сериал, автор, срок, заметка) — из M10; остальное — каталог M2 и выходы M12. Главная **не заводит своих таблиц**: это представление существующих данных.

## F-06-01 Три баннера дня (OP-05) · P0

1. **Назначение.** Показать три разных повода зайти и объяснить каждый.
2. **Роли.** Все. Публикация «выбора редакции» — админ (M10 F-10-08).
3. **Триггер.** Открытие S-01; пересчёт — раз в `home.reload_hour` локальной суток.
4. **Сценарий.** Три баннера в ряд. Каждый: кадр 16:9, название, метка причины («Новинка» / «Классика» / «Выбор редакции»), рейтинг IMDb, год. Клик ведёт на страницу сериала. Правила отбора и запасные — в §0 и F-06-02.
5. **Альтернативы и ошибки.** Нет ни одного сериала под правилом «Новинка» — берётся запасное окно, затем классика. «Выбор редакции» не назначен — третий баннер берётся из второго круга правил, **но не повторяет уже показанный сериал**. Три правила дали один и тот же сериал — показываем один, остальные места занимают следующие по рейтингу. Нет фона 16:9 — баннер с заглушкой (M10 F-10-04), но он всё равно показывается: пустой баннер хуже, чем баннер без картинки.
6. **Состояния.** Три баннера · два (редкое, при пустом каталоге) · пусто (каталог не импортирован — S-43 со ссылкой на админа) · загрузка.
7. **Данные.** E-Banner, сериал, рейтинг IMDb, год, дата.
8. **Правила.**
   - (а) Метка причины обязательна и всегда одна из трёх. Баннер без метки не показывается.
   - (б) Рейтинг — IMDb, из числа голосов приходят с датой обновления; при < `external_rating.min_votes_display` показываем «Мало оценок» (M2 F-02-10).
   - (в) Текст — на градиентной подложке, не на кадре; контраст ≥ 4,5:1 к подложке (`R-DES-23`).
   - (г) Один сериал не занимает два места подряд; в наборе трёх все сериалы разные.
   - (д) Баннеры не показываются на S-01, если пользователь сегодня уже видел их все и закрыл блок — **не реализуем**: скрытие без объяснения ломает десктопный скриншот и демонстрацию. **[ГИПОТЕЗА]** на защите баннеры всегда видны.
9. **Валидация и лимиты.** Ровно три места; при нехватке кандидатов — пустые места не показываются, сетка подстраивается.
10. **Edge cases.** EC-H1, EC-H2, EC-H3.
17. **Побочные эффекты.** EV-03; сброс кэша главной в `home.reload_hour`; при смене «выбора редакции» — сброс немедленно.
18. **Приёмка.** *Дано* сегодня вышел новый эпизод у сериала с рейтингом 9,1 и у сериала с рейтингом 8,0; *тогда* первым баннером идёт сериал с 9,1. *Дано* два сериала вышли в один день с одинаковым рейтингом; *тогда* выбор детерминирован, при повторном открытии тот же. *Дано* админ снял выбор редакции; *тогда* третий баннер пересчитывается без ручного вмешательства. *Дано* у сериала нет фона 16:9; *тогда* баннер показан с заглушкой и фокусной точкой по умолчанию, CLS = 0.
19. **UI.** Три колонки, стекло над кадром, текст слева, объект справа:

```
┌─────────────────────────────────────────────────────────────────┐
│ ┌─ стекло, градиент ────┐   ┌─ стекло ────────┐   ┌──────────┐ │
│ │ НОВИНКА               │   │ КЛАССИКА        │   │ ВЫБОР    │ │
│ │ Название сериала       │   │ Название        │   │ РЕДАКЦИИ │ │
│ │ 2008–2013 · IMDb 9,1  │   │ 2001 · IMDb 9,4 │   │ …        │ │
│ └───────────────────────┘   └─────────────────┘   └──────────┘ │
│   ↑ метка причины — главное    ↑ крупное число      ↑          │
│      (focal point)                                              │
│      текст в левой трети, объект кадра — в правой (R-DES-02)   │
└─────────────────────────────────────────────────────────────────┘
```
   **Фокальная точка:** метка причины на первом баннере; на остальных — название; крупных чисел по одному на баннер. **Телефон (< 640):** баннеры каруселью, один на экран, метка причины остаётся; свайп и кнопки. **Планшет (640–1024):** первый баннер во всю ширину, второй и третий — в ряд. **Десктоп:** три в ряд. **Скелетон:** три прямоугольника 16:9, внутри — две полосы: метка и название.
20. **КП.** Скриншот на плакат «модели представления»; OP-05 — в ПЗ 4.1.2.

## F-06-02 Отбор и запасные правила баннеров (OP-05) · P0

1. **Назначение.** Гарантировать, что три баннера есть всегда и что они разные.
2. **Роли.** Система; админ влияет только на «выбор редакции».
3. **Триггер.** `home.reload_hour` локальной суток либо ручной пересчёт админом.
4. **Сценарий.** (1) **Новинка:** среди сериалов в состоянии «Выходит» с выходом сегодня — наибольший рейтинг IMDb. (2) **Классика:** `startYear ≤ 2016` и рейтинг ≥ 8,5; при отсутствии — любой старше 10 лет. (3) **Выбор редакции:** активная запись без срока или со сроком в будущем. (4) Если кандидат уже занят другим местом — следующий по рейтингу. (5) Если всё пусто — пустое состояние со ссылкой «каталог ещё импортирован».
5. **Альтернативы и ошибки.** В состоянии «Выходит» нет ни одного сегмента с серией сегодня — берётся окно `home.new_release_window_d`. Рейтинг отсутствует — сериал не может быть «Новиной» (сортировка нечем), но может быть «Классикой». Смена выбора редакции посреди суток — пересчёт немедленно, это единственное исключение из суточного ритма.
6. **Состояния.** Все три места · частично · пусто.
7. **Данные.** E-Banner (тип, сериал, дата показа, активен); E-EditorialPick — из M10 F-10-08. Отбор — чистая функция от каталога и выходов, результат сохраняется, а не пересчитывается на запрос.
8. **Правила.**
   - (а) Отбор детерминирован: одинаковые входные данные дают одинаковую тройку, иначе главная «моргает» при каждом заходе.
   - (б) Сериал в состоянии «Ждём сезон», «Завершён» или «Отменён» баннером быть не может.
   - (в) Рейтинг IMDb, не рейтинг сайта: рейтинг сайта на момент суток ещё не накоплен.
   - (г) Расчёт хранится (`E-Banner`), а не пересчитывается на каждый запрос — иначе главная стоит на агрегате.
   - (д) Отбор не выбирает то, что скрыто флажком «скрыть материалы» бана: у скрытых авторов баннеров не бывает, а сериалы каталога не скрываются.
9. **Валидация и лимиты.** Один расчёт в сутки; ручной пересчёт доступен админу и пишется в аудит.
10. **Edge cases.** EC-H4, EC-H5.
17. **Побочные эффекты.** EV-23 при завершении расчёта; сброс кэша S-01.
18. **Приёмка.** *Дано* три сериала «Выходит» с выходом сегодня, рейтинги 9,1 / 9,4 / 8,8; *тогда* первым идёт 9,4. *Дано* «Новинка» и «Классика» дали один сериал; *тогда* в «Классике» следующий по рейтингу. *Дано* ручной пересчёт дважды подряд; *тогда** результат тот же — пересчёт идемпотентен.
19. **UI.** Не визуализируется отдельно — результат виден в F-06-01. Админ видит отчёт расчёта на S-76: «Новинка: X (9,4) · Классика: Y (9,1) · Выбор: Z (выбор админа)».
20. **КП.** Диаграмма деятельности «отбор баннеров» — из неё получается **IDEF0-уровень A-0** для листа 5.1: три параллельные ветви с одним выходом.

## F-06-04 Бегущая строка подборок · P0

4. **Сценарий.** Зацикленная строка из шести самых популярных подборок. У каждой — баннер (по умолчанию фон первого сериала подборки, админ может заменить — M10), название, число сериалов. Клик ведёт на страницу подборки (S-05). Строка едет сама с интервалом `home.marquee_interval_ms`, появление новой подборки — циклично, без «прыжка».
5. **Альтернативы и ошибки.** Подборок меньше шести — столько и показываем. Нет подборок вовсе — блок скрывается, страница не ломается. У подборки нет фона — заглушка с названием, подборка всё равно показывается. Подборка скрыта админом (EC-S13) — исчезает из строки, число мест пересчитывается.
6. **Состояния.** Шесть · меньше шести · пусто (скрыт блок) · пауза при фокусе.
7. **Данные.** Подборки и их баннеры из M2 F-02-05 и M10; «популярность» — агрегат просмотров за 30 дней. Набор шести фиксируется на сутки, чтобы строка не прыгала.
8. **Правила.**
   - (а) Подборки — **не то же, что жанры**: обобщёны по теме, а не по жанру («вечная битва», «библейские мотивы», «сериалы 2026 года»). Это прямо из `input/spec.md` и часто путается при реализации.
   - (б) Ровно шесть самых популярных — «популярность» по просмотрам страницы подборки за 30 дней; при отсутствии данных — по дате создания.
   - (в) Строка останавливается при наведении и при фокусе, кнопки «влево/вправо» прокручивают вручную (`R-A11Y-09`) — без этого она недоступна с клавиатуры.
   - (г) Двигается только `transform` (`R-DES-25`).
   - (д) При `prefers-reduced-motion` строка стоит на месте, доступна прокруткой и кнопками.
9. **Валидация и лимиты.** Шесть подборок в наборе; баннер подборки ≥ 6 сериалов, иначе подборка скрыта (`CONTENT-PLAN` §2).
10. **Edge cases.** EC-H8, EC-H9.
17. **Побочные эффекты.** EV-06 при переходе; счётчик просмотров подборки.
18. **Приёмка.** *Дано* пользователь нажал Tab на бегущую строку; *тогда* она останавливается и останавливается при уходе фокуса. *Дано* включён `prefers-reduced-motion`; *тогда* строка не едет, кнопки работают. *Дано* подборка скрыта админом; *тогда* строка пересобирается без неё, без перезагрузки.
19. **UI.** Зацикленная лента, пауза на наведении и фокусе:

```
┌ Подборки ────────────────────────────────────────────────────┐
│ ◀ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ▶   │
│   │вечная│ │библ. │ │2026  │ │ ...  │ │      │ │      │     │
│   │битва │ │мотивы│ │год   │ │      │ │      │ │      │     │
│   │12    │ │ 8    │ │ 34   │ │      │ │      │ │      │     │
│   └──────┘ └──────┘ └──────┘ └──────┘ └──────┘ └──────┘     │
│     ↑ баннер = фон первого сериала подборки                    │
│       число сериалов — обязательно: без него полоса сливается  │
└──────────────────────────────────────────────────────────────┘
```
   **Фокальная точка:** на главной фокус не на этой строке — она вторична; при управлении с клавиатуры фокус на кнопке «вправо». **Телефон:** по две подборки, прокрутка свайпом, кнопки остаются. **Скелетон:** шесть прямоугольников 16:9 с одной полосой под каждым.
20. **КП.** Скриншот на плакат.

## F-06-05 Жанры внизу страницы · P0

1. **Назначение.** Дать последний способ уйти в каталог — по жанру.
2. **Роли.** Все.
3. **Триггер.** Открытие S-01.
4. **Сценарий.** Шесть жанров, у каждого шесть случайных сериалов этого года (по `input/spec.md` — «рандомных», и это осознанно: внизу страницы уже нечего выбирать). Название жанра — ссылка на S-03. Страниц у этого блока нет.
5. **Альтернативы и ошибки.** Сериалов этого года в жанре меньше шести — цепочка `CONTENT-PLAN` §2: год → 3 года → всё время. Жанров с шестью сериалами меньше шести — дополняем следующими по количеству. Меньше шести жанров в справочнике — блок скрывается.
6. **Состояния.** Шесть жанров · меньше · пусто (блок скрыт).
7. **Данные.** Жанры из справочника M10 F-10-10; шесть постеров на жанр из каталога M2. Набор фиксируется на сутки и детерминирован.
8. **Правила.**
   - (а) «Случайные» — детерминированно: набор фиксируется на сутки, иначе при каждом обновлении страницы постеры меняются и страницу не узнать.
   - (б) Заголовок жанра — ссылка, кликается вся строка целиком, но подпись остаётся читаемой.
   - (в) Карусели и автопрокрутки здесь нет: блок последний и не должен притягивать внимание.
   - (г) Возрастная метка и рейтинг на постере не показываются: место для них есть только на странице сериала.
9. **Валидация и лимиты.** 6 жанров × 6 сериалов; справочник — из M10 F-10-10.
10. **Edge cases.** EC-H10.
17. **Побочные эффекты.** EV-06 при переходе к жанру и к сериалу.
18. **Приёмка.** *Дано* пользователь обновляет страницу трижды; *тогда* постеры в блоке жанров те же. *Дано* в жанре 4 сериала этого года; *тогда* берётся окно в 3 года. *Дано* жанров меньше шести в справочнике; *тогда* блок скрыт, страница работает.
19. **UI.** Шесть жанров по шесть постеров, без карусели:

```
┌ Жанры ───────────────────────────────────────────────────────┐
│ Драма ›                                                  →   │
│ [ ][ ][ ][ ][ ][ ]                                           │
│ Комедия ›                                                →   │
│ [ ][ ][ ][ ][ ][ ]                                           │
│ Детектив ›                                                →   │
│ [ ][ ][ ][ ][ ][ ]                                           │
│ …                                                            │
└──────────────────────────────────────────────────────────────┘
   ↑ у постеров здесь только картинка: место и время не на что тратить
```
   **Фокальная точка:** название первого жанра со стрелкой. **Телефон:** один жанр на строку, постеры в два ряда. **Планшет:** два жанра в ряд. **Скелетон:** шесть постеров 2:3 без подписей, шесть раз.
20. **КП.** Не выносится на чертежи.

## F-06-06 Строка «Для вас» и персонализация · P1

1. **Назначение.** Показать вошедшему то, что ему может быть интересно, вместо общего «Популярное».
2. **Роли.** Зритель и выше; гостю показывается «Популярное».
3. **Триггер.** Открытие S-01.
4. **Сценарий.** Первым рядом под баннерами: шесть постеров из рекомендаций (M11). Персонализация отключается в настройках; при выключенной показывается тот же ряд «Популярное». Персонализация не должна заметно менять LCP: блок грузится вторым запросом и не блокирует отрисовку.
5. **Альтернативы и ошибки.** Новый пользователь без отметок и оценок — «Популярное», без пустых мест. Рекомендательный сервис недоступен — «Популярное» без сообщения об ошибке. Пользователь скрыл рекомендацию (EV-14 `reco_dismiss`) — сериал не возвращается минимум 30 дней.
6. **Состояния.** Персонализировано · популярное (нет данных) · популярное (отключено) · загрузка.
7. **Данные.** Рекомендации из M11; при недоступности — «популярное» из каталога M2. Скрытые рекомендации (reco_dismiss) исключаются минимум на 30 дней.
8. **Правила.**
   - (а) Гость и зритель без данных получают одинаковую страницу: замысел один, а не два.
   - (б) Холодный старт — из «любимых», выбранных при регистрации (DEC-020, H-55), но в рекомендации они не превращаются в статус «просмотрено» (H-55).
   - (в) Раскрытая карточка постара на этой строке работает так же, как в «Новинках».
9. **Валидация и лимиты.** Шесть постеров; кэш страницы персонализируется по идентификатору.
10. **Edge cases.** EC-H11.
17. **Побочные эффекты.** EV-14; кэш ключа включает набор рекомендаций.
18. **Приёмка.** *Дано* гость; *тогда* блок называется «Популярное». *Дано* зритель без отметок; *тогда* то же, без пустых мест и без сообщения об ошибке. *Дано* рекомендации отключены в настройках; *тогда* то же, и причина не показывается.
19. **UI.** Заголовок меняется, геометрия — нет:

```
┌ Для вас ─────────────────────────────────────────────────────┐
│ [ ][ ][ ][ ][ ][ ]                                           │
└──────────────────────────────────────────────────────────────┘
   у гостя тот же ряд, но заголовок «Популярное»
```
   **Фокальная точка:** заголовок блока. **Телефон:** два в ряд. **Скелетон:** шесть постеров.
20. **КП.** Скриншот на плакат «модели представления».

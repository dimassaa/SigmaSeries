# TOKENS — значения темы

> v0.1 · Фаза 4 · закрывает последний пункт `PRINCIPLES` §14: «токены — позже, после макетов». Обещан в `PLAN` §7. Правила `R-DES-*` описывают **что** должно быть; этот файл — **каким числом**.
> **Референсы и их роль:** `input/DESIGN.md` (21 TSI) даёт сцену заставки, `input/DESIGN (1).md` (OpenSea) — оболочку и плотность, `input/Design.md` — нормы интерфейса. Иерархия источников — `PRINCIPLES` §1. **Сайт светлый и тёмный**, тогда как все три референса тёмные (конфликт D-02, закрыт в `PRINCIPLES`).

## 1. Поверхности и тёмная тема

Семь уровней. Переход между соседними — не менее 3 единиц по воспринимаемой яркости, иначе границы не видно на стекле.

| Токен | Тёмная | Светлая | Где |
|---|---|---|---|
| `--surface-canvas` | `#080809` | `#FBFBFC` | фон страницы |
| `--surface-raised` | `#141415` | `#FFFFFF` | карточки, панели |
| `--surface-overlay` | `#1b1d1f` | `#FFFFFF` | выпадающие, попапы |
| `--surface-sunken` | `#101011` | `#F1F2F4` | поля ввода, код |
| `--surface-glass` | `#1b1d1f` + blur | `#FFFFFF` + blur | только над изображением (R-DES-20) |
| `--surface-hover` | `#26272d` | `#EEF0F3` | наведение |
| `--border-subtle` | `rgba(255,255,255,0.10)` | `rgba(0,0,0,0.08)` | границы |
| `--border-strong` | `rgba(255,255,255,0.18)` | `rgba(0,0,0,0.14)` | активные границы |

Текстовые токены добавлены при первой вёрстке — в списке поверхностей их не
было, а без них компоненты вынуждены были бы писать цвет текста у себя, то
есть тема перестала бы переключаться:

| Токен | Тёмная | Светлая | Контраст к своему фону |
|---|---|---|---|
| `--text-primary` | `#ECECEF` | `#16171A` | 16,9:1 / 17,2:1 |
| `--text-secondary` | `#9A9AA3` | `#5A5C63` | 6,9:1 / 6,8:1 |
| `--text-inverse` | `#080809` | `#FFFFFF` | для текста на акценте |

## 2. Акцент

**Один акцентный цвет на всё приложение** (R-DES-07, правило 60-30-10). Второй акцент — не вводится: правило трёх цветов из `input/Design.md` иначе не выполняется.

| Токен | Тёмная | Светлая |
|---|---|---|
| `--accent` | `#83c3ff` | `#1668d4` |
| `--accent-hover` | `#a3d3ff` | `#0f57b5` |
| `--accent-contrast` | `#080809` | `#FFFFFF` |
| `--accent-area` | 10% | 10% — доля поверхности под акцентом (R-DES-08) |

Яркость акцента разная в темах: `#83c3ff` на тёмном читается, но на светлом почти белый; на светлом акцент темнеет, иначе контракт упал бы ниже 4,5:1.

## 3. Состояния

Цвет **никогда не единственный носитель состояния** (R-DES-09) — везде дублируется значком или текстом.

| Токен | Значение | Всегда с |
|---|---|---|
| `--positive` | `#3fb27f` | ✓ или «готово» |
| `--warning` | `#d99a2b` | ! или «проверьте» |
| `--danger` | `#e05252` | ✕ или «отклонено» |
| `--info` | `--accent` | — |

Контраст всех четырёх к своему фону ≥ 4,5:1. `--danger` на стекле над фотографией не используется: на непредсказуемом фоне гарантировать контраст нельзя, поэтому на баннерах деструктивных состояний нет по дизайну, а не по недоработке.

## 4. Типографика

Семь размеров, четыре веса. Мобильный и десктопный шкалы различаются на 1–2 шага, а не отдельными наборами.

| Токен | Десктоп | Телефон | Назначение |
|---|---|---|---|
| `--text-3xl` | 40px | 28px | крупное число дашборда |
| `--text-2xl` | 32px | 24px | h1 страницы |
| `--text-xl` | 24px | 20px | h2, название сериала |
| `--text-lg` | 18px | 16px | h3, заголовок блока |
| `--text-base` | 16px | 16px | основной текст |
| `--text-sm` | 14px | 14px | подписи, метаданные |
| `--text-xs` | 12px | 12px | метки, сноски |

Веса: `--weight-regular` 400, `--weight-medium` 500, `--weight-semibold` 600, `--weight-bold` 700.

**Шрифт.** Один читаемый, с кириллицей в основном начертании и в цифрах (R-DES-14). **Важно:** `input/DESIGN.md` задаёт Saans, `input/DESIGN (1).md` — gtAmerica; обе — коммерческие без кириллицы (конфликт D-05). Поэтому берётся системный стек с необязательным подключением одного из них для латиницы.

```
--font-sans: system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif;
--font-mono: ui-monospace, "JetBrains Mono", "Cascadia Code", Consolas, monospace;
```

`font-display: swap` обязателен (R-DES-17), и запасной семейный список должен покрывать кириллицу — иначе при медленной загрузке шрифта текст мигнёт на несовместимые метрики.

## 5. Отступы и радиусы

Шкала отступов кратна **4 px** — поштучные значения вне шкалы (`margin: 13px`) запрещены (R-DES-05).

```
--space-1: 4px   --space-2: 8px   --space-3: 12px  --space-4: 16px
--space-5: 24px  --space-6: 32px  --space-7: 48px  --space-8: 64px
--space-9: 96px  --space-10: 128px
```

**Отступы не равны** (правило из `input/Design.md`): между связанными элементами меньше, чем между группами. Конкретно: внутри карточки `--space-3`, между карточками `--space-5`, между секциями `--space-8`. Плоские равные отступы — самая частая причина, по которой интерфейс выглядит «собранным из блоков».

**Радиусы: чем меньше, тем лучше** (R-DES-19). Конфликт D-08 зафиксировал 70px у 21 TSI и ≤ 8px у OpenSea; выбран второй: система ближе к рабочему инструменту, чем к модной обложке.

```
--radius-sm: 4px    кнопки, поля
--radius-md: 8px    карточки, панели
--radius-lg: 12px   модальные окна
--radius-pill: 999px  только метки и переключатели
```

Вложенный радиус всегда меньше внешнего (`input/Design.md`): карточка `--radius-md`, кнопка внутри неё `--radius-sm`. Иначе скругления «схлопываются» визуально.

## 6. Тени и тени отсутствуют как приём

Тотен нет (`input/DESIGN (1).md`, §Elevation). Отделение поверхностей делают три средства: **тонкая линия**, **смена уровня поверхности**, **размытие стекла**. Это дешевле для отрисовки и выглядит современнее, чем набор серых прямоугольников.

Допускается тень только у **плавающего** элемента — попапа, модального окна — и ровно одна, мягкая:

```
--shadow-float: 0 8px 32px rgba(0,0,0,0.28);   /* только для .is-floating */
```

## 7. Правило 3:1 и границы фокуса

| Токен | Значение |
|---|---|
| `--focus-ring` | `2px solid var(--accent)` |
| `--focus-offset` | `2px` |
| `--focus-contrast` | ≥ 3:1 к любой поверхности |

Видимый фокус обязателен у каждого интерактивного элемента и не должен обрезаться родительским `overflow` (M0 F-00-08).

## 8. Как пользоваться

1. В компоненте — **только токен**, никогда не hex. Иначе тему не переключить и не объяснить.
2. Добавляя токен — здесь, а не в компоненте.
3. Значение, которое понадобится в трёх местах, **становится токеном**; в двух — оставляется локальным (YAGNI).
4. Значение «подберём позже» в коде не оставляется: нет токена — есть осознанное число с комментарием.

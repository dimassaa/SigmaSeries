# ANALYTICS — стандарт событий, метрик и экспериментов

> v0.1 · Фаза 3 · питает модуль M8 и экраны S-60…S-66. Правила `R-AN-NN`. Каждый модуль в измерении 16 своей спеки ссылается на события `EV-NN` отсюда. Метки: **[ГИПОТЕЗА]**.

## 1. Правила

| ID | Правило |
|---|---|
| R-AN-01 | Имена событий — `объект_действие` в нижнем регистре со знаком подчёркивания; схема каждого события версионируется. |
| R-AN-02 | Общие свойства у каждого события: `event_id` (UUID), `ts_client`, `ts_server`, `anon_id`, `user_pseudo_id` (после входа), `session_id`, `locale`, `theme`, `device_class`, `viewport_bucket`, `page_type`, `referrer_type`, `experiments` (список «эксперимент → вариант»), `app_version`, `is_demo`. |
| R-AN-03 | **Согласие:** до согласия — только серверные агрегированные счётчики без идентификаторов; идентификаторы (`anon_id`) — после согласия. |
| R-AN-04 | В событиях нет персональных данных: email, имён, свободного текста, полного IP (усечён). |
| R-AN-05 | События, влияющие на данные (решения модерации, импорт, назначение роли), пишет **сервер**, а не клиент. |
| R-AN-06 | Сессия — 30 минут простоя; новый вход не обрывает её. |
| R-AN-07 | Клиент отправляет пакетами (`sendBeacon`), повтор с тем же `event_id` безопасен. |
| R-AN-08 | Дедупликация по `event_id`; допуск расхождения часов клиента — проверяется по `ts_server`. |
| R-AN-09 | Роботы отфильтровываются (список агентов, отсутствие скриптов, частота); отфильтрованное хранится с признаком, а не теряется. |
| R-AN-10 | Хранение: сырые события 90 дней, агрегаты бессрочно (`SECURITY` §4). |
| R-AN-11 | Синтетические данные помечены `is_demo`; демо и реальные не смешиваются в метриках; на дашбордах — бейдж «демо-данные». |
| R-AN-12 | **Приём событий:** проверка схемы и размера, лимит частоты, одноразовый токен сессии против подделки; невалидное отбрасывается и считается. |
| R-AN-13 | У каждой метрики есть определение в словаре (§3); дашборд показывает ссылку на определение. |
| R-AN-14 | Эксперимент назначается по стабильному хэшу идентификатора с солью эксперимента; вход пользователя не меняет вариант. |
| R-AN-15 | Назначение — **на сервере**; экспозиция пишется в момент показа проверяемого элемента, а не при назначении. |
| R-AN-16 | Анализ эксперимента: проверка деления трафика (SRM, χ², порог p < 0,001), запрет решений до достижения запланированной выборки (защита от «подглядывания»), оценка размера выборки до запуска. |
| R-AN-17 | Аналитик видит только псевдонимизированные идентификаторы; экспорт — только агрегаты. |
| R-AN-18 | Показатели скорости (LCP, INP, CLS) приходят как события `web_vitals`. |
| R-AN-19 | **Исключение для поиска:** тексты запросов в события не пишутся. Отчёт «поиск без результата» строится из отдельного серверного агрегата: нормализованная строка (≤ 60 знаков), счётчик, без идентификатора пользователя; строки, похожие на email, телефон или ссылку, отбрасываются; хранение 30 дней. |

## 3. Словарь метрик

| Метрика | Определение |
|---|---|
| Активный пользователь (день / неделя / месяц) | Хотя бы одно «значимое» событие: `status_set`, `episode_mark`, `rating_set`, `material_submit`, `reco_click`, `banner_click`; просмотр страницы один — не активность |
| Новый пользователь | `signup_complete` |
| Активация | Первая `episode_mark` или `status_set` в течение 7 дней после регистрации |
| Отслеживаемых сериалов на пользователя | Число сериалов со статусом «Смотрю» или «В планах» |
| **North star [ГИПОТЕЗА]** | Отметок просмотренных серий на активного пользователя в неделю |
| Удержание | Доля когорты (по неделе регистрации), снова активной через 1, 2, 4 недели |
| Воронка роста | Визит → `signup_complete` → активация → активность на неделе 2 |
| CTR баннеров / рекомендаций | `*_click` / `*_impression` |
| Прошли с первого раза | Доля `material_submit` с результатом «опубликован» без помеченности |
| Время в очереди (медиана, p90) | От появления в очереди до `moderation_decision` |
| Поиск без результата | Доля `search_submit` с нулём результатов |
| p75 LCP / INP / CLS | По `web_vitals` |

## 5. Синтетическое население

Генератор создаёт пользователей, оценки, отметки и события с реалистичной формой: суточные и недельные ритмы, всплески в день премьер, длинный хвост активности, доля «ретро»-отметок, долю помеченных материалов. Всё с `is_demo = true`. Качество рекомендаций и значимость A/B на синтетике проверяют работоспособность, а не истину (`PLAN` А5). Детали — `SEED-AND-SIMULATION` (Фаза 5).

# PERFORMANCE — стандарт скорости и бюджетов

> v0.1 · Фаза 3. Правила `R-PERF-NN`. Пороги Core Web Vitals подтверждены (2026-10-04): LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 на 75-м процентиле реальных посещений. Остальные числа — **[ГИПОТЕЗА, H-24]**, подтверждаем замерами в Фазе 7.

## 1. Бюджеты

| Метрика | Цель | Где измеряем |
|---|---|---|
| LCP (главная, мобильный, медленная 4G) | ≤ 2,5 с, цель ≤ 2,0 с | Lighthouse CI, RUM |
| INP | ≤ 200 мс | RUM |
| CLS | ≤ 0,1, цель 0 | Lighthouse CI, RUM |
| TTFB кэшированных страниц, p95 | ≤ 200 мс | серверные метрики |
| Ответ API, p95 | ≤ 300 мс | серверные метрики |
| HTML страницы, сжатый | ≤ 60 КБ | CI |
| JS на первую отрисовку, сжатый | ≤ 150 КБ | CI |
| CSS на первую отрисовку, сжатый | ≤ 60 КБ | CI |
| Шрифты | ≤ 2 файла, ≤ 100 КБ суммарно | CI |
| Изображение LCP (баннер) | ≤ 150 КБ | CI |
| Постер-миниатюра | ≤ 25 КБ | CI |
| Запросов к БД на страницу | ≤ 15, без N+1 | тесты |
| Заставка: передача до показа сайта | ≤ 400 КБ (12–16 заранее размытых кадров ≈ 15–25 КБ) | CI |
| Рост памяти процесса за час нагрузки | без устойчивого роста | нагрузочный прогон |

## 2. Правила

| ID | Правило |
|---|---|
| R-PERF-01 | У каждого индексируемого экрана есть бюджет и запись в `COVERAGE`; превышение блокирует слияние (CI). |
| R-PERF-02 | **CLS = 0 как цель:** у изображений `width`/`height` или `aspect-ratio`; скелетоны того же размера; шрифты с запасным `size-adjust`; вставки сверху страницы после загрузки запрещены. |
| R-PERF-03 | Элемент LCP главной (баннер) не ленивый: `fetchpriority="high"`, предзагрузка нужного размера. Остальные изображения — `loading="lazy"`. |
| R-PERF-04 | Изображения: современный формат + запасной, `srcset` по готовым вариантам, отдача из БД через адрес с версией и `Cache-Control: immutable`, `ETag`. |
| R-PERF-05 | Шрифты: самостоятельный хостинг, подмножество (кириллица + латиница), `font-display: swap`, предзагрузка ≤ 2 файлов. |
| R-PERF-06 | Кэш: версионированные ресурсы — год; блоки главной (баннеры, жанры) — на сутки; правая панель — на ≈ 5 минут; сброс при правках админа. |
| R-PERF-07 | Сжатие ответов (Brotli или gzip), HTTP/2. |
| R-PERF-08 | Запросы к БД: индексы под каждый шаблон запроса, проверка планов (`EXPLAIN`) для горячих, пулы соединений с лимитами, пагинация по ключу. |
| R-PERF-09 | Тяжёлое — вне запроса: импорт, агрегаты аналитики, итоги, рассылки идут задачами по расписанию или из очереди. |
| R-PERF-10 | Бюджет стекла и анимаций — `PRINCIPLES` R-DES-22, 25: анимируем `transform`/`opacity`; rail — наложение без перераскладки; бегущая строка — CSS. |
| R-PERF-11 | Карточка постера при наведении: данные подгружаются по намерению (задержка ≈ 150 мс), ответ кэшируется; на touch — по нажатию. |
| R-PERF-12 | Страницы «Новинок» (3 по 6) приходят одним запросом и переключаются без загрузок; следующие страницы подгружаются заранее. |
| R-PERF-13 | Заставка: кадры предварительно размыты при подготовке, а не `filter` на больших картинках; общий срок ≤ 5–7 с по таймеру независимо от загрузки; не блокирует отрисовку страницы под ней. |
| R-PERF-14 | Скрипты: загрузка по требованию для редких экранов (дашборды, студия); сторонних скриптов нет. |
| R-PERF-15 | RUM: метрики Web Vitals отправляются как события (`ANALYTICS` EV-20); аналитик видит p75 по страницам. |

## 3. Нагрузочные сценарии

| ID | Сценарий | Цель |
|---|---|---|
| L-01 | Главная: 100 одновременных посетителей, кэш прогрет | p95 ≤ 300 мс, ошибок 0 |
| L-02 | **Флуд запрещённым контентом:** 1000 пользователей по 5 материалов в минуту | Очередь не растёт выше потолка, p95 отправки ≤ 500 мс, редактор открывает очередь без задержки |
| L-03 | Страница сериала + отметка серий: 50 одновременных пользователей | p95 ≤ 300 мс, нет дублей отметок |
| L-04 | Импорт во время нагрузки на сайт | p95 сайта не хуже, чем на 20% |
| L-05 | Поток уведомлений: премьера популярного сериала у 10 000 подписчиков (синтетика) | Рассылка завершается за разумное время без блокировки запросов |
| L-06 | Поток событий аналитики | Приём не блокирует запросы; потеря событий < 1% |

## 4. Измерения

CI: Lighthouse с бюджетами на 6 эталонных страницах (главная, каталог, сериал, календарь, отзывы, вход); размеры пакетов. Продакшен: RUM по 75-му процентилю. Нагрузка: сценарии L-01…L-06 перед заморозкой и перед защитой. Железо для отчёта в ПЗ фиксируем (процессор, память, ОС).

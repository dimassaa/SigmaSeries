# TESTING — стратегия тестирования

> v0.1 · Фаза 3 · раздел ПЗ 4.3. Правила `R-TST-NN`. Инструменты выбираем в Фазе 7; здесь — что и как проверяем. Метки: **[ГИПОТЕЗА]**.

## 1. Уровни

| Уровень | Что проверяет | Примеры |
|---|---|---|
| Модульные | Чистая бизнес-логика `OP-xx` | нормализация и поиск модерации; рейтинг сайта; подписи «через N дней»; полнота карточки; выбор баннеров; рекомендации; агрегация аналитики |
| Интеграционные | Приложение + настоящая БД, миграции вверх и вниз | отметка серии → прогресс; публикация материала → очередь; импорт на фикстурах |
| Контрактные | Разбор данных IMDb и TMDB на записанных ответах (без сети в CI) | пара по обратному идентификатору; выход как группа серий; нет ru-описания; нет метки RU/BY |
| Сквозные (e2e) | Основные пути из `JOURNEYS` | J-02, J-03, J-04, J-09, J-13, J-14 |
| Безопасность | `SECURITY`, `THREAT-MODEL` | матрица прав; XSS-корпус; SSRF; лимиты; заголовки |
| Доступность | `A11Y` | axe; клавиатура; масштаб |
| Скорость | `PERFORMANCE` | бюджеты страниц; нагрузка L-01…L-06 |
| i18n | `I18N` | отсутствующие ключи; псевдолокаль; множественные числа 1/2/5/11/21 |
| SEO | `SEO` | канонические адреса, hreflang, карта сайта, разметка, `robots` |
| Восстановление | Бэкап | автоматическое восстановление копии в пустую БД и проверка целостности |

## 2. Правила

| ID | Правило |
|---|---|
| R-TST-01 | Для каждого `OP-xx` есть модульные тесты с границами (пусто, один, максимум, неверный ввод). |
| R-TST-02 | **Матрица прав генерируется из `ROLES-PERMISSIONS`:** каждый маршрут × роль (гость, зритель, редактор, аналитик, админ, без роли) → ожидаемый код ответа; тест падает, если матрица и код расходятся. |
| R-TST-03 | Тесты не ходят в сеть: ответы TMDB и IMDb — записанные фикстуры; обновляем осознанно. |
| R-TST-04 | Тестовые данные детерминированы (зерно генератора); синтетическое население (`ANALYTICS` §5) воспроизводимо. |
| R-TST-05 | Каждое требование `F-xx` имеет критерии приёмки Given/When/Then и ссылку на тест (`TRACEABILITY`). |
| R-TST-06 | Ошибка, найденная вручную, получает регрессионный тест. |
| R-TST-07 | Допуск к слиянию (CI): линтер, модульные и интеграционные, axe на эталонных страницах, бюджеты размера, проверка ключей i18n, сканер секретов, аудит зависимостей. |
| R-TST-08 | Покрытие строк бизнес-логики ≥ 80%, модерации и прав — ≥ 90% по ветвлениям **[ГИПОТЕЗА]**. Число — ориентир, не цель. |
| R-TST-09 | Восстановление из копии проверяется автоматически по расписанию (`SECURITY` R-SEC-30). |
| R-TST-10 | Перед защитой — прогон полного сценария демо на чистой машине без интернета (EC-D9). |

## 4. Фикстуры из спайка

Реальные случаи, которые обязаны быть в тестах импорта:
- сериал, найденный и подтверждённый обратным идентификатором, но с другим локальным названием;
- **сезон целиком в один день** (6–10 серий с одной датой);
- сериал со статусом Returning без дат («ждём сезон»);
- сериал с датами далеко за окном (2027);
- новинка без IMDb-идентификатора и без рейтинга;
- нет описания ru (но есть en);
- нет метки RU/BY (есть только США);
- нет фона без текста;
- ответ 429 с `Retry-After` и обрыв сети посреди запуска.

## 5. Шаблон тест-кейса (и для таблицы в ПЗ)

| Поле | Содержание |
|---|---|
| ID | `TC-NN` (не путать с `T-NN` из модели угроз) |
| Требование | `F-xx` / `R-…` |
| Цель | что проверяем |
| Предусловия | данные, роль, язык, тема |
| Шаги | нумерованные |
| Ожидаемый результат | наблюдаемый и измеримый |
| Фактический результат, статус | заполняется при прогоне |
| Тип | авто / ручной |

## 6. Чек-лист фичи

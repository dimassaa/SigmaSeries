# DATA-SOURCES — откуда берутся данные и как попадают в систему

> v0.2 · Фаза 1, обновлён прогонами 1 и 2 (§10, 2026-10-04 и 2026-10-06) · закрывает G-02. Решение автора (DEC-008): основное — из IMDb, постеры и остальное — из TMDB; чего нет — заглушка; пробелы вручную заполняет админ.
> Первичная сверка с документацией — 2026-10-03. **Пункты, помеченные `[проверить]` ниже, относятся к тому, что спайк уже измерил; после прогонов помечено `[проверено спайком]`.** Остальные помеченные требуют первоисточника — их снимает Фаза 7.

## 1. Есть ли у IMDb предстоящие релизы?

**Нет — в доступных нам данных.**
- В датасетах IMDb нет дат выхода и расписания: у серий только номер сезона и номер серии (`title.episode`), у сериала — год начала и окончания.
- Календарь релизов у IMDb есть на сайте, но парсить сайт по условиям нельзя **[проверить]**; официальный доступ к данным — платная лицензия.
- **Расписание берём из TMDB:** даты серий в данных сезонов, ближайшая и последняя серия в карточке сериала. **TVmaze проверен прогоном 2 и не подключается:** ни у одного из 60 «ждущих сезон» нет даты следующей серии (DEC-019). Пробелы заполняет админ.
- Ограничение: у TMDB для сериала одна дата выхода — **оригинальная** (по обсуждению на форуме TMDB региональных дат нет) **[проверить]**. Для аудитории RU/BY это «дата первого выхода», а не локальная; в интерфейсе формулируем честно.

## 3. Идентификаторы

- **IMDb `tconst` — первичный бизнес-ключ.** `tmdb_id` связываем поиском TMDB по внешнему идентификатору IMDb **[проверено спайком]**: 994 из 1000, обратный идентификатор совпал у всех совпавших (§10, прогон 2).
- Проверка пары: **обратный идентификатор** (в данных TMDB указан тот же `tconst`) и год начала (±1). Название — только справочно: в спайке оба «расхождения» из 80 оказались разными локализациями одного сериала (C.B. Strike / Strike; Asur: Welcome to Your Dark Side / Asur). Неподтверждённые — в список для ручной проверки.
- Сопоставление запоминаем; заново не ищем, пока админ не сбросит.
- Серии связываем по паре (сезон, номер). Серии IMDb без пары в TMDB остаются без даты; серии TMDB без пары создаём из TMDB.

## 4. Отбор каталога

1. **Кандидаты:** `titleType` ∈ {сериал, мини-сериал}, `isAdult = 0` (H-19).
2. **Исключаем жанры:** Animation (мультфильмы и аниме не входят), Talk-Show, News, Game-Show, Reality-TV, Short.
3. **Популярность = число голосов IMDb;** берём 1000 лучших (DEC-009). Плюс критерия: стабильность и независимость от сети. Минус: перекос к старым сериалам.
4. **Новинки и идущие** — через TMDB: объединение (а) сериалов с первой датой выхода от «12 месяцев назад» до 31.12.2026 и (б) сериалов, у которых есть серия с датой в окне «сегодня … 31.12.2026» (фильтр по дате эфира **[проверено спайком 2]**: в TMDB 2183 сериала с серией до 31.12, у первых 30 отобранных дата в окне есть у всех). Сортировка по популярности TMDB, потолок ≈ 300 (H-20). Для каждого берём IMDb-идентификатор из данных TMDB; нет — рейтинга IMDb не будет (в спайке у 17% новинок его нет ⇒ второй рейтинг, TMDB, нужен).
5. Итог ≈ 1000–1250. Добавленный сериал остаётся, даже если выпал из топ-1000 (чтобы не терять пользовательские данные); убирает только админ.
6. **Состояние выхода** (вычисляется, H-27): «Выходит» — есть серия в окне от −14 дней и дальше; «Ждём сезон» — статус Returning, дат нет; «Завершён», «Отменён». Календарь и «Новинка дня» работают только по «Выходит». Основание — прогон 2, а не прогон 1: в полном прогоне из 157 сериалов «Выходит» дата в окне есть у 139 (89%), а у 143 «Ждём сезон» нет ни одной (§10).

## 5. Конвейер (M12)

| Стадия | Что делает | Выход |
|---|---|---|
| 0 Датасеты IMDb | Скачать архивы, читать **потоком** с фильтром по `tconst`; целиком в БД не загружать | Промежуточные выборки |
| 1 Отбор | Правила §4 | Список кандидатов |
| 2 Сопоставление | §3 | Пары IMDb ↔ TMDB |
| 3 Обогащение | Детали, ключевые слова, внешние идентификаторы, рейтинги контента, переводы (дополнительные подзапросы в одном ответе) + сезоны | Сырые данные TMDB |
| 4 Запись | Обновление по `tconst`; происхождение каждого поля; блокировки ручных правок | Таблицы каталога |
| 5 Изображения | Скачать постер и фон, сделать варианты размеров, записать в БД | Изображения в БД |
| 6 Полнота | Пересчитать «неполные» и их причины | Список неполных |
| 7 Отчёт | Отобрано / сопоставлено / без постера / без описания ru / без дат серий / ошибки | Отчёт запуска (виден админу) |

Правила:
- Повтор безопасен (обновление, а не вставка), запуск возобновляем с контрольной точки, есть «сухой прогон».
- Вежливо к API: ≈ 10–20 запросов в секунду при потолке TMDB порядка 40–50 **[проверить]**; на 429 — пауза по `Retry-After` и растущая задержка; загрузка картинок — ограниченное число параллельных соединений.
- **Ручное побеждает импорт:** поле с блокировкой не перезаписывается; у каждого значения видно происхождение.
- Запуск не должен ломать публичный сайт: запись транзакциями, публикация после проверки.
- Ключ TMDB — только в переменных окружения.
- **Расписание запусков:** график серий идущих — ежедневно; рейтинги IMDb — еженедельно; полный пересмотр каталога — по кнопке; **снимок для защиты** — за 1–2 дня до защиты.

## 7. Календарь до 31 декабря 2026

- **Цель (DEC-010):** календарь заполнен минимум до конца декабря.
- **Метрика готовности [ГИПОТЕЗА]:** по сериалам «Выходит» у 100% есть даты ближайших серий; **плотность календаря — не менее 25 выходов в неделю на ближайшие 4 недели** (прогон 2 на 6 октября: 189, 147, 120, 112; следующие 4 недели — 62, 53, 45, 40; дальше 27, 27, 16, 11, 4 — анонсы ещё не сделаны, к декабрю плотность вырастет). Доля «идущих по статусу с датой» метрикой не является: многие из них ждут сезон.
- **Пробелы и плотность календаря:** (1) в каталог добавляем сериалы, у которых есть серия в окне (§4, п. 4); (2) админ массово задаёт график, когда дата известна из других источников; (3) уведомление «объявлена дата» для ждущих сезон (H-26); (4) на защите календарь показывает данные на момент снимка — реальные, без выдумок.
- Виды выхода: еженедельно / сезон целиком / пачками (EC-C4). **В спайке у 13 из 80 сериалов все серии сезона имеют одну дату** (6–10 серий в один день): **выход = группа серий сезона с одной датой.**

## 8. Атрибуция и условия

- **IMDb:** личное и некоммерческое использование; проект учебный. На странице «О данных» — указание источника; сайт IMDb не парсим.
- **TMDB:** бесплатно для некоммерческого использования; обязательна атрибуция (логотип и текст в разделе About/Credits); хранение копий — до 6 месяцев по вторичным источникам **[проверить в официальных условиях]**; картинки отдаются CDN без лимита запросов, но с ограничением параллельных соединений **[проверить]**.
- **TVmaze: не подключаем** (DEC-019). Проверено спайком: из 60 проверенных сериалов «Ждём сезон» дата следующей серии есть у 0. Условия на случай возврата — CC BY-SA, атрибуция обязательна, ≥ 20 запросов за 10 секунд.
- Коммерческое использование потребует новых условий — вне проекта.

## 9. Риски и edge cases

| ID | Ситуация | Поведение |
|---|---|---|
| EC-D1 | Сериал не найден в TMDB | Публикуется с заглушками; в списке неполных, причина «нет в TMDB» |
| EC-D2 | Неверное сопоставление (однофамильцы, ремейки с тем же названием) | Проверка года и названия; сомнительные — в список для ручной проверки |
| EC-D3 | Нет ru-описания | Показываем en; если нет — текстовая заглушка |
| EC-D4 | Сериал «Выходит», но у части серий нет даты | Эти серии не попадают в «Новинку дня» и правую панель; сериал в неполных («график с пропусками»). «Ждём сезон» без дат — норма, не дефект |
| EC-D5 | Даты перенесены или TBA | Календарь обновляется; подписчики получают уведомление; TBA не показываем как дату |
| EC-D6 | TMDB отвечает 429 или недоступен | Пауза, повтор, при исчерпании — сохраняем прогресс и продолжаем в следующий запуск |
| EC-D7 | Сериал выпал из топ-1000 при пересчёте | Остаётся в каталоге |
| EC-D8 | Ручное значение и новый импорт расходятся | Побеждает ручное (блокировка), расхождение видно в студии |
| EC-D9 | Нет интернета на защите | Работаем со снимком данных; изображения уже в БД |
| EC-D10 | В «топ по голосам» попали не сериалы (шоу, спецвыпуски) | Фильтры §4; остальное убирает админ; список исключений пополняем после спайка |
| EC-D11 | Все серии сезона вышли в один день (стриминг; ≈ 16% в спайке) | Один выход «N серий», одно уведомление, один показ в «Новинке дня»; прогресс и итоги считают серии по отдельности |
| EC-D12 | Статус Returning, дат нет («ждём сезон») | Состояние «Ждём сезон»; в календарь не попадает; подписчик может включить «сообщить, когда объявят дату» |
| EC-D13 | Нет возрастной метки для RU/BY (в спайке у 36%) | Показываем метку по данным другой страны с пометкой или скрываем; одна эта причина карточку неполной не делает |

## 10. Спайк данных ✔ прогоны 1 и 2 (2026-10-04, 2026-10-06)

Измеряем на выборке 50–100 сериалов (старые, идущие, новинки):
1. Доля сопоставления IMDb → TMDB.
2. Доля с постером, **фоном без текста**, ru-описанием, возрастным ограничением.
3. Доля идущих с датой ближайшей серии; число серий с датами по неделям до 31.12.
4. Время и число запросов для 1000 сериалов; объём изображений в БД.
5. Качество критерия «топ-1000 по голосам»: сколько «странных» тайтлов.

### Прогон 2 — план (выполнен 2026-10-06, итоги ниже)

1. Полный прогон: `--sample 1000 --new 300` (≈ 15 минут).
2. Режим «в эфире»: сериалы с серией в окне «сегодня … 31.12» по популярности (до 300); число серий **и выходов (групп)** по неделям отдельно для топ-1000 и «в эфире» — получаем N для метрики плотности.
3. Доли состояний «Выходит» / «Ждём сезон» / «Завершён» / «Отменён» по каталогу.
4. Для «ждущих сезон»: есть ли дата у следующего сезона в данных сезонов; есть ли даты в TVmaze (поиск по IMDb-идентификатору, **[проверить]**). Если у TVmaze заметно больше — подключаем.
5. Метки возраста: сколько сериалов без RU/BY, но с меткой США; таблица соответствия.
6. Вес изображений: постер и фон в трёх размерах (оценка объёма БД).
7. Число премьер 2026 года по жанрам (проверка блока «жанры этого года»).
8. Сохранить полные списки серий (вы уже добавили это в свою версию скрипта — оставьте как основу M12).
9. Люди: доля сериалов с режиссёром или создателем (IMDb `title.crew`, запасной вариант TMDB `created_by`) и с ≥ 3 актёрами (`title.principals`, категории actor, actress, self).
10. Список значений статуса TMDB в каталоге (для таблицы соответствия состояниям выхода, H-39) и число запросов при загрузке всех сезонов в двух языках (оценка H-29).

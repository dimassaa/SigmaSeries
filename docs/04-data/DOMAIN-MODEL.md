# DOMAIN-MODEL — модель данных

> v0.1 · Фаза 5 · читать перед `DATABASE.md`. Документ отвечает на два вопроса из `PLAN` §1: **у каждого поля есть источник** и **у каждого поля есть потребитель**. Поля приведены здесь; типы, ограничения и индексы — в `DATABASE.md`.
> Сущности `E-` были названы в `MODULES` ещё в Фазе 2 (40 штук); здесь они сведены, уточнены и разложены по группам. Спеки модулей M0, M1, M2, M3, M4, M5, M6, M9, M10, M12 — источник полей.

## 1. Как читать

- **Сущность** — то, чему посвящена таблица. Не нужна для того, что можно вычислить.
- **Атрибут** помечен источником: `ИМП` — приходит из импорта IMDb/TMDB; `ВВ` — вводит пользователь; `СИС` — ставит система; `ПРО` — производная величина, не хранится, а вычисляется или кэшируется.
- **Потребитель** отвечает на вопрос «кто это читает». Поле без потребителя — лишнее, и оно удаляется.
- Идентификаторы `E-` и `OP-` совпадают с реестрами.

## 7. Что хранится, а что вычисляется

| Величина | Решение | Почему |
|---|---|---|
| Рейтинг сайта | **Кэш** `E-SeriesRatingStat` | Пересчёт при каждом чтении — это полная выборка оценок на каждый запрос списка |
| Прогресс просмотра | **Кэш** `E-Progress` | Тот же счёт по тот же просмотр списков |
| Состояние выхода сериала | **ПРО** из дат выходов | Хранение означало бы два источника истины для одного и того же (DECISIONS, исправление 7) |
| Группа отзыва | **ПРО** из текущей оценки автора | Группы должны пересчитываться при изменении оценки; хранить — значит рассинхронизировать |
| Онлайн | **Агрегат** почасовой | Сырые отметки активности — миллионы строк ради одного числа |
| Полнота карточки | **ПРО** | Меняется при каждом импорте; хранить — значит забыть пересчитать (OP-07) |
| «Похожие» | **ПРО** при запросе | Кэш протухает быстрее, чем живёт |
| Баннер дня | **Хранится** | Иначе главная меняется при каждом запросе и три раза в секунду |
| Набор шести сериалов в блоке жанров | **ПРО**, фиксируется на сутки | Иначе «случайные» постеры меняются при каждом обновлении (EC-H10) |

## 9. Имена из спек, которых здесь нет

Спеки M1, M4, M10, M11, M12 и брифы `MODULES` называют сущности под именами, отличными от принятых здесь. **Таблица ниже — единственное место, где эти имена сопоставлены**, иначе код будет читать сорок таблиц вместо пятидесяти двух. Найдена сквозной проверкой ссылок 2026-10-09.

## 10. Открытые решения для Фазы 7

1. **Схема сырого JSON TMDB** — хранить ли ответы для повторной обработки без запросов. Влияет на объём БД примерно на 40% и на возможность пересчитать обогащение после смены правил.
2. **Гранулярность событий** — сырые события 90 дней, агрегаты бессрочно (`R-AN-10`). Разделение таблиц или одна с партиционированием.
3. **Полнотекстовый поиск по телу материала** — нужен ли для модерации и для поиска. Влияет на выбор СУБД сильнее, чем всё остальное вместе.
4. **Разделение баз** — одна СУБД на всё или отдельная для аналитики. Влияет на бэкап и на требование Windows-окружения.

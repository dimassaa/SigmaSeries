# STACK — стек и его обоснование

> v0.1 · Фаза 7 · закрывает ПЗ 4.2.2 «обоснование выбора компонентов и технологий». **Основание для письма руководителю (DEC-021):** берём только то, что реально нужно, с обоснованием по каждой зависимости.
> Ограничения задания: Node.js + Express, бизнес-логика на JavaScript (TypeScript **не одобрен**, DEC-017), CommonJS / UMD / ES Modules, одна каскадная таблица стилей, СУБД из списка, Windows 10+, браузеры Yandex / Firefox / Chrome / Opera. Версии проверяются по документации на дату сдачи (C-13), а не по памяти.

## 2. Выбор СУБД: PostgreSQL

Бланк разрешает MySQL, PostgreSQL или MongoDB. Решающий довод — **русский полнотекстовый поиск по телу отзывов, руководств и обсуждений без внешнего сервиса.**

| Критерий | PostgreSQL | MySQL | MongoDB |
|---|---|---|---|
| Ссылочная целостность (Бланк 3.3.1) | нативно | нативно | **нет внешних ключей в строгом смысле** |
| Полнотекстовый поиск по русскому без внешнего сервиса | `tsvector`, словари включаются в стандартную поставку | требует конфигурации ngram и внешних плагинов | есть, но решение принимается в приложении |
| JSONB для параметров уведомлений | да | ограниченно | естественно, но это не аргумент: JSON — не наш основной тип |
| `smallint` + `numeric` для рейтинга и агрегатов | да | есть | не применимо |
| Демонстрация на Windows 10+ без Docker | официальная сборка | официальная сборка | нет |

**Отвергнуто:** MongoDB — потому что ссылочная целостность в задании не «подразумевается», а требуется, и в MongoDB её пришлось бы имитировать в коде, то есть переписать требование. MySQL — рабочий вариант, проигрывает только на русском полнотексте; если руководитель предпочтёт MySQL, единственная потеря — индекс `ix_material_search` переносится на внешний модуль.

## 3. Зависимости: список и обоснование

DEC-021 требует по каждой библиотеке ответить на четыре вопроса: какую задачу решает, почему не проще своими силами, размер и поддержка, лицензия. Ничего сверх этого списка не ставится без письменного согласования.

### Серверные

| Пакет | Задача | Почему не своими силами | Размер | Лицензия |
|---|---|---|---|---|
| `express` | HTTP-сервер и маршрутизация | Предписан Бланком | — | MIT |
| `pg` | драйвер PostgreSQL | Предписан выбором СУБД; поддержка протокола и пула вручную — это работа, не относящаяся к курсовой | 1 МБ | MIT |
| `argon2` | хеширование паролей | Криптография, которую нельзя писать самому. `bcrypt` тоже подходит, но argon2id — современнее и у него есть штатная защита от перебора памяти | 2 МБ + нативный модуль | MIT |
| `express-session` + `connect-pg-simple` | сессии в БД | Хранение сессий в памяти теряется при перезапуске — на защите это означает вылет из аккаунта посреди демонстрации | 200 КБ | MIT |
| `sharp` | подготовка изображений | Перекодирование JPEG/WebP и ресайз своими силами нереальны | 30 МБ + нативный | Apache-2.0 |
| `nodemailer` | отправка писем | SMTP и подтверждение почтового ящика на защите — то, что нельзя проверить глазами | 1 МБ | MIT |
| `qrcode-generator` | QR-код для настройки 2FA (F-01-05 §19) | QR — это ISO/IEC 18004: коррекция ошибок, маски, выбор версии. Свой рендерер — это 200+ строк спецификации, и ошибку в них поймал бы только настоящий телефон на защите | 543 КБ, **ноль зависимостей** | MIT |
| `node-cron` | расписание задач | Внешний планировщик не нужен: задач пять, все живут в том же процессе (ADR-004) | 20 КБ | ISC |

Про `qrcode-generator` против `qrcode`: вторая втрое компактнее (132 КБ против 543 КБ), но тянет три пакета, включая `yargs` для командной строки, которой серверу не нужно. Лишняя зависимость обходится дороже выигранных килобайт, а правило DEC-021 — «только реально нужное». Согласовано автором 11.10 (DEC-030).

Проверка QR настоящая: сгенерированный код декодируется библиотекой `jsqr` и сверяется с исходным `otpauth://`. Тест «QR нарисовен» ничего не доказывал бы — ошибку заметил бы только человек с телефоном.

### Клиентские

**Ни одной библиотеки.** Это решение, а не нехватка средств:

| Что обычно берут пакетом | Как сделано здесь | Почему так |
|---|---|---|
| UI-фреймворк | серверный рендеринг строковыми шаблонами (`src/view/*.js`) | `R-DES-25` требует анимировать только `transform` и `opacity`, а `R-DES-28` — скелетоны с точными размерами. Оба требования нативно выполняются прямо, и лишнего согласования не требуется (DEC-017) |
| Иконки (набор SVG-шрифта или статика lucide) | символы и буквенные метки в разметке | Набор иконок потребовал бы шрифта с иконками или сотни SVG; рядом с текстом состояния («новое», «скоро», «Включено») значок всё равно второй, а не первый (R-A11Y-19) |
| Библиотека i18n (intl-messageformat и подобные) | `Intl` из состава среды плюс ICU-строки своими руками | `Intl` встроен в браузер; отдельный пакет дублировал бы его ценой 30 КБ и своим форматом сообщений |

**Итого 9 зависимостей, все серверные.** Из них 3 предписаны Бланком или следуют из выбора СУБД, 3 — криптография и форматы (писать самому нельзя), 3 заменяют работу, которая иначе стала бы ошибками.

### Чем заменены пакеты, которые в списке стояли раньше

Черновик §3 обещал `zod`, `helmet`, `multer`, `marked`, `esbuild` и `sass`. Ни один из них в сборке нет, и обещание в документе было хуже отсутствия: на вопрос комиссии «где у вас валидация входа» отвечать было бы нечем. Чем заменено:

| Обещанный пакет | Чем заменён в коде | Где смотреть |
|---|---|---|
| `zod` | проверка по правилам `R-SEC-13` на сервере, руками | `src/services/auth/validate.js`, белые списки в `src/config/settings.js` |
| `helmet` | тот же набор заголовков выставляется вручную в `src/app.js` — для серверного рендеринга без форм и загрузок этого достаточно | `src/app.js`, комментарий «Заголовки безопасности» |
| `multer` | загрузки файлов в проекте нет: изображения лежат в БД, а постинг изображений на форуме в P0 не входит | `DATABASE.md`, раздел про `e_image` |
| `marked` | разбор пользовательской разметки в P0 не входит; материалы хранятся как текст и экранируются при выводе (`R-SEC-11`) | `src/view/render.js` |
| `esbuild` | сборки нет: сервер и клиент — нативные ES-модули, Node запускает их напрямую, браузер получает как есть | `package.json` |
| `sass` | таблицы стилей — обычный CSS в частях; их склейка в **один** файл делает `node tools/build-css.mjs`, без препроцессора | `tools/build-css.mjs` |

Если модуль, которому нужна одна из этих библиотек, дойдёт до кода (`marked` — руководства M5), пакет добавляется в таблицу **до** установки и объясняется здесь по образцу DEC-021.

Проверка соответствия списка коду: `node tools/check-stack.mjs`. Ловит расхождение в обе стороны — описанного, но не установленного и установленного, но не описанного.

## 4. Что сознательно не ставится

| Не ставим | Почему |
|---|---|
| Redis и очереди | Не разрешены Бланком без согласования; **согласованы 12.10 (DEC-031)**. Задачи решаются планировщиком на Node.js и таблицами в БД — очередь писем уже так и сделана (`e_mail`) |
| TypeScript | Не одобрен, DEC-017. Типизация через JSDoc + `tsc --checkJs` |
| ORM (Prisma, Sequelize) | `DATABASE.md` пишет схему руками — с ORM пришлось бы описывать её дважды, в DDL и в моделях. SQL нужен и для листинга в приложении |
| UI-фреймворк | См. §3 |
| Docker | Бланк требует Windows 10+ без указания на контейнеры; нативная установка PostgreSQL и Node.js проще для демонстрации |
| Линтер и форматтер | Не влияют на работу приложения; форматирование держится дисциплиной, а не инструментом. Если руководитель пожелает — `prettier` ставится одной командой |
| Файловые хранилища | Изображения в БД по C-04 |

## 6. Что нужно подтвердить перед началом кода

1. **Письмо руководителю** — три пункта: одна CSS (сборка), английский интерфейс, Redis. Согласовано устно 12.10, см. DEC-031; письмо остаётся черновиком.
2. **Версии** — зафиксировать по документации на дату сдачи, а не по памяти (C-13). Список пакетов с версиями — в `package.json`.
3. **MySQL вместо PostgreSQL** — если руководитель настаивает, меняется §2 и индекс полнотекстового поиска; остальное не трогается.

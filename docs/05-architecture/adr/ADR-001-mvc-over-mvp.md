# ADR-001. MVC вместо MVP

> 2026-10-09 · Положение: **принято** · Закрывает: Бланк 3.2 (MVC или MVP)

## Контекст

Задание разрешает две архитектурные модели. Различие между ними — в том, знает ли представление о модели.

## Решение

MVC: представление знает о модели и форматирует её; контроллер связывает HTTP и сервис; бизнес-логика живёт в сервисах.

## Почему

Правил отображения в проекте много и они повторяются на каждом экране: формат `8,7 / 10` с локальным разделителем, локальная дата вместо момента, три рейтинга подряд, скрытие спойлера, счётчик «3 из 24». В MVP каждое представление реализует их заново, и к 60 экранам расхождения становятся видимыми пользователю.

## Отвергнуто

- **MVP** — дешевле в краткосрочной перспективе при малом числе экранов, но здесь экранов 60.
- **Чистый SPA** — отвергнуто отдельно, см. ADR-002.

## Последствия

- Контроллеры толще, чем при MVP.
- Тест на сервис пишется без HTTP: сервис не видит `req`.
- Требование Бланка 3.3.1 «бизнес-логика реализует основные алгоритмы обработки данных» выполняется буквально: алгоритмы — именованные функции.

# ADR-004. Планировщик внутри процесса

> 2026-10-09 · Положение: **принято** · Закрывает: Бланк 3.3.3 (инфраструктура); `M3` F-03-07, F-12-07

## Контекст

Пять задач по расписанию: синхронизация расписания, открытие новых, обновление рейтинга, полный прогон, резервная копия и уборка. Бланк перечисляет инфраструктуру и не включает ни очередей, ни внешних планировщиков.

## Решение

`node-cron` в процессе приложения. Внешние очереди и Redis — не используются.

## Почему

- Задач пять, они не требуют независимости от веб-сервера и не должны выполняться при недоступности приложения.
- Любой внешний компонент сверх перечня Бланка требует согласования руководителем (письмо, п. 3). Пока ответа нет — не добавляем.

## Отвергнуто

- **Redis + очереди** — лучше переживает перезапуск и даёт повторные попытки, но требует согласования и не работает на Windows нативно.
- **Внешний планировщик (cron в ОС)** — ещё один компонент сверх перечня, при нулевом выигрыше: задачи те же.

## Последствия

- **Задачи не переживают перезапуск процесса.** Поэтому каждая задача при старте проверяет, не просочилась ли она, и запускается, если просочилась (`M3` F-03-07 правило (а), порог 36 часов). Это правило описано в спеке и теперь обосновано архитектурой, а не просто взято.
- Не более одного запуска одновременно — блокировка в БД, а не в памяти (иначе не работает после рестарта).
- Порядок ночью: резервная копия → очистка → синхронизация → открытие новых → рейтинги.

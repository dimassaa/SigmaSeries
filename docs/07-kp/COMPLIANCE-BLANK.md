## 7. Что из этого следует для определения «100%» (`PLAN` §1)

| Пункт `PLAN` §1 | Состояние |
|---|---|
| 1. Все измерения каждой фичи заполнены | да, по всем 13 модулям |
| 2. У каждого экрана назначение, блоки, источники, матрица состояний, карта фокальной точки и третей, три брейкпоинта, размеры скелетона, SEO | **частично**: функция, блоки, источники, фокус и трети, брейкпоинты, скелетоны и SEO есть в спеках; матрицы состояний по экранам нет |
| 3. Нет «сирот»: у каждого поля есть источник, у каждого поля БД есть потребитель | да: `DOMAIN-MODEL` §2–6, обе колонки заполнены |
| 4. Матрица прав без пустых клеток | да: `ROLES-PERMISSIONS` §2, 5 ролей × 24 объекта |
| 5. Нет открытых `[ВОПРОС]` | 11 из 12 закрыты (DEC-025), открыт Q-19 — ждёт `catalog-snapshot.json` |
| 6. `COMPLIANCE-BLANK.md` полностью зелёный | **этот файл: 36 из 63** |
| 7. Междокументная сверка | `build_registries.py` — сходится, код 0. Сверка по всем 11 семействам ID — 2026-10-09, исправлено 61 расхождение |

Критерий `PLAN` §1 по-прежнему измеряет полноту спецификации. Расширен пунктом «все предъявляемые артефакты Бланка существуют» — без него прогресс по нему нельзя считать готовностью к защите.

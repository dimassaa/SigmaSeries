# ПЛАН ПОЯСНИТЕЛЬНОЙ ЗАПИСКИ

> Рабочий план, не текст записки. Источник структуры — `docs/бланк.docx` (§4 — содержание ПЗ, §5 — графический материал). Оформление — по `docs/Стандарт 2024.pdf` (СТП 01-2017) на этапе вёрстки. Все цифры ниже взяты из проекта на 19.11.2026: 71 таблица БД, 104 фичи, 62 экрана, 17 бизнес-операций, 1698 тестов, 9 производственных зависимостей.

## 0. Принципы

1. **Каждый раздел отвечает на вопрос «что сделано и почему так»**, а не пересказывает учебник. Теория — только та, без которой решение не обосновать.
2. **Одно утверждение — одно доказательство**: цифра, таблица, диаграмма или ссылка на приложение. «Быстро», «удобно», «надёжно» без числа не пишем.
3. **Преимущества — в каждом разделе**, привязаны к месту: технологии — в 4.2.2, алгоритмы — в 4.2.4, безопасность — в 4.2.6, качество — в 4.3.
4. **Тяжёлые артефакты готовятся кодом**: UML — PlantUML, IDEF0/BPMN — diagrams.net/bpmn.io, скриншоты — реальные экраны демо-базы.
